# Octocode Awareness
Trigger this skill for shared repo work before planning, during edits, after verification, or when users ask about memories, locks, signals, hooks, wiki context, reflection, handoffs, or stale awareness state.
Use the bundled/local CLI when present: `node scripts/awareness.mjs` inside an installed skill, or `node packages/octocode-awareness/dist/bin/awareness.js` in this repo. Use `npx @octocodeai/octocode-awareness` only when no local CLI exists.
Canonical store: global `~/.octocode/memory/awareness.sqlite3`, scoped by workspace/artifact/repo/ref. `<repo>/.octocode/` is generated by `repo inject`; it is not the DB.
First command: `<local-awareness-cli> workspace status --workspace "$PWD" --compact`; then `schema commands --compact` for discovery.

## Before / During / After
- **Before**: `workspace status`, `memory recall`, `refinement get`, `signal list`; inspect `.octocode/AGENTS.md` when present.
- **During**: `lock acquire|wait|release`, `signal publish|reply|ack|resolve`, `memory record`, `agent register|list`.
- **After**: `verify audit|mark`, `reflect record|mine-weakness|export-harness`, `session capture`, `repo inject`.
- **Ongoing**: `maintenance digest`, `lock prune`, `memory forget`, `signal prune`, `docs staleness`; use `octocode-skills` or `npx octocode` when repeated friction should become a better skill.

## Must-Know
- Recall is lexical FTS plus salience/scoping by default; `--semantic` only works when a host provides embeddings.
- Old prompts for `octocode-agent-communication` or `octocode-reflection` mean this skill.
- Before relying on hooks, read `references/hooks.md`; Claude-style hosts may run frontmatter hooks, while Codex/Cursor/Pi need host wiring.
- Hooks use runner commands `pre-edit|post-edit|harness-guard|stop-verify|notify-deliver|session-end`.

## Installation / Init Flow
1. Install: `npx octocode skill --add --path "{{path_to_skills_location}}/octocode-awareness" --platform common`.
2. Init: `<local-awareness-cli> maintenance init --compact`; then status and `schema commands --compact`.
3. Hooks: preview `<local-awareness-cli> hooks install --host codex --project-dir <repo> --dry-run --compact`; after approval install and run `hooks check --host codex --strict --compact` (same for `cursor`/`claude`).
4. Smoke: `node scripts/schema.mjs` for schemas, `node scripts/install.mjs --check-only` for init flow, `node scripts/smoke-multi-agent.mjs` for lock/signal/verify flow.
5. Audit hook internals: `scripts/hook-runner.mjs` dispatches lifecycle events, `scripts/extract-hook-files.mjs` extracts write paths, and `scripts/install-hooks.mjs` is the legacy installer wrapper.

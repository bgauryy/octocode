# Octocode Awareness
Trigger this skill for shared repo work before planning, during edits, after verification, or when users ask about memories, locks, signals, hooks, wiki context, reflection, handoffs, or stale awareness state.
Canonical CLI: `node scripts/awareness.mjs` inside an installed skill, or `node packages/octocode-awareness/dist/bin/awareness.js` in this monorepo. Use `npx @octocodeai/octocode-awareness` only when neither local path exists. Below, `<cli>` means that chosen binary.
Canonical store: global `~/.octocode/memory/awareness.sqlite3`, scoped by workspace/artifact/repo/ref. `<repo>/.octocode/` is generated by `repo inject`; it is not the DB.
First command: `<cli> attend --workspace "$PWD" --query "<current task>" --compact`; then `schema commands --compact` for discovery. One-page recipes: `references/agent-cheatsheet.md`.

## Before / During / After
- **Before**: `<cli> attend --workspace "$PWD" --query "<task>" --compact`; for code evidence `npx octocode search "<term>" <path> --no-color` (see `references/octocode.md`); `workspace status --workspace "$PWD" --compact`; `query workboard --workspace "$PWD" --format table`; `memory recall --query "<task>" --workspace "$PWD" --smart --compact`; `refinement get --workspace "$PWD" --state open --compact`; `signal list --agent-id "$OCTOCODE_AGENT_ID" --workspace "$PWD" --compact`; inspect `.octocode/AGENTS.md` when present.
- **During**: `<cli> lock acquire --agent-id "$OCTOCODE_AGENT_ID" --workspace "$PWD" --target-file <path> --rationale "<why>" --test-plan "<verify>" --compact`; use `lock wait` for bounded waits and `lock release` after verification; `signal publish|reply|ack|resolve --agent-id "$OCTOCODE_AGENT_ID" --workspace "$PWD" ...`; `memory record ... --compact`; `agent register|list --workspace "$PWD" --compact`.
- **After**: `<cli> verify audit --agent-id "$OCTOCODE_AGENT_ID" --workspace "$PWD" --compact`; `verify mark ...`; `reflect record|mine-weakness|export-harness ... --compact`; `session capture --agent-id "$OCTOCODE_AGENT_ID" --workspace "$PWD" --compact`; `repo inject --workspace "$PWD" --compact` when projections should refresh.
- **Ongoing**: `<cli> maintenance digest --workspace "$PWD" --dry-run --compact`; `lock prune` / `memory forget --dry-run` / `signal prune` / `docs staleness`; use `octocode-skills` or `npx octocode` when repeated friction should become a better skill.

## Must-Know
- Recall is lexical FTS plus salience/scoping by default. CLI `--semantic` ranks only when `OCTOCODE_EMBED_CMD` is set (host embedder); otherwise it warns and stays lexical.
- Code/GitHub/package search uses `npx octocode search ... --no-color` (or Octocode MCP). Do not expect a vendored `octocode` binary in this skill — the native engine is platform-installed via npx. Read `references/octocode.md` when deeper research routing is needed.
- Prefer operational commands over organ metaphors. Read `references/homeostatic-loop.md` only when explaining attend/workboard/digest policy or memory/wiki bloat.
- Read `references/self-reflection-dialogue.md` when a hard idea needs role dialogue, subagent debate, tutor/student review, tester/builder critique, or alter-ego style self-review.
- Before relying on hooks, read `references/hooks.md`; Claude-style hosts may run frontmatter hooks, while Codex/Cursor/Pi need host wiring.
- Hooks use runner commands `pre-edit|post-edit|harness-guard|stop-verify|notify-deliver|session-end`.

## Installation / Init Flow
1. Install: `npx octocode skill --add --path "{{path_to_skills_location}}/octocode-awareness" --platform common`.
2. Init: `<cli> maintenance init --compact`; then `workspace status --compact` and `schema commands --compact`.
3. Hooks: preview `<cli> hooks install --host codex --project-dir <repo> --dry-run --compact`; after approval install and run `hooks check --host codex --strict --compact` (same for `cursor`/`claude`).
4. Agent smoke: `<cli> attend --workspace "$PWD" --query "smoke" --compact` then `workspace status --workspace "$PWD" --compact`.
5. Maintainer-only: `yarn workspace @octocodeai/octocode-awareness test:smoke`, `node scripts/schema.mjs`, `node scripts/install.mjs --check-only`; read `scripts/smoke-multi-agent.mjs` for multi-agent smoke checks, `scripts/hook-runner.mjs` for hook orchestration, `scripts/extract-hook-files.mjs` for hook file detection, and `scripts/install-hooks.mjs` for legacy installer compatibility.

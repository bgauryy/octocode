# Terra with and without Jev — frozen v1

Goal: measure whether Jev changes research decisions and improves evidence-backed answers on ten canonical GitHub questions and one reported React bug.

Primary metric: paired final-answer quality out of 10, graded independently against source evidence. Components: factual correctness 0–4, coverage 0–2, verifiable citations 0–2, calibration/absence of unsupported claims 0–2. Record a pass at >=8 with no major false claim. Bug-specific diagnostics are additional, not extra points in the pooled metric.

Subjects: Q1–Q10, copied unchanged from compare/github-questions, plus BUG as specified in questions.json. Public benchmark; possible prior model knowledge. The bug issue supplies a diagnosis, so this tests diagnosis verification and solution quality, not blind bug discovery.

Arms: fresh gpt-5.6-terra agents, high reasoning, one agent per arm answering all eleven cases in order. No shared arm transcripts or answers. Within-arm cross-case context is allowed and a limitation. Sampling beyond the selected model/effort is not exposed. Host tokens are null unless actual telemetry is available; never substitute zero.

Budgets: at most 12 logged Octocode research invocations per case; schema inspections excluded but logged. Each invocation may batch up to five queries. No alternate search/network routes in evaluated arms. Baseline zero Jev calls; treatment exactly one logged remote Jev call per case, pinned jev-1.13.0, zero retries, 10-second total timeout. A failed/missing call invalidates that treatment pair; retain the failure. Do not replace failed cases. Save all answer and decision artifacts even when incomplete. No nested agents.

Treatment: after initial evidence and before finalizing, supply available context, mainGoal, goal, concise public reasoning, two or more plausible hypotheses/interpretations or next checks, exact evidence and unknowns. Ask independent typed questions whose answer can change the next action. A hypothesis remains provisional. Record the proposed direction before Jev and actual direction afterwards, including ignored advice and why. For a deterministic question, use a bounded alternative-check probe for this forced-call experiment and mark ordinary policy as skip; do not claim this establishes useful routing.

Research parity: both arms use the same Octocode CLI and schemas, time window and call cap. Record resolved source refs; moving branches and different retrieved packets are a known end-to-end confound. Do not read sibling arm, curator, previous benchmark answers or hidden gold. Repository instructions apply; benchmark arms may write only their own case directories. Public skill reading and the question/harness files are setup, not research calls. The baseline uses octocode-research with the optional Jev branch disabled.

Artifacts per case: answer.md with a complete answer and original-source links; result.json with caseId, model, reasoningEffort, startedAt, endedAt, conclusion, sources, unsupportedClaims, gaps, confidence, hostInputTokens:null, hostOutputTokens:null, tokenTelemetryReason; decision-before.json and decision-after.json with hypotheses, currentDirection, uncertainty and planned/actual nextCheck. Treatment adds request.json and adviceApplied:boolean, decisionChanged:boolean plus explanation in result.json. Tool wrapper logs calls, wall time, bytes and provider output automatically.

Grading: a fresh Terra curator establishes source-backed expected answer atoms without reading either arm. Seal gold before sending it the arm artifacts for grading. Use the same rubric for both arms; acknowledge that arm identity cannot be fully blinded from all artifacts. Grade source truth separately from following the issue reporter's proposed mechanism. For BUG check reproduction evidence, diagnosis verification, patch specificity, regression coverage and unsupported claims about runtime effects. Do not award runtime reproduction credit for a conceptual trace.

Attribution: classify Jev effects as useful direction change, corroboration, ignored advice, harmful change or no decision opportunity. Report actual before/after evidence; self-reported benefit alone is weak evidence. Count corrections and corruptions, unsupported claims, retrieval calls and query rows, Jev calls, exact Jev tokens, summed tool time and arm elapsed time. Do not call summed network duration total investigation time. Report unavailable host tokens and infrastructure failures.

Decision rule: report-only pilot. A positive delta suggests a larger matched replication; a flat or negative delta does not justify broader routing. No mid-run changes to questions, budgets, rubric or policy. Preserve canonical question files and older benchmark results.

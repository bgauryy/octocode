# W9 answer key — unsafe code in Tokio's AsyncRead impls (rust @ facc6fc)

`tokio/src/` holds **32** `impl … AsyncRead for …` blocks, none of them inside `#[cfg(test)]`. **6** have an `unsafe`
block inside their own `poll_read` body:

| Type | `impl` at | `poll_read` | `unsafe` at | What the unsafe block does |
|---|---|---|---|---|
| `Blocking<T>` | `tokio/src/io/blocking.rs:53` | :57 | :78 | Inside the closure that `sys::run` runs on the blocking pool, calls `unsafe fn Buf::read_from(&mut inner, max_buf_size)` (blocking.rs:241). That function reserves capacity, casts the spare `MaybeUninit<u8>` capacity to `&mut [u8]` for `Read::read`, then `set_len(n)`. The SAFETY comment defers to the contract of `unsafe fn Blocking::new` (blocking.rs:43): the inner `Read` never reads the buffer and reports the length correctly. |
| `Take<R>` | `tokio/src/io/util/take.rs:78` | :79 | :98–100 | `buf.assume_init(n)`: after the inner reader fills the sub-buffer `b = buf.take(limit)`, this marks those `n` bytes as initialized in the outer `ReadBuf` before `buf.advance(n)`. It is guarded by `assert_eq!(b.filled().as_ptr(), buf_ptr)`, which checks that the inner reader did not swap the buffer. |
| `Receiver` (Unix pipe) | `tokio/src/net/unix/pipe.rs:1458` | :1459 | :1466 | `unsafe { self.io.poll_read(cx, buf) }` calls `unsafe fn PollEvented::poll_read` (io/poll_evented.rs:161), whose contract is that the source can read into uninitialized memory. SAFETY: `mio_pipe::Receiver` wraps a `std::fs::File`. |
| `NamedPipeServer` (Windows) | `tokio/src/net/windows/named_pipe.rs:893` | :894 | :899 | The same `PollEvented::poll_read` call on `PollEvented<mio_windows::NamedPipe>`, with no SAFETY comment. |
| `NamedPipeClient` (Windows) | `tokio/src/net/windows/named_pipe.rs:1684` | :1685 | :1690 | The same as `NamedPipeServer`. |
| `ChildStdio` (Unix process) | `tokio/src/process/unix/mod.rs:331` | :332 | :338 | `unsafe { self.inner.poll_read(cx, buf) }` on `PollEvented<Pipe>`, the same `PollEvented::poll_read` call. SAFETY: "pipes support reading into uninitialized memory". |

Background for the last four: `PollEvented::poll_read` casts `buf.unfilled_mut()` to `&mut [u8]` (poll_evented.rs:173),
reads, then runs `unsafe { buf.assume_init(n) }` and `buf.advance(n)` (poll_evented.rs:217–218). The unsafe block in
these `poll_read`s exists only to call that `unsafe fn`.

**Must contain:** all six types with the `impl` file and line (±1 line), and for each a correct reading of the unsafe
block: the `Buf::read_from` call for `Blocking`, `assume_init` on the outer `ReadBuf` for `Take`, and the call to the
unsafe `PollEvented::poll_read` (reading into uninitialized memory) for the other four.

**Optional:** the `poll_read` and `unsafe` lines; the platform cfgs (`pipe.rs` and `process/unix` are Unix-only,
`named_pipe.rs` is Windows-only); the total of 32 impls; a note that `PollEvented::poll_read` itself holds the
uninitialized-memory cast and `assume_init`.

**Common wrong answers:**
- Including types whose `poll_read` reaches unsafe code only through a helper. These have no unsafe block in their
  own `poll_read`: `TcpStream` (stream.rs:1488 → `poll_read_priv` at :1448, unsafe at :1454), `UnixStream`
  (stream.rs:1041 → `poll_read_priv` at :1089, unsafe at :1095), the TCP and Unix `ReadHalf`/`OwnedReadHalf` that
  delegate to those, and `File` (fs/file.rs:609 → `Inner::poll_read_inner` → `spawn_blocking_read`, whose
  `buf.read_from` is at :1123). Listing them is acceptable only when they are clearly marked as indirect.
- Citing `PollEvented::poll_read` (poll_evented.rs:161) or `Buf::read_from` as an `AsyncRead` impl: both are inherent
  methods.
- Missing `Take` (its unsafe block spans several lines and sits mid-function) or the two Windows named-pipe impls.
- Including `impl AsyncRead` blocks from `tokio/tests/`, `tokio-util`, `tokio-stream` or `tokio-test`, or the doc-comment
  example at `io/async_fd.rs:118`.
- Counting `unsafe` uses elsewhere in the same file, such as `BorrowedFd::borrow_raw` in `AsFd` impls or
  `OwnedFd::from_raw_fd` in `pipe.rs`.

## The .netrc fix

| | Value |
|---|---|
| Advisory | GHSA-9hjg-9r4m-mvj7 / CVE-2024-47081, published 2025-06-09; it links the fixing commit and PR #6965 |
| Fixing commit | **`96ba401c1296ab1dda74a2365ef36d88f7d144ef`** "Only use hostname to do netrc lookup instead of netloc" |
| Author / committer | Nate Prewitt (authored 2024-09-25) / Ian Stapleton Cordasco (committed 2025-06-04T15:39:25Z) |
| PR | #6965 (opened by `sethmlarson`, merged by `sigmavirus24` on 2025-06-04). The PR has one commit, and its merge commit is that commit |
| Release | in `v2.32.4` (`compare v2.32.4...96ba401` = `behind`), not in `v2.32.3` (`ahead`) |

The code it changed: `src/requests/utils.py`, in `get_netrc_auth()`. The hunk is `@@ -236,13 +236,7 @@`, and the new line is 239 at the commit and 232 at `v2.32.4`.

```diff
         ri = urlparse(url)
-
-        # Strip port numbers from netloc. This weird `if...encode`` dance is
-        # used for Python 3.2, which doesn't support unicode literals.
-        splitstr = b":"
-        if isinstance(url, str):
-            splitstr = splitstr.decode("ascii")
-        host = ri.netloc.split(splitstr)[0]
+        host = ri.hostname
```

Why this fixes the leak: for `http://example.com:@evil.com/`, the netloc is `example.com:@evil.com`. Splitting on `:` gave `example.com`, so requests looked up the `.netrc` entry for `example.com` and sent those credentials to `evil.com`. `ri.hostname` returns the real host, `evil.com`. In the 2.31.0 source the vulnerable lines are `requests/utils.py:230–237` (before the move to the `src/` layout).

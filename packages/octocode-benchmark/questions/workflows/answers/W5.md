# W5 answer key — How http.Server.Shutdown stops a server (golang/go @ go1.22.0)

Tag `go1.22.0` is a lightweight tag on commit `a10e42f219abb9c5bc4e7d86d9464700a42c7d57`. File
`src/net/http/server.go` (blob `acac78bc`, 3,843 lines). `func (srv *Server) Shutdown(ctx context.Context) error`

`closeIdleConns` (**3036–3058**) holds `s.mu` and goes through `s.activeConn`. A `StateNew` connection older than 5 s
counts as idle (3045–3047, issue 22682). A connection that is not idle, or has `unixSec == 0`, makes the server not
quiescent (3048–3052). An idle connection gets `c.rwc.Close()` and is deleted (3054–3055). The function returns
`quiescent` (3057).

**Wait between checks.** `pollIntervalBase := time.Millisecond` (2996) starts the wait at **1 ms**.
`nextPollInterval` (2997–3006) returns `pollIntervalBase + rand.Intn(int(pollIntervalBase/10))`, which adds up to 10%
jitter (2999, `math/rand` imported at line 19). It then doubles the base (3001) and clamps it to
**`const shutdownPollIntervalMax = 500 * time.Millisecond`** (2963, documented at 2956–2962; clamp at 3002–3003). The
first timer is set at 3008. The waits are about 1, 2, 4, …, 256 ms, then 500 ms every time after that, each plus up to
10% jitter. `shutdownPollIntervalMax` is the only named constant in server.go. The 1 ms start is the `time.Millisecond`
constant assigned to a local variable, so an answer that names `time.Millisecond` = 1 ms as the second constant is correct.

**Return values.** If the context ends first, Shutdown returns `ctx.Err()` (3016): `context.DeadlineExceeded` or
`context.Canceled`. The listeners are already closed, but active connections stay open, and the caller can call
`Close` (2935) to force them. If the server goes quiet first, Shutdown returns `lnerr`, the listener-close error or
nil (3012). The doc comment at 2965–2984 says the same.

## A good answer must contain

- `closeListenersLocked` (called at 2989, defined at 3060) and `closeIdleConns` (called at 3011, defined at 3036).
- Wait: starts at 1 ms, doubles, adds up to 10% jitter, capped by `shutdownPollIntervalMax` = 500 ms (2963).
- `ctx.Err()` returned when the context ends first (3016), and `lnerr` otherwise (3012).
- Citations in `src/net/http/server.go` at `go1.22.0`.

## Optional

- `inShutdown`, the `onShutdown` goroutines, `listenerGroup.Wait()`, the 5-second `StateNew` rule, the contrast with
  `Close`, and that hijacked connections (WebSockets) are neither closed nor waited for (2977–2981).

## Common wrong answers

- A fixed 500 ms ticker `shutdownPollInterval`: that is Go 1.15 and earlier (`go1.15.15` server.go:2677
  `var shutdownPollInterval`, ticker at 2710). Backoff with jitter appears by `go1.16` (const at 2708).
- Line numbers from `master` (where `shutdownPollIntervalMax` is at 3395 and the import is `math/rand/v2`) or from
  another release.
- Saying Shutdown returns nil or `ErrServerClosed` when the context expires, or that it force-closes active or
  hijacked connections.
- Saying `Close` is what closes the idle connections, or giving the wrong cap (for example 1 s).

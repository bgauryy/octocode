# W10 answer key — Excalidraw's delete action (tsx @ f3d99c4)

Deleting is a soft delete: elements are copied with `isDeleted: true` and stay in the scene array. Paths are relative
to `packages/`.

**Bound text:** it is updated in `deleteSelectedElements`, at `actionDeleteSelected.tsx:124–125`. A text element bound
to a container (`isBoundToContainer(el)`) whose `containerId` is selected is itself marked
`newElementWith(el, { isDeleted: true })`, so a container's label, including an arrow's label, is deleted with it. When
a frame is deleted, a bound text among the frame's children selects its container instead (:64–67). If the bound text
alone is deleted, `fixBindingsAfterDeletion` → `BoundElement.unbindAffected` removes it from the container's
`boundElements`.

**Bound arrows:** they are unbound, not deleted, in two places.

1. In `deleteSelectedElements` (`actionDeleteSelected.tsx:97–111`), each **elbow** arrow in the deleted element's
   `boundElements` gets its `startBinding`/`endBinding` that pointed at the element set to `null` via
   `app.scene.mutateElement`. This happens before the element is marked deleted.
2. For every arrow, `fixBindingsAfterDeletion` → `BindableElement.unbindAffected` (binding.ts:2545) sets the
   `startBinding`/`endBinding` (or `containerId`) that points at a deleted element to `null` on each non-deleted bound
   element. When an arrow is itself deleted, `BoundElement.unbindAffected` (binding.ts:2429) removes it from the bound
   shapes' `boundElements`.

**Must contain:** the chain `onKeyDown` → `ActionManager.handleKeyDown` → `actionDeleteSelected` (`keyTest` and
`perform`) → `deleteSelectedElements` → `newElementWith(…, { isDeleted: true })`, with files and lines (±2 lines).
Bound text marked deleted at `actionDeleteSelected.tsx:124–125`. Arrows unbound, not deleted: `fixBindingsAfterDeletion`
in `binding.ts`, plus the elbow-arrow special case at `actionDeleteSelected.tsx:97–111`.

**Optional:** `syncActionResult`/`replaceAllElements`; the linear-editor point-deletion branch; `handleGroupEditingState`
and the frame-children handling; the two `unbindAffected` methods by name; how the handler is attached
(`handleKeyboardGlobally`); that `actionCut` (`actionClipboard.tsx:119`) reuses `actionDeleteSelected.perform`.

**Common wrong answers:**
- Citing the Ctrl/Cmd+Delete branch (App.tsx:6023–6028, opens the clear-canvas dialog) as the delete path. `keyTest`
  excludes Ctrl/Cmd.
- Saying elements are removed or spliced out of the scene. They are copied with `isDeleted: true`.
- Naming `mutateElement` as the function that marks elements deleted. Here `newElementWith` does it;
  `mutateElement` only clears bindings.
- Saying arrows bound to a deleted shape are deleted, or that bound text is only unbound. The reverse is true: arrows
  are unbound and bound text is deleted.
- Missing `fixBindingsAfterDeletion`, or missing the elbow-arrow handling inside `deleteSelectedElements`.
- Tracing `onKeyDownFromPointerDownHandler` (App.tsx:10655) or `handleNavigationModeKeyDown` (App.tsx:3266) as the
  entry. The second also calls `actionManager.handleKeyDown`, but it is registered only for the non-interactive
  editor.

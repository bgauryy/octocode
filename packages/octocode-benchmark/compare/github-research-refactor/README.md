# Frozen GitHub research refactor evaluation

Ten public-source research questions, one baseline and one candidate attempt each (20 total maximum), fresh isolated app-server sessions at gpt-6-astra/high. Freeze this protocol and cases before baseline. Baseline runs before the changed runtime is built; candidate runs only after implementation is frozen. No per-case feedback is supplied to implementation workers. Public tasks are exploratory, not held-out generalization evidence.

Primary KPI: sum of actual host input plus output tokens. PROMISING requires at least 5% reduction, 10/10 correct in each arm, every requested fact and citation directly verified from model-visible source, and no increase in tool errors. Invalid/incomplete comparisons are INCONCLUSIVE and expose no token-reduction number. Provider usage remains unknown absent real receipts. Cached input, calls, errors, optional Clasify calls, and wall time are secondary; concurrent builds may confound wall time.

Catalog descriptions and canonical core instructions are the treatment. Identical GitHub capabilities plus optional Clasify in both arms. Every observed startup catalog must match its arm's frozen catalog; duplicate identical catalogs are legitimate. No output schema is exported by MCP. Solver output schema only fixes answer formatting. One attempt per task/arm, 12 calls, 50 classification cells, 180 seconds. No tuning to the cases or automatic retries.

Reuse hardened graph-research-v1 stableCatalog/toolFailed/credential cleanup and the existing app-server runner. GitHub admission blocks all local tools, nested local resources, clones, other repositories, and non-pinned source reads. Solvers receive only one task, an empty temporary workspace, and the frozen subject. Evaluator files and other task answers cannot be retrieved by admitted tools. Shell/browser/apps/skills/project instructions/shared communication are disabled by the shared runner. Credentials are removed in finally. GitHub corpus remains public and may be in model pretraining; direct tool evidence is mandatory.

Answers use exact requested scalar/tuple forms with whitespace normalization only. Citation line must contain a frozen deciding statement and be present in actual successful ghGetFileContent result, at the pinned SHA, not merely an encompassing advertised range. Multi-source tasks require all sources. History answers require matching observed commit metadata and a commit URL. Grader self-tests cover positive, negative, missing source, wrong ref, fabricated source, incomplete multi-source, and duplicate catalogs before freeze. Corrections require a new campaign and both arms rerun, not post hoc scoring changes.

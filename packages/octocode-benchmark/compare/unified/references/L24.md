# L24 reference
## Question
In prometheus/prometheus at commit ea954809ce, which functions in the scrape package (non-test code) start goroutines, and what does each of those goroutines do?

## Key facts (graded)
1. Exactly six functions, with seven `go` statements, in `scrape/manager.go` and `scrape/scrape.go` (the other non-test files `clientprotobuf.go`, `metrics.go`, `scrape_append_v2.go`, `st_synthesis.go`, `target.go` start none).
2. `(*Manager).Run` (`manager.go:223`): `go m.reloader()` at 224 — the reloader loop applies target updates on a ticker (`DiscoveryReloadInterval`, default 5 s) when a reload was triggered, until `graceShut`. — evidence: `manager.go:223-242`, `manager.go:249-282`
3. `(*Manager).reload` (`manager.go:283`): one goroutine per target set at 310-313 that runs `sp.Sync(groups)` in parallel ("these take a while"), joined with a `WaitGroup`. — evidence: `manager.go:300-317`
4. `(*Manager).ApplyConfig` (`manager.go:365`): one goroutine per scrape pool at 434, limited to `runtime.GOMAXPROCS(0)` at once by the `canReload` channel; it stops the pool and marks it for deletion if its config is gone, otherwise updates the failure logger and calls `sp.reload(cfg)` when the config changed, recording failures. — evidence: `manager.go:425-458`
5. `(*scrapePool).stop` (`scrape.go:271`): one goroutine per loop at 281 that calls `l.stop()`, joined with a `WaitGroup`. — evidence: `scrape.go:271-295`
6. `(*scrapePool).restartLoops` (`scrape.go:355`): one goroutine per target at 399 that stops the old loop, then sets the forced error and failure logger on the new loop and runs it (`newLoop.run(nil)`). — evidence: `scrape.go:392-406`
7. `(*scrapePool).sync` (`scrape.go:485`): goroutines at 554 that stop loops of targets that disappeared, and `go l.run(nil)` at 582 that starts loops for new targets; it waits only for the stopping goroutines. — evidence: `scrape.go:545-590`

## Acceptable variations
- Line numbers ±2.
- Describing the reloader without the `DiscoveryReloadOnStartup` detail.
- Noting that `restartLoops` is reached from `reload` and that the loops' own `run` methods do not start goroutines in this package.

## Common wrong answers
- Missing either goroutine in `sync` (stop vs start) or the one in `stop`.
- Including test files or functions that only start a goroutine through a call (for example `Run` callers in `cmd/prometheus`).
- Attributing the `restartLoops` goroutine to `reload` or `sync`.

# G14 reference
## Question
Which GitHub repository hosts the Prometheus project's official Go instrumentation library, and in its v1.20.0 release, which bucket boundaries does a histogram get when none are configured, and when are those defaults not applied?

## Key facts (graded)
1. Repository: `prometheus/client_golang` ("Prometheus instrumentation library for Go applications"). Tag `v1.20.0` points to commit `73b811c54a628c7a7fe43005fb81351f64da9289`. — evidence: `gh api repos/prometheus/client_golang/git/ref/tags/v1.20.0`
2. Default buckets: `var DefBuckets = []float64{.005, .01, .025, .05, .1, .25, .5, 1, 2.5, 5, 10}`, documented as tailored to network-service response times in seconds. — evidence: `prometheus/histogram.go:261-265` @ v1.20.0
3. Where they apply: in `newHistogram`, `if len(h.upperBounds) == 0 && opts.NativeHistogramBucketFactor <= 1 { h.upperBounds = DefBuckets }`. — evidence: `prometheus/histogram.go:563-565` @ v1.20.0
4. Not applied when the histogram is configured as a native (sparse) histogram, that is when `NativeHistogramBucketFactor > 1` and no classic buckets are given (it then has no classic buckets). They are also not applied when explicit `Buckets` are given. — evidence: same lines; `histogram.go:566-568` sets the native schema only when the factor is > 1

## Acceptable variations
- Listing the buckets as 5ms … 10s.
- Mentioning that `DefBuckets` is also referenced in the `HistogramOpts.Buckets` doc comment (`histogram.go:~393`).
- Line numbers ±3.

## Common wrong answers
- Naming `prometheus/prometheus` or `prometheus/client_model` as the library repository.
- Wrong bucket values (for example the exponential or linear helper outputs) or a missing bound such as `.005` or `10`.
- Claiming the defaults always apply, ignoring the native-histogram condition.

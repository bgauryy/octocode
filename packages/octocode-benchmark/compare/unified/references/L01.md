# L01 reference
## Question
In django/django at commit 4fab678a07, how does the automatic redirect from a URL without a trailing slash to the one with a slash work?

## Key facts (graded)
1. Default is `APPEND_SLASH = True` in `django/conf/global_settings.py:242`.
2. For ordinary requests the redirect is issued in `CommonMiddleware.process_response` only when `response.status_code == 404` and `self.should_redirect_with_slash(request)` is true — evidence: `django/middleware/common.py:101-111` (condition at line 108). (`process_request` only consults it when a PREPEND_WWW redirect is already being sent, lines 51-61.)
3. `should_redirect_with_slash` (`django/middleware/common.py:63-75`) requires: `settings.APPEND_SLASH` and `request.path_info` not ending in `/` (line 68); the original path does NOT resolve (`not is_valid_path(request.path_info, urlconf)`, line 70) and the slashed path DOES resolve (`is_valid_path("%s/" % request.path_info, urlconf)`, line 71), using `request.urlconf` if set (line 69). `is_valid_path` (`django/urls/base.py:169-178`) returns the ResolverMatch from `resolve()` or False on `Resolver404`.
4. View opt-out: the matched view's `should_append_slash` attribute is returned (default True) at `django/middleware/common.py:73-74`; the `no_append_slash` decorator (`django/views/decorators/common.py:5-24`) wraps the view and sets `_view_wrapper.should_append_slash = False` (line 24).
5. `get_full_path_with_slash` (`django/middleware/common.py:77-99`) builds the path with `request.get_full_path(force_append_slash=True)` + `escape_leading_slashes`, and raises `RuntimeError` when `settings.DEBUG` and method in ("DELETE","POST","PUT","PATCH") (line 87-98) instead of redirecting.
6. Redirect class is `response_redirect_class = HttpResponsePermanentRedirect` (301), `django/middleware/common.py:33`, overridable by subclassing.
## Acceptable variations
- Citing `process_response` start at 101 or the `if` at 108; ranges ±1-2 lines.
- Mentioning additional APPEND_SLASH consumers (LocaleMiddleware `django/middleware/locale.py:57-60`, URL system check `django/urls/resolvers.py:173`, flatpages view/forms, redirects middleware, admin catch_all_view `django/contrib/admin/sites.py:468-477`) is a bonus, not required.
- Saying "301 permanent redirect" without naming the class is fine if the class attribute is otherwise clear.
- Describing the check as "resolve() both paths" is fine.
## Common wrong answers
- Claiming the redirect happens in `process_request` for all requests (it only does so alongside PREPEND_WWW).
- Claiming it redirects regardless of whether the slashed URL resolves, or that it triggers on non-404 responses.
- Claiming POST in DEBUG gets a 307/308 redirect preserving the body (it raises RuntimeError).
- Saying the default is False, or that the redirect is 302.
- Attributing the logic to `django/core/handlers/base.py` or to URL resolver code.

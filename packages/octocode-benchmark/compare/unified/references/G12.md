# G12 reference
## Question
In fastapi/fastapi at commit 4b3949cd9e, how is the `fastapi.security` package organized: which modules does it contain, which public classes does each module define, and which common base class do the security schemes share?

## Key facts (graded)
1. Modules in `fastapi/security/`: `__init__.py`, `api_key.py`, `base.py`, `http.py`, `oauth2.py`, `open_id_connect_url.py`, `utils.py`. — evidence: `gh api repos/fastapi/fastapi/contents/fastapi/security?ref=4b3949cd9e5932f76217131fceabc74145c3db24`
2. Classes per module @ 4b3949cd:
   - `base.py`: `SecurityBase` (line 4).
   - `api_key.py`: `APIKeyBase(SecurityBase)` (11), `APIKeyQuery` (55), `APIKeyHeader` (147), `APIKeyCookie` (235), all subclasses of `APIKeyBase`.
   - `http.py`: `HTTPBasicCredentials(BaseModel)` (16), `HTTPAuthorizationCredentials(BaseModel)` (29), `HTTPBase(SecurityBase)` (69), `HTTPBasic` (105), `HTTPBearer` (222), `HTTPDigest` (319), the last three subclass `HTTPBase`.
   - `oauth2.py`: `OAuth2PasswordRequestForm` (14), `OAuth2PasswordRequestFormStrict` (162), `OAuth2(SecurityBase)` (330), `OAuth2PasswordBearer(OAuth2)` (433), `OAuth2AuthorizationCodeBearer(OAuth2)` (547), `SecurityScopes` (653).
   - `open_id_connect_url.py`: `OpenIdConnect(SecurityBase)` (11).
   - `utils.py`: no class; the function `get_authorization_scheme_param` (splits an `Authorization` header into scheme and parameter).
3. Common base: every security scheme (API key, HTTP, OAuth2, OpenID Connect) derives from `fastapi.security.base.SecurityBase`, directly or through `APIKeyBase`, `HTTPBase` or `OAuth2`. The request-form classes, the credential models and `SecurityScopes` are not schemes and do not derive from it.
4. Public surface: `__init__.py:1-15` re-exports `APIKeyCookie`, `APIKeyHeader`, `APIKeyQuery`, `HTTPAuthorizationCredentials`, `HTTPBasic`, `HTTPBasicCredentials`, `HTTPBearer`, `HTTPDigest`, `OAuth2`, `OAuth2AuthorizationCodeBearer`, `OAuth2PasswordBearer`, `OAuth2PasswordRequestForm`, `OAuth2PasswordRequestFormStrict`, `SecurityScopes`, `OpenIdConnect`. `SecurityBase`, `APIKeyBase` and `HTTPBase` are not re-exported.

## Acceptable variations
- Line numbers ±3.
- Noting that `http.py` and `oauth2.py` use `get_authorization_scheme_param` from `utils.py`.
- Noting that `SecurityBase` only declares `model` and `scheme_name`.

## Common wrong answers
- Listing a module that does not exist at this commit (for example `oauth2_password.py` or `openid.py`).
- Claiming `OAuth2PasswordRequestForm` or `SecurityScopes` subclass `SecurityBase`.
- Claiming the credential classes (`HTTPBasicCredentials`, `HTTPAuthorizationCredentials`) are security schemes.

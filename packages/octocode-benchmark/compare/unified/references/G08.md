# G08 reference
## Question
What is the root cause of sveltejs/svelte issue #18837, and how was it fixed?

## Key facts (graded)
1. Root cause location: the `getOwnPropertyDescriptor` trap of the state proxy created in `proxy(value)` in `packages/svelte/src/internal/client/proxy.js` (lines ~206-227 at 6eb720a). `Object.hasOwn(proxy, prop)` invokes this trap. — evidence: `packages/svelte/src/internal/client/proxy.js:206-227` @ 6eb720a1b7cafca3ebe0ab5c76674272cd3044f9
2. Mechanism: the trap never creates a per-property source for a missing property and, when the target has no own descriptor, reads the existing source with the untracked `source?.v` (not `get(s)`); it only calls tracked `get(s)` when a descriptor with `value` exists AND a source already exists. So for a property that does not exist yet, no reactive dependency is registered and adding it (or deleting it) doesn't invalidate the expression. — evidence: `proxy.js:207-224` @ 6eb720a (`var value = source?.v;` at :214)
3. Contrast: the `has` trap (used by `prop in proxy`) creates a source (initialized to `UNINITIALIZED` when absent) whenever there's an `active_effect` and the prop is missing or a writable own property, and reads it via tracked `get(s)`, so later `set`/`deleteProperty` updates on that source re-run the dependent effect. — evidence: `proxy.js:229-263` @ 6eb720a (creation at :237-254, `get(s)` at :256)
4. Fix: PR #18838 "fix: make Object.hasOwn reactive for state proxies", squash-merged as a72dc8eadbf63189d9ae12e9ea18711378f8f12f (parent 6eb720a…). — evidence: https://github.com/sveltejs/svelte/pull/18838
5. Fix content: the trap now first calls `this.has?.(target, prop)` (reusing the `has` trap's source-creation eligibility, so prototype/non-writable inherited properties are not given sources and keep existing semantics), then if a source exists reads it with tracked `get(s)`, returns `undefined` when the value is `UNINITIALIZED`, otherwise patches/synthesizes the descriptor's `value`. A runtime-runes test `object-has-own-reactive` covers add and delete. — evidence: `packages/svelte/src/internal/client/proxy.js:206-232` @ a72dc8eadbf63189d9ae12e9ea18711378f8f12f; PR body
## Acceptable variations
- Line numbers ±3.
- Describing "`.v` read bypasses dependency tracking" as "peeks the value without subscribing" is equivalent.
- Citing the merge commit's short SHA a72dc8e is acceptable.
## Common wrong answers
- Blaming the `has` trap or the `get` trap as the root cause.
- Claiming `Object.hasOwn` goes through the `has` trap (it uses [[GetOwnProperty]] → `getOwnPropertyDescriptor`).
- Pointing to a compiler-side transform instead of the runtime proxy.
- Naming a different PR (e.g. #18864, which is about spread `value`).

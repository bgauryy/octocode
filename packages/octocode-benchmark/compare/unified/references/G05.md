# G05 reference
## Question
In psf/requests at commit 611c6162cb, how does a Session follow redirects, and what does it change about the request between hops?

## Key facts (graded)
1. `Response.is_redirect` is true when a `location` header is present and the status is in `REDIRECT_STATI` (301, 302, 303, 307, 308); `Session.send` (when `allow_redirects` defaults True) calls `self.resolve_redirects(r, request, **kwargs)` and collects the generator into `history`; `get_redirect_target` re-encodes the Location header latin1→utf8. — evidence: `src/requests/models.py:95-101,877-881`, `src/requests/sessions.py:134-152,773,802-805`
2. `should_strip_auth(old, new)`: strip if hostnames differ; do NOT strip for `http` (port 80/None) → `https` (port 443/None); do NOT strip when scheme unchanged and both ports are the scheme's default or None (`DEFAULT_PORTS = {"http": 80, "https": 443}`); otherwise strip iff port or scheme changed. `rebuild_auth` deletes `Authorization` only if present and `should_strip_auth` is true, then re-applies credentials from `.netrc` via `get_netrc_auth(url)` when `trust_env` is set. — evidence: `src/requests/sessions.py:154-184,309-332`, `src/requests/utils.py:85`
3. `rebuild_proxies` calls `resolve_proxies(prepared_request, proxies, self.trust_env)` (env proxies honoring NO_PROXY via `should_bypass_proxies`, using `setdefault` so explicit proxies win), always deletes any existing `Proxy-Authorization`, and re-adds a Basic `Proxy-Authorization` from the proxy URL's credentials only when the target scheme does not start with `https` (to avoid leaking it on TLS-tunneled requests; urllib3 handles it there). It runs before `rebuild_auth` in the loop. — evidence: `src/requests/sessions.py:334-367,271-273`, `src/requests/utils.py:911-939`
4. `rebuild_method`: 303 → GET (unless HEAD); 302 → GET (unless HEAD); 301 turns only POST into GET. For any status other than 307/308, `Content-Length`, `Content-Type`, `Transfer-Encoding` are removed and the body set to None; the `Cookie` header is always popped and rebuilt from the jar. — evidence: `src/requests/sessions.py:370-392,247-261`
5. Bound/history: each iteration appends to `hist`, and when `len(resp.history) >= self.max_redirects` raises `TooManyRedirects("Exceeded N redirects.")`; `max_redirects` defaults to `DEFAULT_REDIRECT_LIMIT = 30`. In `Session.send`, the original response is inserted at the front of the collected list, the last response is popped as the returned `r`, and `r.history` is set to the rest; with `allow_redirects=False` the next request is stored on `r._next` via `yield_requests=True`. — evidence: `src/requests/sessions.py:216-219,488`, `src/requests/models.py:103`, `src/requests/sessions.py:806-821`
## Acceptable variations
- Line numbers ±3.
- Status codes may be named (moved/found/see_other/temporary_redirect/permanent_redirect) instead of numbers.
- Mentioning fragment preservation / relative Location joining (`sessions.py:225-244`) or body rewinding is extra credit, not required.
## Common wrong answers
- Claiming Authorization is stripped on any scheme change including http→https on default ports.
- Claiming Authorization is stripped whenever the path/URL changes on the same host.
- Claiming 301 turns every method into GET, or that 307/308 drop the body.
- Claiming `Proxy-Authorization` is always re-added / kept for https targets.
- Claiming the default redirect limit is 10 or 20.

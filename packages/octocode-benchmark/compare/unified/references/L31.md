## Acceptable variations
- Using NuGet's display names (`.NETFramework4.5`, `.NETStandard2.0`, …).
- Mentioning that the csproj version numbers (`VersionPrefix 11.0.1`, `AssemblyVersion 11.0.0.0`) are placeholders that the build overrides (`csproj:6-10`; `Build/build.ps1:201-204`).

## Common wrong answers
- Reading the package version from the local csproj (11.0.1) and treating it as the release version.
- Saying `netstandard2.0` or `net6.0` was dropped.
- Comparing with a different release (for example 13.0.1) or with the default branch on GitHub instead of the local checkout.

# G01 reference
## Question
Review fastapi/fastapi PR #16403 ("Add native OpenTelemetry support"). What does it change in runtime behavior, and what should a reviewer watch out for?

## Key facts (graded)
1. New keyword-only `telemetry: TelemetryConfig | None = None` parameter on `FastAPI.__init__`; it is merged over defaults `tracer_provider/meter_provider/logger_provider=None`, `tracing/metrics/logs/operation_spans/auto_configure=True`, `exclude=None`, and stored as `self._telemetry`, then wrapped in `NativeTelemetry(...)`. — evidence: `fastapi/applications.py:67`, `fastapi/applications.py:1033-1045`
2. `FastAPI.__call__`: a `lifespan` scope is routed through `fastapi.telemetry._runtime.lifespan`, which on `lifespan.startup` calls `_configure_from_environment` (adds OTLP exporters from env unless `auto_configure` is False or `OTEL_SDK_DISABLED=true`) and flushes owned exporters on shutdown/failure; http/websocket requests go through `self._native_telemetry(...)`, BUT bypass it (plain `super().__call__`) when the scope type is not http/websocket, when `"fastapi.telemetry"` is already in the scope (nested/mounted FastAPI app), or when `NativeTelemetry.enabled()` is false (no explicit provider and global providers unconfigured for every enabled signal). `exclude(scope)` returning true also skips instrumentation (sets `scope["fastapi.telemetry"]=None`). — evidence: `fastapi/applications.py:1196-1226`, `fastapi/telemetry/_runtime.py:85-99,210-239`, `fastapi/telemetry/_asgi.py:172-196,227-233`
3. `build_middleware_stack` now inserts `Middleware(ExceptionTelemetryMiddleware)` immediately after `ServerErrorMiddleware` and before `self.user_middleware`; it catches `Exception`, records it via `_exception` (dedup per request, emits a log event `http.server.request.exception` / `fastapi.websocket.exception`) and re-raises, so exceptions are observed before the error handler turns them into a 500. — evidence: `fastapi/applications.py:1066-1070`, `fastapi/telemetry/_asgi.py:87-113,143-154`
4. Double instrumentation guard: `_legacy_otel(self.middleware_stack)` walks the built stack's `.app` chain looking for `opentelemetry.instrumentation.asgi.OpenTelemetryMiddleware`; if found, `NativeTelemetry.__call__` turns off native tracing, logs and metrics (`tracing = config["tracing"] and not legacy_otel`, etc.). — evidence: `fastapi/telemetry/_asgi.py:72-84`, `fastapi/telemetry/_asgi.py:235-244`, `fastapi/applications.py:1225`
5. Operation spans `fastapi.dependencies`, `fastapi.endpoint`, `fastapi.serialization` (routing) and `fastapi.background_task` (new `BackgroundTasks.__call__`) are created via `_operation(...)`/`_traced_operation` (span name `f"fastapi.{name}"`, `code.function.name` attribute), only when `operation_spans` is enabled (tracer passed as None otherwise); sync endpoints run `_run_sync_endpoint` inside `run_in_threadpool` so the `fastapi.endpoint` span is opened in the worker thread. — evidence: `fastapi/routing.py:359,362-364,498,748,809,828`, `fastapi/background.py:64-67`, `fastapi/telemetry/_api.py:186-240`, `fastapi/telemetry/_asgi.py:320`
6. Packaging: `opentelemetry-api>=1.44.0` becomes a hard runtime dependency of fastapi (every install pulls it), while the SDK and `opentelemetry-exporter-otlp-proto-http` are added to a new `opentelemetry` extra and to `standard`, `standard-no-fastapi-cloud-cli` and `all`; automatic export fails with an error pointing to `fastapi[opentelemetry]` if the SDK is missing. — evidence: `pyproject.toml:50,61-64,66-67,87-88,107-108`, `fastapi/telemetry/_runtime.py:130`
## Acceptable variations
- Line numbers ±3; citing the diff hunk instead of the file is fine.
- Describing enabled() as "only active when an OpenTelemetry SDK provider is configured (or passed explicitly)" is correct.
- Mentioning that metrics are not recorded for websockets (`metering = ... and not is_websocket`, `_asgi.py:244`) is a bonus, not required.
- Also noting `_route_selected` calls in routing (http.route attribute) or `_validation_failed` on validation errors is fine extra detail.
## Common wrong answers
- Claiming OpenTelemetry is entirely optional / only in an extra (the API package is a required dependency).
- Claiming the exception middleware is placed innermost (next to ExceptionMiddleware) or after user middleware.
- Claiming FastAPI detects contrib via the `_is_instrumented_by_opentelemetry` flag (the code explicitly checks the built stack instead).
- Saying telemetry is off by default (defaults are all True; it is inert only while no providers are configured).

# L02 reference
## Question
In django/django at commit 4fab678a07, where does Django stop you from saving an object whose foreign key points to an unsaved instance, and how does that check work?

## Key facts (graded)
1. The guard is `Model._prepare_related_fields_for_save(self, operation_name, fields=None)` in `django/db/models/base.py:1276`.
2. Callers: `Model.save()` (`django/db/models/base.py:864`, operation_name="save"); `QuerySet._prepare_for_bulk_create` (`django/db/models/query.py:794`, "bulk_create", itself called from `bulk_create` at query.py:920); `QuerySet.bulk_update` (`django/db/models/query.py:1042-1043`, "bulk_update", passing `fields=fields` so only updated fields are checked, per base.py:1282-1283).
3. Raise condition: for each concrete field that `is_relation` and `is_cached(self)` (base.py:1286), with a truthy related `obj` (1287-1289), if `not obj._is_pk_set()` (1296) it raises `ValueError("%s() prohibited to prevent data loss due to unsaved related object '%s'.")` (1300-1303). A manually assigned pk passes the check (comment 1290-1295): Django lets the DB raise IntegrityError instead.
4. Before raising, if the reverse side is not multiple (one-to-one), it removes the object from the related instance cache: `field.remote_field.delete_cached_value(obj)` (base.py:1298-1299).
5. Saved-after-assignment housekeeping: if the local attname value is in `field.empty_values` or is an `Expression`, it re-assigns `setattr(self, field.name, obj)` to copy the now-set pk (base.py:1304-1309); and if `obj`'s target-field value differs from `self`'s attname value, it clears the cached relation via `field.delete_cached_value(self)` (1312-1315).
6. Generic foreign keys: a second loop over `self._meta.private_fields` (base.py:1317-1330) checks cached fields having `fk_field` and raises the same message (f-string) when `obj and not obj._is_pk_set()`.
## Acceptable variations
- `asave()`/`abulk_create()` reaching the same code via their sync counterparts may be mentioned.
- Line ranges ±2; naming `bulk_create`'s own def line (query.py:861) instead of 920 is fine.
- Wording like "pk is None/unset" for `_is_pk_set()` (defined `django/db/models/base.py:716`).
## Common wrong answers
- Claiming the check happens at assignment time inside the ForwardManyToOneDescriptor `__set__`.
- Claiming it is in `save_base`/`_save_table` or raises IntegrityError/TypeError.
- Omitting bulk_update or claiming bulk_update checks all fields.
- Claiming a manually set pk on an unsaved object is rejected.
- Claiming GenericForeignKey isn't covered.

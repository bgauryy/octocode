# L03 reference
## Question
In django/django at commit 4fab678a07, how do callbacks registered with `transaction.on_commit` get stored, discarded and eventually run?

## Key facts (graded)
1. Registration: `transaction.on_commit(func, using=None, robust=False)` (`django/db/transaction.py:142-147`) delegates to `BaseDatabaseWrapper.on_commit` (`django/db/backends/base/base.py:727`), which inside an atomic block appends the tuple `(set(self.savepoint_ids), func, robust)` to `self.run_on_commit` (base.py:730-732).
2. Outside an atomic block: if autocommit is off it raises `TransactionManagementError("on_commit() cannot be used in manual transaction management")` (base.py:733-736); in autocommit mode it calls `func()` immediately, with robust wrapping in try/except + `logger.exception` (base.py:737-747).
3. Savepoint rollback: `Atomic.__exit__` on exception with an inner savepoint calls `connection.savepoint_rollback(sid)` (`django/db/transaction.py:296`), and `savepoint_rollback` filters `run_on_commit` to drop entries whose recorded sids contain that `sid` (base.py:415-420). A full `rollback()` clears `run_on_commit` entirely (base.py:341).
4. Outermost success: `Atomic.__exit__` calls `connection.commit()` (transaction.py:276); `commit()` does not run hooks — it only sets `self.run_commit_hooks_on_set_autocommit_on = True` (base.py:330), deferring them until autocommit is restored so callbacks execute after the transaction is fully finished (outside any transaction).
5. In the `finally` of `Atomic.__exit__`, when leaving the outermost block, `connection.set_autocommit(True)` is called (transaction.py:315-320); `set_autocommit` checks `if autocommit and self.run_commit_hooks_on_set_autocommit_on` and calls `self.run_and_clear_commit_hooks()` then resets the flag (base.py:490-492).
6. `run_and_clear_commit_hooks` (base.py:749-766) swaps the list out (`self.run_on_commit = []`), runs callbacks FIFO via `pop(0)`; robust callbacks' exceptions are caught and logged ("Error calling %s in on_commit() during transaction (%s)."), non-robust exceptions propagate (remaining queued callbacks are then not run since the list was already detached).
## Acceptable variations
- Citing `Atomic.__exit__` start (transaction.py:237) rather than individual lines.
- Mentioning `savepoint_commit(sid)` after rollback (transaction.py:299) or durable/closed_in_transaction branches is fine.
- Saying hooks run "when autocommit is restored" is equivalent to fact 5.
## Common wrong answers
- Claiming callbacks run directly inside `commit()` or `Atomic.__exit__`.
- Claiming inner savepoint rollback discards all callbacks, or that savepoint release (success) triggers callbacks.
- Claiming callbacks run LIFO or concurrently.
- Claiming on_commit outside a transaction is queued/ignored, or always raises.
- Claiming robust errors propagate.

# L27 reference
## Question
In prometheus/prometheus at commit ea954809ce, a scrape config's `metric_name_validation_scheme` setting is parsed into a type that comes from a dependency. Which module and version provide that type, according to the checkout's dependency pins, and at that version, which values does it accept and what does each value allow in metric and label names?

## Key facts (graded)
1. Local side: the field is `MetricNameValidationScheme model.ValidationScheme` with YAML key `metric_name_validation_scheme` in both the global config (`config/config.go:528`) and `ScrapeConfig` (`config/config.go:851`); `model` is `github.com/prometheus/common/model`. The global default is `model.UTF8Validation` (`config/config.go:191`); an unset scrape-level value inherits the global one (`config/config.go:1002-1009`).
2. Pin: `go.mod:69` requires `github.com/prometheus/common v0.71.0` (tag `v0.71.0` → commit `9a4aff03c12e71d3fc29e32a4581deb8e456d88e`).
3. Type at v0.71.0: `type ValidationScheme int` with `UnsetValidation` (iota), `LegacyValidation`, `UTF8Validation`; `String()` gives `"unset"`, `"legacy"`, `"utf8"`. — evidence: `model/metric.go:62-93` @ v0.71.0
4. Accepted values: YAML/JSON unmarshalling go through `Set`, which accepts `""` (leaves the value unchanged, so it stays unset), `"legacy"` and `"utf8"`, and returns `unrecognized ValidationScheme` for anything else. — evidence: `model/metric.go:107-150` @ v0.71.0
5. What each allows:
   - `legacy`: metric names must be non-empty and use only `[a-zA-Z_:]` with digits allowed after the first character (`isValidLegacyRune`, `metric.go:548-550`); label names the same but without `:` (`IsValidLabelName`, `metric.go:176-188`; also `LabelNameRE = ^[a-zA-Z_][a-zA-Z0-9_]*$`, `model/labels.go:100`).
   - `utf8`: any non-empty valid UTF-8 string for both metric and label names (`metric.go:165-169`, `metric.go:189-193`).
   - `unset`: not valid for name checks (`IsValidMetricName`/`IsValidLabelName` panic on it); Prometheus fills it from the global setting before use.
   — evidence: `model/metric.go:152-197` @ v0.71.0

## Acceptable variations
- Line numbers ±3 on either side.
- Writing the legacy patterns as regexes (`^[a-zA-Z_:][a-zA-Z0-9_:]*$` for metric names).
- Mentioning the related `metric_name_escaping_scheme` defaults (`config/config.go:1011-1040`) is extra information.
- Mentioning the deprecated global `model.NameValidationScheme = UTF8Validation` (`metric.go:51`) and Prometheus's check that it stays UTF-8 (`config/config.go:990-993`).

## Common wrong answers
- Naming `prometheus/client_golang` or `client_model` as the provider, or a different `prometheus/common` version.
- Claiming `legacy` allows `:` in label names, or that `utf8` allows empty names.
- Claiming the YAML values are `Legacy`/`UTF8` in other casing, or that unknown values silently fall back.

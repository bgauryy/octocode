# G18 reference
## Question
For the npm package undici@6.21.0: which Node.js versions does it declare support for, which source commit was it published from, and in that release what default timeouts does a `Client` use for response headers, response bodies and keep-alive connections?

## Key facts (graded)
1. Engines: `"node": ">=18.17"`. — evidence: npm registry `https://registry.npmjs.org/undici/6.21.0` (`engines`); `package.json` @ tag v6.21.0
2. Source commit: `61ec3531a64ffeec953a990c11735ff09455de4e` in `nodejs/undici` — the registry's `gitHead` for 6.21.0, and the commit that tag `v6.21.0` points to. — evidence: npm registry `gitHead`; `gh api repos/nodejs/undici/git/ref/tags/v6.21.0`
3. Header and body timeouts: `headersTimeout` and `bodyTimeout` both default to `300e3` ms (300 s). — evidence: `lib/dispatcher/client.js:238-239` @ v6.21.0
4. Keep-alive: `keepAliveTimeout` defaults to `4e3` ms, `keepAliveMaxTimeout` to `600e3` ms, `keepAliveTimeoutThreshold` to `2e3` ms. — evidence: `lib/dispatcher/client.js:229-231` @ v6.21.0

## Acceptable variations
- Values written in seconds (300 s, 4 s, 600 s, 2 s).
- Omitting `keepAliveTimeoutThreshold`.
- Mentioning that a server `Keep-Alive: timeout=` hint can override the keep-alive timeout, bounded by `keepAliveMaxTimeout`.
- Line numbers ±3.

## Common wrong answers
- Giving defaults from undici 7.x/8.x or from Node's built-in `http` module.
- Claiming there is no default body or headers timeout.
- Naming a commit on the default branch instead of the release commit.

# L30 reference
## Question
tokio-rs/tokio PR #8546 fixes an index-wraparound bug in the mpsc channel. Does tokio-rs/tokio at commit facc6fc47e still have that bug? Where are the affected spots in that checkout, and what does the PR change at each one?

## Key facts (graded)
1. Yes. PR #8546 "sync: fix mpsc index wraparound in block reclamation" (fixes #8545 "MPSC rollover frees a block still held by a producer") was merged 2026-10-02 into the `tokio-1.51.x` branch as `8513291fda51999116a200f178f59e843d858637`; the local checkout still has the old code at all three spots below. Effect (PR body): when `tail_position` wraps past `usize::MAX`, the receiver can reclaim a block that a slower sender still reads, a data race / use-after-free, reachable on 32-bit targets after 2^32 messages.
2. `Block::has_value` — local `tokio/src/sync/mpsc/block.rs:180-185`: `if slot_index < self.header.start_index { return false; }` and `if slot_index >= self.header.start_index + super::BLOCK_CAP { return false; }`. PR: one check, `if start_index(slot_index) != self.header.start_index { return false; }`.
3. `Block::grow` — local `block.rs:357-361`: `Block::new(self.header.start_index + BLOCK_CAP)`. PR: `self.header.start_index.wrapping_add(BLOCK_CAP)`.
4. `Rx::reclaim_blocks` — local `tokio/src/sync/mpsc/list.rs:391-405`: `if required_index > self.index { return; }`. PR: `if required_index.wrapping_sub(self.index) as isize > 0 { return; }` (a wrap-safe "is ahead" comparison).
5. Test support: the PR adds `list::channel_from_index` (and makes `list::channel()` call it with 0), a non-test `chan::channel_from_list` helper, and the test-only (`#[cfg(all(test, not(loom)))]`) `chan::channel_from_index` and `unbounded::unbounded_channel_from_index`, plus a `wraparound` unit test in `list.rs` that starts the channel near `usize::MAX`. — evidence: https://github.com/tokio-rs/tokio/pull/8546/files

## Acceptable variations

- Noting that `Block::try_push` already used `wrapping_add` when it re-numbers a block (`block.rs:328-329`), so the bug was the inconsistent plain `+` and comparisons elsewhere.

- Missing `reclaim_blocks` (the comparison that lets the receiver free a block too early).
- Describing the fix as switching to atomics or locks.

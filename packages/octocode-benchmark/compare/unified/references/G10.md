# G10 reference
## Question
Review tokio-rs/tokio PR #8156 ("net: enable Miri tests for TCP socket"). What does it change, and which networking tests still don't run under Miri, and why?
## Key facts (graded)
1. The PR (merged as 32312ae0d6f0b1c6457f1323e3e7f568f448d0db, base c6d58ce7e7bf4a6e7e6efc1ffeb42daa3a627c17, 37 files) lets TCP tests run under Miri: it removes the crate-level `not(miri)` gates and "No `socket` on miri" ignores from the TCP test files (`tokio/tests/tcp_accept.rs`, `tcp_connect.rs`, `tcp_echo.rs`, `tcp_into_split.rs`, `tcp_into_std.rs`, `tcp_peek.rs`, `tcp_shutdown.rs`, `tcp_socket.rs`, `tcp_split.rs`, `tcp_stream.rs`) and from the TCP doc examples in `tokio/src/net/tcp/{listener,socket,stream}.rs`; CI's Miri nightly moves from nightly-2026-04-27 to nightly-2026-05-20.
2. TCP tests still ignored under Miri, each with a stated reason: `SO_LINGER` unsupported (`tcp_shutdown.rs`, `tcp_socket.rs` linger tests, `tcp_stream.rs` set_linger); binding before connecting unsupported (`tcp_socket.rs`); `TCP_NODELAY` only supported on connected sockets (`tcp_socket.rs`); TClass/TOS not supported (`tcp_socket.rs` cfg(not(miri))); a Miri memory leak when `readv` returns an error (`tcp_stream.rs`, rust-lang/miri#5054).
3. UDP and Unix-domain-socket tests stay excluded; their "No `socket`" comments are reworded to "No UDP sockets" / "No Unix domain sockets" (e.g. `tokio/tests/udp.rs`, `uds_*.rs`, `tokio/src/net/udp.rs`, `tokio/src/net/unix/...`).
4. Other remaining exclusions get specific reasons: Miri only processes host I/O events when switching into the scheduler (rust-lang/miri#5047; `io_copy_bidirectional.rs`, `rt_common.rs`), leaked threads (#7010, `rt_common.rs`), "Too slow on miri" (`rt_threaded.rs`, `rt_common.rs`), no `mkfifo` (`net_unix_pipe.rs`), no quickack option (`net_quickack.rs`).
5. `tcp_echo.rs` uses a lower iteration count under Miri.
## Acceptable variations
- Listing a representative subset of the enabled TCP test files is fine if the change's scope (TCP enabled, UDP/UDS still excluded) is clear.
- Grouping reasons without naming every file is fine for fact 4.
## Common wrong answers
- Saying all networking tests now run under Miri (UDP and Unix sockets stay excluded).
- Omitting the reasons for the still-ignored TCP tests.

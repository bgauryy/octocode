# L06 reference
## Question
In vercel/next.js at commit d155ba9ebf, how does the `generateEtags` config option end up affecting HTTP responses?

## Key facts (graded)
1. Default/validation: `generateEtags: true` in the default config (`packages/next/src/server/config-shared.ts:2213`); schema `generateEtags: z.boolean().optional()` (`packages/next/src/server/config-schema.ts:670`).
2. Classic server path: the `BaseServer` constructor destructures `generateEtags` from `this.nextConfig` (`server/base-server.ts:540`) into `this.renderOpts.generateEtags` (line 577); at response time it reads `const { generateEtags, poweredByHeader } = this.renderOpts` (line 2152) and calls `this.sendRenderResult(req, res, { result: body, generateEtags, ... })` (2169-2174), which `NextNodeServer.sendRenderResult` (`server/next-server.ts:549-567`) forwards to `sendRenderResult` in `server/send-payload.ts`.
3. Route-module path: handlers call `send-payload`'s `sendRenderResult` directly with `generateEtags: nextConfig.generateEtags` — e.g. `server/route-modules/pages/pages-handler.ts:727-742` (line 739) and `build/templates/app-page-runtime.ts` (import at line 78; e.g. lines 1801-1811, flag at 1804).
4. Decision in `sendRenderResult` (`server/send-payload.ts:35-93`): `const payload = result.isDynamic ? null : result.toUnchunkedString()` (line 64) and ETag only `if (generateEtags && payload !== null)` (line 66). `isDynamic` is `typeof this.response !== 'string'` (`server/render-result.ts:195-197`) — streamed/dynamic results never get an ETag.
5. Value: `generateETag(payload)` (`server/lib/etag.ts:46-51`) returns a strong tag (`weak` defaults false) `"` + `fnv1a52(payload).toString(36)` + `payload.length.toString(36)` + `"`.
6. 304 + static files: `sendEtagResponse` (`server/send-payload.ts:11-33`) sets the `ETag` header and, if `fresh(req.headers, { etag })`, sets `statusCode = 304`, ends the response and returns true, so `sendRenderResult` returns early (lines 67-70). For static files, `server/lib/router-server.ts:662-666` passes `etag: config.generateEtags` to `serveStatic`.
## Acceptable variations
- Citing any of the other `sendRenderResult` calls in `app-page-runtime.ts` (1819-1826, 1922-1953, 2004-2088, ~2154) for fact 3.
- Mentioning `poweredByHeader` flowing alongside (X-Powered-By set only for HTML, send-payload.ts:54-56) is fine.
- Line numbers ±2.
## Common wrong answers
- Claiming the ETag is an MD5/SHA hash or is computed for streamed responses.
- Claiming ETags are computed in router-server/middleware for rendered pages, or in `app-render.tsx`.
- Claiming the default is false.
- Claiming route handlers (`route.ts`) get Next-generated ETags via this flag (no `generateEtags` usage in the app-route template/module).

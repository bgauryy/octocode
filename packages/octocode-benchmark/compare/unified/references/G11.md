# G11 reference
## Question
In encode/httpx at commit b5addb64f0, which transport implementations ship with the package, which module defines each one, and which of them can be used with the synchronous `Client`, the `AsyncClient`, or both?

## Key facts (graded)
1. The transports live in the `httpx/_transports/` package, which holds exactly `__init__.py`, `asgi.py`, `base.py`, `default.py`, `mock.py` and `wsgi.py`. — evidence: `gh api repos/encode/httpx/contents/httpx/_transports?ref=b5addb64f0161ff6bfe94c124ef76f6a1fba5254`
2. Base interfaces: `BaseTransport` (sync, `base.py:14`) and `AsyncBaseTransport` (async, `base.py:65`). — evidence: `httpx/_transports/base.py:11,14,65` @ b5addb64
3. Concrete transports and their side:
   - `HTTPTransport(BaseTransport)` — sync, `default.py:135`;
   - `AsyncHTTPTransport(AsyncBaseTransport)` — async, `default.py:279`;
   - `ASGITransport(AsyncBaseTransport)` — async only, `asgi.py:63`;
   - `WSGITransport(BaseTransport)` — sync only, `wsgi.py:44`;
   - `MockTransport(AsyncBaseTransport, BaseTransport)` — both, `mock.py:15`.
   — evidence: the `class` lines above @ b5addb64
4. All seven names (`ASGITransport`, `AsyncBaseTransport`, `BaseTransport`, `AsyncHTTPTransport`, `HTTPTransport`, `MockTransport`, `WSGITransport`) are re-exported by `_transports/__init__.py:7-15` and by the top-level `httpx/__init__.py` (`from ._transports import *` at line 10, and listed in `__all__`). — evidence: `httpx/_transports/__init__.py:1-15`, `httpx/__init__.py:10,33-99` @ b5addb64

## Acceptable variations
- Calling `HTTPTransport`/`AsyncHTTPTransport` the "default" (httpcore-backed) transports.
- Mentioning the stream helpers (`ResponseStream`, `AsyncResponseStream`, `ASGIResponseStream`, `WSGIByteStream`) as non-transport classes in the same modules is fine.
- Line numbers ±2.

## Common wrong answers
- Saying `ASGITransport` works with the sync `Client` or that `WSGITransport` works with `AsyncClient`.
- Saying `MockTransport` is sync-only or async-only.
- Listing a transport module that does not exist at this commit (for example a separate `http2.py` or `urllib3` transport).

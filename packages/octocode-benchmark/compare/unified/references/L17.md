# L17 reference
## Question
In JamesNK/Newtonsoft.Json at commit 52fa3aef1f, how are required members enforced when deserializing an object?

## Key facts (graded)
1. `DefaultContractResolver.SetPropertySettingsFromAttributes` copies `property._required = propertyAttribute._required` when a `[JsonProperty]` is present; only when there is NO `[JsonProperty]` does `[DataMember]` apply (`IsRequired ? Required.AllowNull : Required.Default`); then, unconditionally after both, `[JsonRequired]` sets `property._required = Required.Always` — so `[JsonRequired]` wins. — evidence: `Src/Newtonsoft.Json/Serialization/DefaultContractResolver.cs:1518-1519`, `DefaultContractResolver.cs:1546-1548`, `DefaultContractResolver.cs:1575-1577`, `DefaultContractResolver.cs:1585-1588`
2. Class-wide default: `[JsonObject(ItemRequired = ...)]` is copied to `contract.ItemRequired = attribute._itemRequired` in `CreateObjectContract`; at check time the effective value is `property.Ignored ? Required.Default : property._required ?? contract.ItemRequired ?? Required.Default` (member's nullable `_required` falls back to the contract's `ItemRequired`). — evidence: `DefaultContractResolver.cs:361-364`, `Src/Newtonsoft.Json/Serialization/JsonSerializerInternalReader.cs:2677`
3. Presence tracking gate: `PopulateObject` builds `propertiesPresence = contract.Properties.ToDictionary(m => m, m => PropertyPresence.None)` only if `contract.HasRequiredOrDefaultValueProperties` (true when `ItemRequired != Default`, or any property has `Required != Default` or `DefaultValueHandling.Populate`) or the serializer's `DefaultValueHandling` includes `Populate`; otherwise null (no checks). — evidence: `JsonSerializerInternalReader.cs:2466-2469`, `Src/Newtonsoft.Json/Serialization/JsonObjectContract.cs:143-170`
4. Recording: for each matched member `SetPropertyPresence` sets `PropertyPresence.Null` for `JsonToken.Null`/`Undefined` (and for a string that `CoerceEmptyStringToNull` coerces), else `PropertyPresence.Value`; after the object ends, `PopulateObject` loops all entries and calls `EndProcessProperty(..., presence, true)`. — evidence: `JsonSerializerInternalReader.cs:2526`, `JsonSerializerInternalReader.cs:2543`, `JsonSerializerInternalReader.cs:2726-2749`, `JsonSerializerInternalReader.cs:2581-2590`
5. Errors in `EndProcessProperty`: presence `None` + (`AllowNull` or `Always`) → "Required property '{0}' not found in JSON."; presence `Null` + `Always` → "Required property '{0}' expects a value but got null."; presence `Null` + `DisallowNull` → "Property '{0}' expects a non-null value." (`DisallowNull` with a missing member does not throw). Exceptions go through `IsErrorHandled`/`HandleError`, else rethrown. — evidence: `JsonSerializerInternalReader.cs:2671-2724` (throws at 2684, 2703, 2707; catch at 2712-2721)

## Common wrong answers
- Saying `[JsonProperty(Required=...)]` overrides `[JsonRequired]` (the opposite is true).
- Saying `[DataMember(IsRequired=true)]` maps to `Required.Always` (it maps to `AllowNull`) or that it applies even when `[JsonProperty]` is present.
- Pointing at `JsonSerializerInternalWriter` (serialization-side null check at line ~595) or the legacy `JsonValidatingReader`/schema code as the deserialization check.
- Claiming presence is always tracked for every object.

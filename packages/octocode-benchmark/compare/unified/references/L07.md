# L07 reference
## Question
In vercel/next.js at commit d155ba9ebf, how does calling the App Router's `redirect()` or `permanentRedirect()` on the server turn into an HTTP response?

## Key facts (graded)
1. Encoding: `getRedirectError` (`packages/next/src/client/components/redirect.ts:10-18`) creates `new Error('NEXT_REDIRECT')` with ``digest = `NEXT_REDIRECT;${type};${url};${statusCode};` `` (line 16). `redirect()` defaults `type` to `'push'` when `actionAsyncStorage.getStore()?.isAction` else `'replace'` and uses 307 (lines 38-40); `permanentRedirect()` uses 308 with default type `'replace'` (55-61). Codes: `SeeOther=303, TemporaryRedirect=307, PermanentRedirect=308` (`client/components/redirect-status-code.ts`).
2. Recognition/decoding: `isRedirectError` (`client/components/redirect-error.ts:18-42`) splits the digest on `;`, takes destination as `slice(2, -2).join(';')` and status as `at(-2)`, requiring code `NEXT_REDIRECT`, type `push|replace`, and a numeric status present in `RedirectStatusCode`. Decoders: `getURLFromRedirectError` (`redirect.ts:70-77`, same `slice(2,-2).join(';')` so `;` in URLs is preserved), `getRedirectTypeFromError` (79-85), `getRedirectStatusCodeFromError` (87-93).
3. Page render failing before shell (catch in `renderToStream`, `server/app-render/app-render.tsx:4386-4403`): `res.statusCode = getRedirectStatusCodeFromError(err)` (307/308), `metadata.statusCode` set, `location` header set to `addPathPrefix(url, basePath)`, and mutable cookies appended as `set-cookie`. (Same pattern in `prerenderToStream` at app-render.tsx:9839-9846.)
4. After streaming began: `makeGetServerInsertedHTML` (`server/app-render/make-get-server-inserted-html.tsx:56-73`) injects `<meta id="__next-page-redirect" http-equiv="refresh" content="{0|1};url={basePath-prefixed url}">` — delay 0 for 308 (permanent), 1 otherwise.
5. Route handler: `AppRouteRouteModule.handleHandlerError` (`server/route-modules/app-route/module.ts:424-449`) returns `new Response(null, { status, headers })` with `Location: url` (no basePath prefixing) plus mutable cookies; status is 303 if `actionStore.isAction`, else the digest status.
6. Server action (`handleAction`, `server/app-render/action-handler.ts:1324-1357`): fetch action → status 200 and `createRedirectRenderResult(...)` which sets `x-action-redirect: {url};{type}` (action-handler.ts:383, 393) and may include the target's Flight payload; non-fetch (MPA/no-JS) action → status 303 with `Location` header and empty body (`RenderResult.EMPTY`).
## Acceptable variations
- Client-side handling (`client/components/redirect-boundary.tsx:49-50`, `client/components/app-router.tsx:304-305`) is a bonus.
- Describing fact 3 via the prerender path only is acceptable if the status/location/basePath details match.
- Line numbers ±2.
## Common wrong answers
- Claiming `redirect()` uses 302/301 or that `permanentRedirect` is 301.
- Claiming the type default is always 'replace' (or always 'push').
- Claiming the destination is parsed as `split(';')[2]` (would truncate URLs with `;`).
- Claiming route handler redirects prefix basePath, or that server-action fetch redirects return 303.
- Claiming redirect after streaming sets a Location header / changes status.

# G06 reference
## Question
In encode/httpx at commit b5addb64f0, how does the synchronous Client decide whether a request goes through a proxy or connects directly?

## Key facts (graded)
1. `Client.__init__` computes `allow_env_proxies = trust_env and transport is None` and `proxy_map = self._get_proxy_map(proxy, allow_env_proxies)`; `_get_proxy_map` returns `{"all://": Proxy(proxy)}` for an explicit proxy, otherwise (if allowed) the environment map from `get_environment_proxies()` with each URL wrapped in `Proxy` (None stays None), else `{}`. So passing a custom `transport=` disables env proxies. — evidence: `httpx/_client.py:239-251,685-686`
2. `get_environment_proxies()` uses `urllib.request.getproxies()`; for `http`/`https`/`all` it produces `"{scheme}://"` keys (adding `http://` if the proxy value has no scheme). For each NO_PROXY entry: `*` → return `{}` (no proxies at all); entry containing `://` → used as-is → None; IPv4 → `all://<ip>` → None; IPv6 → `all://[<ip>]` → None; `localhost` → `all://localhost` → None; any other host → `all://*<host>` → None (so `.example.com` → `all://*.example.com`). A None value means "use the default transport". — evidence: `httpx/_utils.py:30-75`
3. `self._mounts` is built as `{URLPattern(key): None or self._init_proxy_transport(proxy, ...)}` from the proxy map, then updated with user `mounts` (same key → user override wins), then re-sorted with `dict(sorted(self._mounts.items()))`. `URLPattern.__lt__` compares `priority = (port_priority, -len(host), -len(scheme))` where a pattern with a port gets 0 (else 1), so rules with a port come first, then longer hosts, then longer (explicit) schemes. `_transport_for_url` returns the first matching pattern's transport, substituting the default `self._transport` when the value is None; no match → default transport. `_send_single_request` calls it per request. — evidence: `httpx/_client.py:697-716,760-769,1005`, `httpx/_utils.py:205-223`
4. `URLPattern.matches`: scheme must equal unless the pattern scheme is `all` (stored as ""); host checked via regex unless host empty/`*`; port must equal if given. Host regex: `*.example.com` → `^.+\.example\.com$` (subdomains only, not the apex); `*example.com` → `^(.+\.)?example\.com$` (apex and subdomains); plain host → exact. Keys without `:` raise `ValueError` ("Proxy keys should use proper URL forms..."). — evidence: `httpx/_utils.py:162-203`
5. `Proxy` accepts only `http`, `https`, `socks5`, `socks5h` URLs (else `ValueError("Unknown scheme for proxy URL ...")`), moving URL credentials into `auth`. `HTTPTransport` maps no proxy → `httpcore.ConnectionPool`, `http`/`https` proxy → `httpcore.HTTPProxy` (with proxy_auth/headers/ssl_context), `socks5`/`socks5h` → `httpcore.SOCKSProxy` (ImportError if `socksio` missing). — evidence: `httpx/_config.py:207-222`, `httpx/_transports/default.py:155-214`
## Acceptable variations
- Line numbers ±3. The async client mirrors the same logic (`httpx/_client.py:1399-1430,1474-1483`); citing it instead is acceptable.
- Describing ordering as "most specific first" is acceptable only if the port > host length > scheme length criteria are stated.
## Common wrong answers
- Claiming requests.Session-style per-request NO_PROXY evaluation at send time (httpx precomputes mounts at client construction).
- Claiming `.example.com` in NO_PROXY also excludes `example.com` (it becomes `*.example.com`, subdomains only).
- Claiming explicit `proxy=` is combined with env proxies (explicit proxy replaces the env map entirely).
- Claiming mounts are consulted in insertion order.

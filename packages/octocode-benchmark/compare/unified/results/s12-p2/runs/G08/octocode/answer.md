**Root cause:** The state proxy's `getOwnPropertyDescriptor` trap in `packages/svelte/src/internal/client/proxy.js` never subscribed to a per-property source for key existence. `Object.hasOwn(proxy, prop)` goes through that trap. The `has` trap (used by `prop in proxy`) does create that dependency. So `'x' in s` was reactive and `Object.hasOwn(s, 'x')` was not. This comes from the issue (#18837, "Object.hasOwn(proxy, prop) is not reactive") and the diff of the fix PR. I didn't read the pre-fix file directly.

**Fix:** PR #18838 ("Fixes #18837"), merged 2026-09-18. It changes the `getOwnPropertyDescriptor` trap in `proxy.js` (hunk at ~line 204) in three ways:
- **Dependency:** the trap now begins with `this.has?.(target, prop);`. That reuses the `has` trap's logic, so it creates the same per-property source with the same eligibility rules and inherited properties keep their existing behavior. Adding or deleting the property now invalidates the expression.
- **Restructure:** it reads `sources.get(prop)` once. If a source exists, it calls `get(s)`. If the value is `UNINITIALIZED` (the property was deleted or doesn't exist), it returns `undefined`.
- **Descriptor value:** when the real descriptor has a `value`, it substitutes the source's value. Otherwise it returns a synthetic `{enumerable: true, configurable: true, ...}` descriptor.

The PR also adds a patch changeset (`.changeset/reactive-has-own.md`). It adds a regression test, `tests/runtime-runes/samples/object-has-own-reactive/`, which clicks "add y" and "delete y" and checks that `Object.hasOwn(state,'y')` toggles between `true` and `false` in the DOM.

**Uncertainty:** the diff was truncated at the synthetic-descriptor return, so I didn't see the remaining lines of that hunk. I cite hunk offsets rather than exact post-merge line numbers.

# Terra with the Jev tool: candidate-only GitHub campaign

## Goal and comparison
Evaluate whether agents use the current pure Jev tool appropriately during complete GitHub investigations. Run only Octocode + optional Jev, as requested. No baseline runs. The canonical30 historical zero-Jev baseline used Sonnet in one continuous session with an older build; its correctness is context only. Do not compare its cached/session tokens with this campaign or attribute model/protocol differences to Jev.

## Cases and isolation
Use Q1–Q30 from compare/github-questions unchanged, one fresh Terra-medium session per case. They are reused public development questions, not contamination-free holdout. Freeze question bytes, compiled MCP/core instructions, native addon/binaries, proxy, response schema and protocol. No skill is loaded. Disable shell, web/browser, connectors, subagents and skill discovery. Expose only five remote read tools plus optional Jev through the logging MCP proxy. Each run has an empty workspace and separate Octocode home/cache. Remote refs/indexes remain live; record returned revisions and dates. Do not claim immutable GitHub search results.

The runner uses Codex app-server and its normal one-call approval interface. It approves only host-generated requests correlated with a pending call to the scoped Octocode server and one of the six authorized tools. Unknown elicitation forms and persistent grants are declined. No approval reviewer model participates. Retain approval receipts and actual thread model settings. Earlier failed exec preflights remain separate setup costs; they are not question attempts or baseline runs.

The MCP catalog is checked to contain exactly those six tools. This Codex version may still advertise generic built-in capabilities despite disabled feature flags; actual command, patch, browser and collaboration calls invalidate a run. Empty built-in resource discovery is permitted as setup, but returned external resources invalidate isolation. Do not claim prohibited built-in names were absent from the model's catalog.

## Budget and execution
One pass,30 candidate runs, maximum300seconds per run,40 ordinary queries including nested Jev retrieval,20 Jev questions. Run at most two independent questions concurrently; elapsed times are descriptive, not controlled latency comparisons. One separate infrastructure preflight is allowed before freezing the case-run schedule. No per-question retries or prompt tuning after case results. Preserve failures and costs. If instrumentation fails, stop and version the campaign before further cases. Model is requested as gpt-5.6-terra, effort medium; no independent model-bearing provider receipt is assumed.

## Measurements
Primary: source-verified completed questions/30. Correctness per canonical rubric0–10; research depth and workflow1–5, independently reviewed from cited/observed evidence. Missing or unsupported facts do not pass. Keep model-judged or historical-reference provisional grades distinct from verified grades. Historical answers/judges never enter solver prompts or tool surface.

Report actual host input, cached-input subset, output and total tokens from terminal usage receipts; do not count cached input twice. Report missing receipts as unknown. A250k host-token ceiling is ex-post eligibility, not an enforced token budget. Host tool-output limit is fixed at12,000tokens; proxy receipts preserve full responses but do not prove untruncated host ingestion. Record all costs including failed attempts. Separately sum Jev provider usage using attribution; usage unavailable on errors is unknown, never zero. Tool-visible bytes are diagnostics, not exact model ingestion.

Usage assessment: actual Jev calls/questions, Noul/Choice/Score mix, hidden tool contexts versus supplied values, repeated contexts/grouping, errors/repairs, and follow-up deciding reads. Jev use is optional; zero calls can be correct admission. Agent self-reported avoided work is not measured savings. Review whether each judgment changed a documented next action; uncertainty handling and unsupported conclusions matter more than call volume.

## Acceptance and rating
Publish all30 outcomes, completed/failed/invalid counts, source-grounded grades, tool-use metrics and cost distributions. No universal efficiency or calibration rating from anecdotes. A quality rating requires completed evidence grading; no causal Jev improvement percentage without a matched baseline. Judge implementation safety separately from agent adoption and task effectiveness. Stop on broken runtime/schema/auth, leaked grading access or missing usage instrumentation; retain the failing preflight/case.

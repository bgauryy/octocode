4. What is the fundamental architectural difference in their reconciliation strategies?

## Answer

- Vue's renderer/reconciler entry is `packages/runtime-core/src/renderer.ts`, centered on `patch()` and related functions such as `patchElement`, `patchChildren`, and component update effects.
- React's reconciler entry is in `packages/react-reconciler/src/ReactFiberWorkLoop.js` plus `beginWork`/`completeWork`/commit modules in `ReactFiberBeginWork.js`, `ReactFiberCompleteWork.js`, and commit files.
- Vue compares old/new VNodes directly in `patch()` using shape flags, patch flags, keyed diffing, and reactive effects; React builds and schedules Fiber work, computes changes during render, then applies them in a commit phase.
- Architecturally, Vue combines runtime VDOM patching with fine-grained reactive dependency triggering, while React schedules component-level Fiber reconciliation with lanes/priorities and an explicit render/commit split.

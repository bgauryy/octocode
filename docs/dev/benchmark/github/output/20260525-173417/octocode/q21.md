### Q21 — Vue 3 reactivity vs React hooks: dependency tracking

Using `vuejs/core` (`packages/reactivity/src/`) and `facebook/react` (`packages/react-reconciler/src/`):
1. Find the state/reactivity primitive in each.
2. How does Vue track which components depend on which reactive values?
3. How does React know which components to re-render?
4. What are the practical consequences of each approach for the developer?

## Answer

- Vue's primitive lives in `packages/reactivity/src/`: `ref`, `reactive`, `track`, and `trigger` store dependencies in a target/key dependency graph (`targetMap`/`Dep`).
- React's primitive lives in `packages/react-reconciler/src/ReactFiberHooks.js`: `useState` uses hook queues and `dispatchSetState` to schedule work on a Fiber.
- Vue tracks which reactive keys each active effect reads, so mutations trigger only dependent effects/components; React re-renders the scheduled component Fiber and reconciles its subtree.
- Practically, Vue gives automatic fine-grained dependency tracking, while React requires explicit hook ordering/state updates and relies on memoization to avoid extra component work.

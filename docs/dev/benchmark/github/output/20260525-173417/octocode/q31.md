### Q31 — Svelte 5 vs Vue 3: compile-time vs runtime reactivity

Using `sveltejs/svelte` and `vuejs/core`:
1. Where does reactivity live: compiler, runtime, or both?
2. Find the Svelte compiler's output for a `$state` variable vs Vue's `ref()` runtime call.
3. How does each framework know which part of the DOM to update when state changes?
4. What is the fundamental tradeoff between compile-time and runtime reactivity?

## Answer

- Svelte 5 reactivity is both compiler and runtime: the compiler recognizes `$state` runes and emits reads/writes against runtime signal/source primitives.
- Vue 3 reactivity is primarily runtime: `ref()`/`reactive()` in `packages/reactivity/src/` create tracked objects whose getters call `track` and setters call `trigger`.
- Svelte knows what DOM to update from compiler analysis plus generated effects; Vue knows through runtime dependency collection between render effects and reactive keys.
- The tradeoff is Svelte's compile-time optimization and less runtime bookkeeping versus Vue's flexible runtime tracking without requiring a Svelte-specific compiler for every reactive operation.

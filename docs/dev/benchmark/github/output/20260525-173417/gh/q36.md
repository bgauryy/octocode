## Answer

- Astro extracts island hydration directives in `withastro/astro` at `packages/astro/src/runtime/server/hydration.ts`.
- `HydrationMetadata` is the server-side description of an island hydration target: `{ directive: string; value: string; componentUrl: string; componentExport: { value: string } }`.
- `extractDirectives(inputProps, clientDirectives)` scans the props passed to a component and separates framework directives from normal component props.
- It recognizes `server:*`; specifically `server:root` sets `extracted.isPage = true`.
- It recognizes `client:*` props and lazily creates `extracted.hydration`. `client:component-path` fills `hydration.componentUrl`; `client:component-export` fills `hydration.componentExport.value`; `client:component-hydration` and `client:display-name` are marker/display props and are ignored.
- Any other `client:<name>` becomes the actual hydration directive: `hydration.directive = key.split(':')[1]` and `hydration.value = value` (for example `client:load`, `client:idle`, `client:visible`, `client:media`, etc.).
- It validates the directive against `clientDirectives`; an unsupported directive throws an error listing supported `client:*` methods.
- It has special validation for `client:media`: the directive value must be a string media query or it throws `AstroErrorData.MissingMediaQueryDirective`.
- Non-client props are copied into `props`, while `propsWithoutTransitionAttributes` excludes transition attributes such as `data-astro-transition-scope`, `data-astro-transition-persist`, and `data-astro-transition-persist-props`; symbol props are preserved in both.

## Answer

- PR `#7336` in `trpc/trpc` is `fix(server): handle React 19 proxy coercion in createInnerProxy`; it was merged on `2026-04-14T21:20:31Z`.
- Problem solved: React 19 can coerce proxy objects to primitives by calling `valueOf()`, `toString()`, or `toJSON()` during rendering, string interpolation, or logging. The recursive proxy returned by `createInnerProxy()` used to treat those property accesses/calls as normal route path segments, which could return another proxy, break primitive coercion, or recurse indefinitely.
- Changed file `packages/server/src/unstable-core-do-not-import/createProxy.ts`: adds special handling for coercion method calls. The final fix checks the last path segment in the `apply` trap; if it is `valueOf`, `toString`, or `toJSON`, it returns a debug string `tRPC.proxy(<path>)` based on `path.slice(0, -1).join('.')` instead of forwarding to the proxy callback.
- Changed file `packages/server/src/unstable-core-do-not-import/createProxy.test.ts`: adds `createRecursiveProxy() - handles React 19 proxy coercion keys`, covering root coercion (`proxy.valueOf()`, `proxy.toString()`, `proxy.toJSON()`), nested coercion (`proxy.foo.valueOf()`, `proxy.foo.bar.toString()`, `proxy.foo.bar.baz.toJSON()`), and normal chaining.
- Core technical fix: the PR initially tried a `get` trap guard, but that broke legitimate route names such as `proxy.toString.query()`. The merged fix moved the guard to the `apply` trap, so only direct invocation of coercion keys is intercepted while property access remains chainable.
- Why React 19 specifically: React 19's rendering/coercion paths may call primitive-conversion hooks (`valueOf`, `toString`, `toJSON`) on values it encounters. A JavaScript `Proxy` that recursively returns proxies for every property must therefore handle these well-known coercion methods explicitly, or React's primitive coercion sees proxy objects/functions instead of a primitive string and can recurse or crash.
- Review/discussion: CodeRabbit suggested adding root-path coercion assertions; those were added. The later commit explicitly addressed the subtle route-naming issue by preserving `proxy.toString.query()` chaining while still making `proxy.toString()` return `tRPC.proxy()`.

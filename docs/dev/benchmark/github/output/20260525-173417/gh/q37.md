## Answer

- `renderPage()` is defined in `withastro/astro` at `packages/astro/src/runtime/server/render/page.ts`.
- Signature: `export async function renderPage(result: SSRResult, componentFactory: AstroComponentFactory | NonAstroPageComponent, props: any, children: any, streaming: boolean, route?: RouteData): Promise<Response>`.
- It imports Astro streaming/string render APIs from `./astro/render.js`: `renderToAsyncIterable`, `renderToReadableStream`, and `renderToString`.
- For non-Astro page components (`!isAstroComponentFactory(componentFactory)`), it marks root props with `server:root`, renders via either the experimental render queue (`buildRenderQueue` + `renderQueue`) or `renderComponentToString`, encodes the full string, sets `Content-Type: text/html` and `Content-Length`, optionally sets CSP, and returns a `Response`.
- For Astro component pages, it sets metadata about whether `<head>` appears in the tree, then chooses the response body based on `streaming`.
- Streaming path: on Node but not Deno it calls `renderToAsyncIterable(result, componentFactory, props, children, true, route)` and passes that async iterable as the `Response` body; otherwise it calls `renderToReadableStream(...)`.
- Non-streaming path: it calls `renderToString(result, componentFactory, props, children, true, route)`.
- If rendering returns a `Response`, it returns that directly. Otherwise it builds final headers from `result.response`, injects CSP when configured, computes `Content-Length` for non-streaming string bodies, applies special status/statusText for `/404` and `/500`, and returns the final `Response`.

### Q31 — Svelte 5 vs Vue 3: compile-time vs runtime reactivity

Using `sveltejs/svelte` and `vuejs/core`:
1. Where does reactivity live: compiler, runtime, or both?
2. Find the Svelte compiler's output for a `$state` variable vs Vue's `ref()` runtime call.
3. How does each framework know which part of the DOM to update when state changes?
4. What is the fundamental tradeoff between compile-time and runtime reactivity?

## Answer

- **Where reactivity lives**: Svelte 5 — primarily **compile-time** (the compiler transforms `$state` to runtime signal calls); Vue 3 — primarily **runtime** (reactive system is fully at runtime via proxies/`ref()`)
- **Svelte compiler output for `$state`**: The compiler (`VariableDeclaration.js` in `packages/svelte/src/compiler/phases/3-transform/client/visitors/`) transforms `let count = $state(0)` into `let count = $.state(0)` (where `$.state` is the runtime `state()` source primitive from `sources.js`); if the value is an object, it wraps with `$.proxy(value)` first for deep reactivity
- **Vue `ref()` runtime call**: `ref(0)` creates a `RefImpl` instance (in `packages/reactivity/src/ref.ts`) with a `dep` (dependency tracker); reading `.value` calls `this.dep.track()` to register the current active effect; writing `.value` calls `this.dep.trigger()` to notify subscribers — all at runtime, no compilation needed
- **How each knows which DOM to update**: Svelte — the compiler generates **fine-grained template update functions** that directly call the DOM (e.g., `text_effect(() => set_text(node, count))`) subscribed to specific sources; Vue — the renderer's `patch()` function runs a virtual DOM diff when the component's render effect re-executes (triggered by reactive dep changes)
- **Fundamental tradeoff**: Svelte compile-time reactivity produces smaller, faster runtime code with no VDOM overhead but requires a compiler step and makes dynamic patterns harder; Vue runtime reactivity needs no build step for components, supports dynamic composition patterns, but carries a reactive system + VDOM runtime cost

### Q21 — Vue 3 reactivity vs React hooks: dependency tracking

3. How does React know which components to re-render?
4. What are the practical consequences of each approach for the developer?

## Answer

- **Vue 3 state primitive**: `ref()` / `reactive()` in `packages/reactivity/src/ref.ts` and `reactive.ts`; backed by `ReactiveEffect` class in `packages/reactivity/src/effect.ts`
- **React state primitive**: `useState`/`useReducer` hooks in `packages/react-reconciler/src/ReactFiberHooks.js` (`mountReducer` / `updateReducer`); state stored in fiber's `memoizedState` hook linked list
- **Vue dependency tracking**: When a reactive value is read inside a component's `setup()` or render function, the getter of the Proxy records the current `ReactiveEffect` (component's render effect) as a subscriber via `dep.track()`; on mutation, `dep.trigger()` queues the subscribed effects — this is automatic and precise (sub-component granularity)
- **React re-render detection**: React re-renders when `setState` / `dispatch` is called; `scheduleUpdateOnFiber()` marks the fiber with an update lane and the work loop re-executes the component function from scratch; `React.memo` / `shouldComponentUpdate` can skip subtrees, but the default is full re-render of the subtree
- **Practical consequences**: Vue's approach means only components that actually read a changed value re-render — no need for `memo`/`useMemo`/`useCallback`; React requires manual memoization to avoid cascading re-renders but offers more explicit control and simpler mental model for data flow (unidirectional)

## Answer

- The `Postpone` component is defined in `packages/next/src/server/app-render/dynamic-rendering.ts` and re-exported from `packages/next/src/server/app-render/rsc/postpone.ts`
- `Postpone` calls `postponeWithTracking()` which calls `React.unstable_postpone(reason)` — this throws a special React signal (not an Error) that tells React to abort rendering the current subtree and record it as "postponed"
- React catches the postpone signal at the nearest Suspense boundary during the prerender phase; the static shell (everything renderable without dynamic data) is streamed/committed, and the postponed subtree boundary is left as a "hole" with its resumption state serialized
- The static shell is assembled in `packages/next/src/server/app-render/app-render.tsx` using `continueStaticPrerender()` / `continueStaticFallbackPrerender()` from `stream-ops.web.ts`, which call React's `prerender()` (from `react-dom/static`) to generate the static HTML + postponed state
- The postponed state is serialized as `DynamicDataPostponedState` or `DynamicHTMLPostponedState` (in `postponed-state.ts`) and stored in the `resume-data-cache`; on a dynamic request, `resume()` (from `react-dom/server`) restores the component tree and fills in the postponed holes with live data

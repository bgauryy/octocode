### Q33 — How does Hono chain middleware? (`compose()`)

In `honojs/hono`, find `src/compose.ts`. How does `compose()` build and execute the middleware chain? What prevents `next()` from being called twice?

## Answer

- `compose()` is implemented in `honojs/hono` at `src/compose.ts`, modeled after `koa-compose`.
- It returns a function `(context, next) => Promise<Context>` that closes over the middleware array and starts execution with `dispatch(0)`.
- `dispatch(i)` selects `middleware[i][0][0]` as the current handler, sets `context.req.routeIndex = i`, and invokes it as `await handler(context, () => dispatch(i + 1))`; the `next` callback is therefore a recursive dispatch to the next middleware.
- If the middleware array is exhausted, it uses the outer `next` handler only when `i === middleware.length && next`.
- Double-`next()` protection is the `index` guard: `index` starts at `-1`; `dispatch(i)` throws `Error('next() called multiple times')` when `i <= index`, then records `index = i`.
- Errors from handlers are caught; if `onError` exists and the thrown value is an `Error`, Hono stores it on `context.error`, calls `onError(err, context)`, and marks `isError = true`; otherwise the error is rethrown.
- If no handler exists and `context.finalized === false`, `onNotFound(context)` may produce the response. When a handler returns `res`, Hono assigns `context.res = res` if the context is not finalized or if the result came from the error handler.

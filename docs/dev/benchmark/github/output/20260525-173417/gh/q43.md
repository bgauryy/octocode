## Answer

- Top-level directories in `withastro/astro` include `.agents`, `.changeset`, `.devcontainer`, `.flue`, `.github`, `.gitpod`, `.vscode`, `.zed`, `benchmark`, `configs`, `examples`, `packages`, `patches`, `reference`, and `scripts`.
- `.github` holds GitHub Actions/issue/PR automation; editor/devcontainer folders hold local development configuration.
- `.changeset` contains release/change management metadata.
- `benchmark` contains performance benchmark material.
- `configs` contains shared repo configuration.
- `examples` contains example Astro projects and usage samples.
- `packages` is the pnpm workspace area for the actual Astro packages.
- `patches` contains package patches; `reference` contains reference fixtures/material; `scripts` contains repo automation.
- Package directories under `packages/` are: `astro-prism`, `astro-rss`, `astro`, `create-astro`, `db`, `integrations`, `internal-helpers`, `language-tools`, `markdown`, `telemetry`, `underscore-redirects`, and `upgrade`.
- `packages/astro` is the core Astro framework/runtime/compiler package.
- `packages/create-astro` is the project scaffolding CLI.
- `packages/integrations` groups official framework/platform integrations.
- `packages/language-tools` supports editor/language tooling.
- `packages/markdown`, `astro-prism`, and `astro-rss` support content/markdown/syntax highlighting/RSS features.
- `packages/db` provides Astro DB functionality, `telemetry` handles telemetry, `internal-helpers` holds shared internal utilities, `underscore-redirects` handles redirects support, and `upgrade` contains migration tooling.

## Answer

- `trpc/trpc` currently has these directories under `packages/`: `client`, `next`, `openapi`, `react-query`, `server`, `tanstack-react-query`, `tests`, and `upgrade`.
- `packages/server` is the core server/runtime layer: routers, procedures, middleware, adapters, root config, and server-side callers.
- `packages/client` is the framework-agnostic client layer for links and calling tRPC APIs from JavaScript/TypeScript clients.
- `packages/react-query` and `packages/tanstack-react-query` are React/TanStack Query integration layers, showing that data-fetching/UI bindings sit above the core client/server protocol.
- `packages/next` is the Next.js-specific integration layer.
- `packages/openapi` is an interoperability adapter layer for exposing or working with OpenAPI-style APIs.
- `packages/tests` centralizes cross-package test fixtures/coverage, and `packages/upgrade` contains migration/upgrade tooling.
- The naming reveals tRPC's layered architecture: a core `server` package, a generic `client` package, then framework/integration packages (`next`, React Query/TanStack Query, `openapi`) that compose on top rather than being part of the core protocol.

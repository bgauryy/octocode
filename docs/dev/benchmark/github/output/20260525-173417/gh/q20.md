## Answer

- **Vue 3 reconciler entry point**: `packages/runtime-core/src/renderer.ts` — function `baseCreateRenderer()` creates the renderer with a `patch()` function as its core
- **React reconciler entry point**: `packages/react-reconciler/src/ReactFiberWorkLoop.js` — `performWorkOnRoot()` drives the fiber work loop using `performUnitOfWork()`
- **How each decides what changed**: Vue's `patch(n1, n2, ...)` compares old vnode `n1` with new vnode `n2`; checks `isSameVNodeType()` and dispatches by `type` (Text/Comment/Fragment/Element/Component) using compiler-emitted `patchFlag` hints; React's fiber work loop traverses the fiber tree calling `beginWork()` on each fiber, using lane-based priority and `alternate` fiber diffing to detect changes
- **How each schedules and commits**: Vue uses a microtask-based queue (`scheduler.ts`) with `queueJob()` + `nextTick()`/`queueFlush()` to batch component updates; React uses cooperative scheduling via the Scheduler package with lanes (`SyncLane`, `ConcurrentMode`), `scheduleUpdateOnFiber()`, and a two-phase commit (mutation + layout effects)
- **Fundamental architectural difference**: Vue 3 uses fine-grained component-level reactivity (reactive proxy system) to know exactly which components need re-rendering before diffing; React re-renders from the updated component downward using the fiber work loop, relying on concurrent mode + `shouldComponentUpdate`/`memo`/`useMemo` to skip subtrees — Vue tracks *who* needs updating at state-change time, React tracks *what work* to do at render time

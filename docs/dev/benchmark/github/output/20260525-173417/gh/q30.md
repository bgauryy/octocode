## Answer

- `createSignal` is defined in `packages/solid/src/reactive/signal.ts`
- It creates a `SignalState<T>` object: `{ value, observers: null, observerSlots: null, comparator }` and returns a `[readSignal, setter]` tuple
- **Fine-grained mechanism**: Solid uses a global `Listener` variable (a `Computation` reference) — when a signal's getter (`readSignal`) is called inside an effect or computed, it registers the current `Listener` into the signal's `observers` array; when the setter calls `writeSignal(s, value)`, it iterates `s.observers` and marks each dependent computation `STALE`, then runs them
- Unlike React's `useState` which re-renders the entire component, Solid signals track **individual DOM nodes** as observers: each template expression `<div>{count()}</div>` creates its own fine-grained `createEffect` that updates only that specific DOM node; there is no virtual DOM diffing — only the exact signals that changed trigger the exact DOM mutations that depend on them
- React's `useState` triggers component re-execution (the function runs top to bottom) producing a new vnode tree that React then diffs; Solid `createSignal` bypasses component re-rendering entirely and updates DOM nodes directly through the signal subscription graph

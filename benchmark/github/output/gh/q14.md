## Answer

- `createSignal` is defined in `solidjs/solid` at `packages/solid/src/reactive/signal.ts`.
- It creates a signal object with a current `value`, comparator, and observer lists, and returns `[readSignal.bind(s), setter]`.
- Fine-grained updates come from dependency tracking: when a signal getter runs inside the current computation/listener, `readSignal` registers that computation in the signal's observers; when the setter calls `writeSignal`, Solid marks exactly those observer computations stale and schedules/runs them.
- Unlike React `useState`, this does not schedule a whole component function to re-render by default; DOM expressions/effects compiled as computations subscribe directly to the specific signals they read.

4. What is the fundamental architectural difference in their reconciliation strategies?

## Answer

- Vue entry point: `vuejs/core` `packages/runtime-core/src/renderer.ts`, especially `baseCreateRenderer(...)` and its inner `patch(n1, n2, container, ...)` function.
- React entry point: `facebook/react` `packages/react-reconciler/src/ReactFiberWorkLoop.js` (work loop/scheduling) together with `ReactFiberBeginWork.js`/`ReactFiberCompleteWork.js` for render work and `ReactFiberCommitWork.js` for commit effects.
- Vue decides changes by comparing old/new VNodes in `patch()`: if node types differ it unmounts/remounts; otherwise it dispatches by vnode shape/patch flags to optimized element/component/children prop patching.
- React decides changes by walking the Fiber tree: updates enqueue lanes on fibers; `beginWork` reconciles new elements against current child fibers to produce work/effect flags; `completeWork` prepares host mutations.
- Vue scheduling/commit: reactive effects schedule component update jobs in the runtime scheduler; the patch operation directly applies DOM host operations as it walks VNodes.
- React scheduling/commit: lane priority scheduling performs interruptible render work (`workLoopConcurrent`/`performUnitOfWork`), then `commitRoot` applies mutation/layout/passive effects in commit phases.
- Fundamental difference: Vue is template/VNode patch driven with compiler patch flags and fine-grained reactive invalidation of components; React is Fiber driven, building a prioritized work-in-progress tree and committing accumulated effects.

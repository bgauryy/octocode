### Q18 — How does Vitest execute a single test? (`runTest`)

In `vitest-dev/vitest`, read `packages/runner/src/run.ts`. What are the key steps in `runTest(test, runner)`, and how does Vitest handle `retry` and `repeats`?

## Answer

- `runTest(test, runner)` in `packages/runner/src/run.ts` marks the test running, records start time, resolves the test function/context, runs before hooks, executes the test with timeout handling, then runs after hooks, records duration/result, updates task state, and fires runner/task hooks.
- It skips execution for skipped/todo tests and handles fixture/test context setup before invoking the test body.
- Failures are caught and stored on the task; on success it clears/sets the result state accordingly, with hook cleanup still attempted.
- `retry` is handled by rerunning a failed test up to the configured retry count, keeping retry metadata/errors so a later successful attempt can pass the test.
- `repeats` are handled as repeated invocations of the same test case (each repeat/retry has its own execution cycle/attempt bookkeeping), so Vitest can run a single test multiple times even without failure.

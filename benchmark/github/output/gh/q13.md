## Answer

- `Postpone` is in `packages/next/src/server/app-render/dynamic-rendering.ts` as `export function Postpone({ reason, route }: PostponeProps): never`.
- It calls `postponeWithTracking(route, reason, dynamicTracking)`, which records dynamic access for PPR and then calls `React.unstable_postpone(createPostponeReason(route, expression))`; Next guards this with `assertPostpone()` because it requires an experimental React build with `unstable_postpone`.
- Usage includes `packages/next/src/server/app-render/create-component-tree.tsx`, where force-dynamic/dynamic holes are rendered as `createElement(Postpone, { reason, route })` under a Suspense boundary.
- Static shell assembly happens in `packages/next/src/server/app-render/app-render.tsx`: the prerender pass lets React postpone dynamic regions, captures postponed state/prelude data, and streams the prerender/static shell; helper state is encoded/decoded in `packages/next/src/server/app-render/postponed-state.ts`.
- At request/runtime time, Next uses the postponed state/resume data and final runtime prerender/resume helpers (`resumeAndAbort`, `resumeToFizzStream`, runtime prerender code in `app-render.tsx`) to fill or stream the postponed dynamic holes after the shell.

## Answer

- `facebook/react` `packages/`: many narrowly scoped React runtime/build packages such as `react`, `react-dom`, `react-reconciler`, `react-server`, `scheduler`, `shared`, `eslint-plugin-react-hooks`, plus many `react-*` feature/runtime packages. The convention reveals a layered platform: public packages, renderer/reconciler internals, scheduler/shared infra, and fixtures/tests.
- `vercel/next.js` `packages/`: centered on `next` plus framework tooling/build integrations such as `create-next-app`, `eslint-config-next`, `next-codemod`, `next-env`, `next-plugin-storybook`, `third-parties`, `font`, etc. The convention reveals a product/framework monorepo around one primary framework package with companion CLI, lint, codemod, and integration packages.
- `remix-run/react-router` `packages/`: `react-router`, `react-router-dev`, `react-router-node`, `react-router-serve`, and adapter packages like `react-router-architect`, `react-router-cloudflare`, `react-router-express`, plus `create-react-router`. The convention reveals a core router plus framework/dev server and deployment/runtime adapters.

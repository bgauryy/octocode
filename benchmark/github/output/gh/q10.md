## Answer

- Vue primitive: `ref()`/`reactive()` in `packages/reactivity/src/`; `packages/reactivity/src/ref.ts` defines `RefImpl` whose getter calls `dep.track()` and setter calls `dep.trigger()`.
- Vue dependency tracking: `packages/reactivity/src/dep.ts` maintains `Dep` links between the currently active subscriber/effect and each reactive property/ref. When a component render effect reads a ref/reactive property, it subscribes; when the value changes, Vue triggers only the subscribed effects/components.
- React primitive: hooks in `packages/react-reconciler/src/ReactFiberHooks.js`, including `mountState`, `updateState`, and `dispatchSetState` behind public `useState`.
- React re-render knowledge: React does not track which values were read during render; calling a state setter enqueues an update on that hook's Fiber, assigns lanes, and schedules that component/fiber subtree for reconciliation.
- Practical consequence: Vue can often update only components/effects that actually read a reactive value and lets dependencies be discovered dynamically at runtime. React requires explicit state ownership and dependency arrays/memoization; updates are component-level, so render purity and stable hook order matter.

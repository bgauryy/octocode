## Answer

- Problem: PR `facebook/react#27733` tries to make `react-devtools-inline` support DevTools “Reload and profile”; the author needed access to the backend `attach` flow for an inline DevTools setup in a browser extension where the official extension cannot debug another extension.
- Changed files: `packages/react-devtools-inline/src/backend.js` adds inline backend attach/reload-and-profile support; `packages/react-devtools-inline/src/frontend.js` exposes frontend support such as `supportsReloadAndProfile`; `packages/react-devtools-shared/src/devtools/index.js` removes shared devtools-side code that the PR moved/rewired; `packages/react-devtools-shared/src/devtools/store.js` adjusts store support for reload/profile; `packages/react-devtools-shell/src/app/devtools.js` changes shell usage/testing of the inline DevTools behavior.
- Review disagreement: reviewer `hoxyq` said simply exporting `attach` is the wrong abstraction; inline DevTools should behave like the extension surface: set `supportsReloadAndProfile`, inject `__REACT_DEVTOOLS_ATTACH__` before the app loads, and have the backend handle `reloadAndProfile`/sessionStorage/reload. Later the disagreement widened to whether this belongs in `react-devtools-inline` at all versus using `react-devtools-core` or publishing/using shared internals.
- Not merged: it received changes requested, the implementation/use case remained unresolved, reviewer bandwidth was low, `react-devtools-inline` might be deprecated/moved, and the PR has repeatedly gone stale; as of the viewed PR it is open but unmerged.

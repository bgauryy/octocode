### Q19 — Astro vs Next.js: SSR rendering and component model

Using `withastro/astro` and `vercel/next.js`:
1. Find the SSR render entry function in each repo.
2. How does each stream HTML to the client?
3. How does Astro's islands model differ architecturally from Next.js's React Server Components?

## Answer

- Astro SSR entry: `withastro/astro` has `renderPage(...)` in `packages/astro/src/runtime/server/render/page.ts`. For Astro component pages it chooses streaming vs non-streaming and returns a `Response`.
- Astro string/stream APIs: `renderPage` imports `renderToAsyncIterable`, `renderToReadableStream`, and `renderToString` from `packages/astro/src/runtime/server/render/astro/render.ts`. In streaming mode it uses `renderToAsyncIterable(...)` on Node or `renderToReadableStream(...)` elsewhere; non-streaming uses `renderToString(...)`.
- Astro streaming mechanics: `renderToReadableStream(...)` calls the component as a template result, buffers head content for pages, creates a `ReadableStream`, and its render destination writes encoded chunks/doctype into the stream before closing or erroring.
- Next.js SSR entry: `vercel/next.js` App Router uses `renderToHTMLOrFlight(...)` in `packages/next/src/server/app-render/app-render.tsx`.
- Next.js stream APIs: RSC/Flight payloads go through `renderToWebFlightStream(...)` in `packages/next/src/server/app-render/stream-ops.web.ts`, which calls `ComponentMod.renderToReadableStream(payload, clientModules, opts)`. HTML/Fizz rendering uses `renderToWebFizzStream(...)`, which calls `renderToInitialFizzStream({ ReactDOMServer: { renderToReadableStream }, element, streamOptions })` and returns the stream plus `allReady`.
- Astro islands model: Astro server-renders pages/components to mostly static HTML and selectively hydrates explicit client islands. `packages/astro/src/runtime/server/hydration.ts` extracts `client:*` directives, component URL/export, props, and generates an island element with attributes such as `component-url`, `renderer-url`, serialized `props`, `ssr`, `client`, and hydration options.
- Next.js RSC model: Next renders a React Server Components tree and streams both HTML and a Flight data stream that describes server/client component boundaries and data. Client components are integrated into a React tree and hydrated/reconciled by React using the Flight payload.
- Architectural difference: Astro treats interactivity as isolated opt-in islands embedded in static/server-rendered HTML, potentially using multiple renderers and independent hydration directives. Next App Router is React-centric: server and client components form one React module graph, with RSC/Flight coordinating server output and client hydration/navigation at framework level.

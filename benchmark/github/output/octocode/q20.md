## Answer

- Problem solved: PR `trpc/trpc#7336` fixes React 19 coercing tRPC recursive proxy objects to primitives by calling `valueOf()`, `toString()`, or `toJSON()` during rendering, interpolation, or logging. Before the fix, those property reads produced another proxy, which could break primitive consumers or recurse indefinitely.
- Changed `packages/server/src/unstable-core-do-not-import/createProxy.ts`: inside `createInnerProxy`’s `apply` trap, it checks whether the last path segment is `valueOf`, `toString`, or `toJSON`; for direct calls like `proxy.toString()` it returns a primitive debug string `tRPC.proxy(<path>)` instead of forwarding to the callback.
- Changed `packages/server/src/unstable-core-do-not-import/createProxy.test.ts`: adds `createRecursiveProxy() - handles React 19 proxy coercion keys`, asserting root coercion returns `tRPC.proxy()`, nested coercion returns strings like `tRPC.proxy(foo.bar)`, and normal route chaining such as `proxy.toString.query()` and `proxy.foo.bar.query()` still returns `{ path, args }`.
- Core technical fix: detect coercion method names only when the proxy is invoked (`apply`), use `path.slice(0, -1).join('.')` for the debug path, and return a string; because the `get` trap still builds paths, names like `toString` remain usable for chained tRPC procedures.
- Why React 19 specifically: React 19 may attempt primitive coercion of objects/proxies in render/logging/debug paths by invoking `valueOf`, `toString`, or `toJSON`; tRPC’s recursive proxy API treats any property as another route segment, so those coercion probes accidentally became proxy route calls unless handled specially.
- Status: merged on `2026-04-14`; CodeRabbit’s walkthrough confirms the intended fix and tests, with no actionable review comments.

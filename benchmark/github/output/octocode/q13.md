## Answer

- The `Postpone` component is in `vercel/next.js` at `packages/next/src/server/app-render/dynamic-rendering.ts`.
- `Postpone({ reason, route })` reads the current work-unit store, uses its `dynamicTracking` only for `prerender-ppr`, and delegates to `postponeWithTracking(route, reason, dynamicTracking)`.
- `postponeWithTracking` asserts React postpone support, records the dynamic access/reason (and optional debug stack) into `dynamicTracking.dynamicAccesses`, then calls `React.unstable_postpone(createPostponeReason(route, expression))`. React throws a special postpone object; Next treats this as the marker for “there is a dynamic hole here, stop prerendering this part now and resume later.”
- The prerender pipeline calls React/Flight prerender APIs via `getServerPrerender(ComponentMod)` in `packages/next/src/server/app-render/stream-ops.web.ts`, which returns `ComponentMod.prerender`, and `app-render.tsx` runs it with the initial server payload, client modules, and prerender options.
- The static shell is assembled from the prerender “prelude”: `app-render.tsx` calls `processPreludeOp(unprocessedPrelude)` to split/peek the prelude stream and determine whether the shell is empty or full, then validates dynamic access with `throwIfDisallowedDynamic(...)`.
- When the render is dynamic/PPR and React returned a `postponed` state, `app-render.tsx` serializes it into `metadata.postponed` with `getDynamicHTMLPostponedState(postponed, DynamicHTMLPreludeState.Empty|Full, fallbackRouteParams, prerenderResumeDataCache, cacheComponents)` from `packages/next/src/server/app-render/postponed-state.ts`.
- `getDynamicHTMLPostponedState` stores `[preludeState, postponed]` plus resume-data cache (and fallback-param replacement metadata when needed). The returned response stream is the static prelude/shell passed through `continueDynamicPrerender(prelude, opts)`, while the postponed state is kept so later dynamic resume requests can continue rendering the holes.

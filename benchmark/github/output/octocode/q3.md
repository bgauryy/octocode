Search `vercel/next.js` for `startTransition` usage in client code. What does it wrap?

## Answer

- Yes. `vercel/next.js` uses React `startTransition` in client-side App Router code.
- In `packages/next/src/client/components/app-router-instance.ts`, `replace(...)` and `push(...)` wrap `dispatchNavigateAction(...)` in `startTransition`; `refresh()` wraps `dispatchAppRouterAction({ type: ACTION_REFRESH })`; the action queue also wraps `setState(deferredPromise)` for non-restore actions.
- In `packages/next/src/client/app-dir/link.tsx`, link clicks wrap `dispatchNavigateAction(href, replace ? 'replace' : 'push', scrollBehavior, linkInstanceRef.current, transitionTypes)` in `React.startTransition`.
- In `packages/next/src/client/components/app-router.tsx`, patched browser `history.pushState`/`replaceState` restoration wraps `dispatchAppRouterAction({ type: ACTION_RESTORE, url, historyState })` in `startTransition`.
- In `packages/next/src/client/app-call-server.ts`, server action dispatch wraps `dispatchAppRouterAction({ type: ACTION_SERVER_ACTION, actionId, actionArgs, resolve, reject })` in `startTransition`.
- Other client uses include hydration/render (`packages/next/src/client/app-index.tsx`, `index.tsx`), error retry/refresh boundaries, hot reload refresh, and link/offline optimistic status updates.

### Q14 — Solid.js `createSignal` vs React `useState`

Find `createSignal` in `solidjs/solid`. What mechanism makes updates fine-grained rather than component-level?

## Answer

- `createSignal` is implemented in `solidjs/solid` at `packages/solid/src/reactive/signal.ts`.
- `createSignal(value, options)` creates a `SignalState` object with `value`, `observers`, `observerSlots`, and an optional `comparator`, then returns `[readSignal.bind(s), setter]`; the setter normalizes functional updates and calls `writeSignal(s, value)`.
- Fine-grained dependency tracking happens in `readSignal`: when a computation/effect is currently running (`Listener` is set), the signal adds that computation to its `observers`, and the computation records the signal in its `sources`/`sourceSlots`.
- Updates are fine-grained in `writeSignal`: if the comparator says the value changed, Solid writes `node.value` (or transition value), then iterates only `node.observers`, marking those computations stale and pushing pure computations to `Updates` and effects to `Effects`; downstream memo observers are marked via `markDownstream`.
- This differs from React `useState`: Solid does not schedule a whole component function to re-render by default. JSX compiles to reactive computations around the exact expressions that read signals, so changing a signal invalidates only the subscribed computations/DOM bindings, not the entire component subtree.

### Q17 — How does Hono chain middleware? (`compose()`)

In `honojs/hono`, find `src/compose.ts`. How does `compose()` build and execute the middleware chain? What prevents `next()` from being called twice?

## Answer

- `compose()` is implemented in `honojs/hono` at `src/compose.ts`.
- It accepts the middleware array plus optional `onError` and `onNotFound`, and returns a request runner `(context, next) => Promise<Context>`.
- For each request it initializes `let index = -1` and starts the chain with `dispatch(0)`.
- `dispatch(i)` is the recursive executor. It first checks `if (i <= index) throw new Error('next() called multiple times')`, then sets `index = i`; this monotonic index is what prevents the same middleware’s `next()` from being awaited/called twice or dispatch from moving backwards.
- If `middleware[i]` exists, the handler is `middleware[i][0][0]` and Hono records `context.req.routeIndex = i`. If there is no middleware at `i`, it uses the outer `next` only when `i === middleware.length`.
- A handler is invoked as `await handler(context, () => dispatch(i + 1))`; this closure is the middleware’s `next`, so calling it advances to the next middleware.
- Errors thrown by handlers are caught; if the thrown value is an `Error` and `onError` exists, Hono stores it on `context.error`, runs `onError(err, context)`, and marks `isError = true`; otherwise it rethrows.
- If no handler exists and the context is not finalized, `onNotFound(context)` supplies the response.
- After a handler/error/not-found result returns, `compose` assigns `context.res = res` when a response was returned and either the context was not finalized or this was an error response, then returns the context.

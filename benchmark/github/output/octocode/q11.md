### Q11 — Svelte 5 `$state` runtime

In `sveltejs/svelte`, find where `$state` values are represented as reactive signals at runtime. What is the core primitive and how is state mutation tracked?

## Answer

- `$state` runtime values in Svelte 5 are represented by signal-like `Source`/`Value` objects in `packages/svelte/src/internal/client/reactivity/sources.js`.
- The core primitive is `source(v)`, which returns a signal object roughly `{ f, v, reactions, equals, rv, wv }`; `state(v)` wraps `source(v)` and records it with `push_reaction_value(s)`.
- Mutable state is created by `mutable_source(initial_value, ...)`, which calls `source(initial_value)` and uses `safe_equals` for mutable comparison semantics.
- The compiler turns `$state(...)` declarations into runtime calls: `packages/svelte/src/compiler/phases/3-transform/client/visitors/VariableDeclaration.js` emits `$.state(value)`, and for proxyable `$state` values first emits `$.proxy(value)`.
- Object/array `$state` is handled by `packages/svelte/src/internal/client/proxy.js`: `proxy(value)` creates a JavaScript `Proxy` and a `Map<any, Source<any>>` of per-property sources plus a version source. Property `get` lazily creates/reads a property source via `get(s)`; `set`, `defineProperty`, and `deleteProperty` update the relevant source with `set(...)` and increment version/length sources when shape changes.
- Mutation tracking flows through `set(source, value, should_proxy)` and `internal_set(...)` in `sources.js`: Svelte checks unsafe mutation rules, optionally proxies the new value, compares with `source.equals`, records old value/batch capture, updates `source.v`/write version, then calls `mark_reactions(source, DIRTY, ...)`.
- `mark_reactions` walks `signal.reactions`, marks derived/effect reactions dirty or maybe-dirty, recursively invalidates deriveds, and schedules normal effects via the batch/effect scheduler while eager effects run immediately.

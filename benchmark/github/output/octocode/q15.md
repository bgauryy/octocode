### Q15 — Svelte 5 vs Vue 3: compile-time vs runtime reactivity

Using `sveltejs/svelte` and `vuejs/core`:
1. Where does reactivity live: compiler, runtime, or both?
2. Find the Svelte compiler's output for a `$state` variable vs Vue's `ref()` runtime call.
3. How does each framework know which part of the DOM to update when state changes?
4. What is the fundamental tradeoff between compile-time and runtime reactivity?

## Answer

- Svelte 5 reactivity lives in both compiler and runtime. The compiler recognizes `$state` runes in `packages/svelte/src/compiler/phases/3-transform/client/visitors/VariableDeclaration.js` and emits runtime calls like `$.proxy(value)` for proxyable state and `$.state(value)` for state sources.
- Svelte runtime state lives in `packages/svelte/src/internal/client/reactivity/sources.js`: `state(v)` creates a signal-like source with `source(v)`, whose object stores `v`, `reactions`, equality, and version fields; `set`/`internal_set` update the source and call `mark_reactions` to dirty/schedule dependent deriveds/effects.
- Svelte object/array `$state` uses `packages/svelte/src/internal/client/proxy.js`: each property lazily gets its own `Source` in a `sources` map; reads call `get(s)` and writes/deletes call `set(s, ...)` plus version/length increments. This lets compiled DOM/effect code subscribe to property-level sources.
- Vue 3 reactivity is primarily runtime. `ref()` is implemented by `RefImpl` in `packages/reactivity/src/ref.ts`, whose `.value` getter calls `dep.track()` and setter updates `_value` then calls `dep.trigger(...)`; `reactive()` in `packages/reactivity/src/reactive.ts` creates proxies with mutable handlers.
- Vue also uses compiler output for render optimization, but not for declaring reactive state: runtime `track()` in `packages/reactivity/src/dep.ts` records active effects in `targetMap: WeakMap<object, Map<key, Dep>>` by target/key. The renderer in `packages/runtime-core/src/renderer.ts` then uses compiler-generated `patchFlag`, `dynamicChildren`, and `dynamicProps` to patch only dynamic DOM props/text/classes/styles.
- Example output shape: a Svelte `$state` variable becomes a runtime source/proxy expression such as `$.state($.proxy(initialObject))` (or `$.state(value)` for non-proxy/raw state). A Vue variable remains an explicit runtime call such as `const count = ref(0)` or `const state = reactive({...})`.
- How DOM updates are known: Svelte's compiler emits direct update/effect code for the exact template expressions; at runtime, sources know their dependent reactions and schedule those DOM updates. Vue render effects rerun when runtime deps trigger, produce new VNodes, and Vue's patcher uses VNode shape plus patch flags to update DOM.
- Tradeoff: Svelte's compile-time approach yields very small, direct DOM updates and less runtime diffing, but depends on compiler analysis/runes semantics and can be less transparent outside compiled code. Vue's runtime reactivity is more flexible and works naturally in plain JS/composables, but pays runtime tracking/proxy/render-effect costs and still patches a VNode tree, mitigated by compiler patch flags.

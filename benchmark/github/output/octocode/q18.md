In `vitest-dev/vitest`, read `packages/runner/src/run.ts`. What are the key steps in `runTest(test, runner)`, and how does Vitest handle `retry` and `repeats`?

## Answer

- `runTest(test, runner)` is in `vitest-dev/vitest` at `packages/runner/src/run.ts`.
- It first calls `runner.onBeforeRunTask?.(test)`. If the test mode is not `run`/`queued`, it emits `test-prepare` and `test-finished` and returns; if the result already failed early, it emits `test-failed-early` and returns.
- It initializes timing/result state: `state: 'run'`, `startTime`, `retryCount: 0`, emits `test-prepare`, registers the test as running, sets it as current, gets the containing suite/file, and reads `repeats = test.repeats ?? 0`.
- Execution is nested loops: `repeatCount` from `0` through `repeats`, and inside it `retryCount` from `0` through `getRetryCount(test.retry)`.
- Each try runs inside `callAroundEachHooks(...)`. It calls `runner.onBeforeTryTask(test, { retry, repeats })`, sets `test.result.repeatCount`, runs suite `beforeEach` hooks and captures their cleanup callbacks, then executes either custom `runner.runTask(test)` or the registered test function from `getFn(test)`, both under `limitMaxConcurrency` and tracing labels.
- On successful callback, it calls `runner.onAfterTryTask`, and if no failure was recorded sets state to `pass`; thrown errors are converted into task failures with `failTask(...)`.
- After the test body, Vitest calls `runner.onTaskFinished`, `afterEach` hooks, `beforeEach` cleanups, fixture cleanup from the checkpoint, `onFinished` hooks, `onFailed` hooks when failed, clears `onFailed`/`onFinished`, calls `runner.onAfterRetryTask`, and does full fixture cleanup.
- Pending/skip results immediately set mode/result to `skip`, emit `test-finished`, clear current/running state, and return.
- Retry handling: if the try passed, the inner retry loop breaks. If it failed and `retryCount < retry`, `passesRetryCondition(test, test.result.errors)` decides whether to retry; if false it breaks. If true, state is reset to `run`, `retryCount` is incremented, optional `getRetryDelay(test.retry)` is awaited, and Vitest emits `test-retried` before the next attempt.
- Repeats handling: the outer loop repeats the whole retry sequence for each `repeatCount` from `0` to `test.repeats`; each try receives both `retry` and `repeats` metadata and updates `test.result.repeatCount`.
- After loops, `test.fails` inverts expected-failure semantics: a pass becomes a failure (`Expect test to fail`), while an ordinary failure becomes a pass unless it was a syntax error. Finally Vitest clears current/running state, sets duration, calls `runner.onAfterRunTask`, and emits `test-finished`.

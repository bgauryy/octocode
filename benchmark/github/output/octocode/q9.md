### Q9 — Vue 3 vs React reconciliation

Using `vuejs/core` and `facebook/react`:
1. Find the core reconciler/renderer entry point in each repo.
2. How does each decide what changed? (Vue's `patch()` vs React's fiber work loop)
3. How does each schedule and commit updates?
4. What is the fundamental architectural difference in their reconciliation strategies?

## Answer

- Vue entry point: `vuejs/core` uses `baseCreateRenderer(...)` and its central `patch(n1, n2, container, ...)` function in `packages/runtime-core/src/renderer.ts`.
- React entry point: `facebook/react` uses the Fiber reconciler work loop in `packages/react-reconciler/src/ReactFiberWorkLoop.js`; `performUnitOfWork(fiber)` calls `beginWork(...)`, then either descends to the next fiber or `completeUnitOfWork(...)`. DOM/host mutations are applied during commit in `packages/react-reconciler/src/ReactFiberCommitWork.js`, e.g. `commitMutationEffects(...)`.
- Vue decides what changed by comparing old/new VNodes in `patch`: if `!isSameVNodeType(n1, n2)` it unmounts/remounts; otherwise it switches by VNode `type`/`shapeFlag` to process text, comments, fragments, elements, components, teleport, and suspense. For elements, `patchElement` uses compiler-generated `patchFlag`, `dynamicChildren`, and `dynamicProps` to update only known dynamic classes/styles/props/text, or falls back to full prop/children patching.
- React decides what changed by walking the fiber tree and recomputing work for scheduled lanes. `beginWork` compares current vs work-in-progress fibers, props/state/context and returns child work; `completeUnitOfWork` builds effect flags/lists. React's diff is fiber-based and priority/lane-aware rather than primarily compiler-patch-flag-based.
- Vue scheduling: each component render is a `ReactiveEffect(componentUpdateFn)`; `instance.update = effect.run`, `instance.job = effect.runIfDirty`, and `effect.scheduler = () => queueJob(job)`. Commit is mostly synchronous inside the queued component update as `patch` calls host operations (`hostPatchProp`, `hostSetText`, `hostInsert`, etc.) and queues post-render hooks/effects.
- React scheduling: updates enter through `scheduleUpdateOnFiber(root, fiber, lane)`, which marks the root updated, tracks render/interleaved lanes, calls `ensureRootIsScheduled(root)`, and may flush sync legacy work. Rendering can yield via `workLoopConcurrent`/scheduler; commit later applies mutation effects with `commitMutationEffects(...)`.
- Fundamental difference: Vue 3 combines runtime reactivity with compiler-informed VNode patching, so reactive dependency invalidation schedules specific component effects and patch flags narrow DOM work. React uses a general Fiber tree with scheduled lanes and a render/commit split; updates re-render affected fibers/components and reconcile children through the Fiber work loop, enabling interruptible/concurrent scheduling at the cost of broader component-level work.

Identify the server render function and the streaming/string API it calls in `vercel/next.js`, `remix-run/react-router`, and `nuxt/nuxt`.

## Answer

- `vercel/next.js` Pages Router: `packages/next/src/server/render.tsx` defines `async function renderToString(element)` and calls `ReactDOMServerPages.renderToReadableStream(element)`, waits for `renderStream.allReady`, then converts the stream with `streamToString(renderStream)`.
- `vercel/next.js` App Router: streaming is in `packages/next/src/server/app-render/stream-ops.web.ts`; it imports `renderToReadableStream` from `react-dom/server` and passes it into Next's `renderToInitialFizzStream({ ReactDOMServer: { renderToReadableStream }, ... })`.
- `remix-run/react-router`: the SSR/data-router entry pattern is `createStaticHandler(routes)` + `query(request)` + `createStaticRouter(dataRoutes, context)` + `<StaticRouterProvider router={router} context={context} />` from `packages/react-router/lib/dom/server.tsx`; the example `examples/ssr-data-router/src/entry.server.tsx` exports `render(...)` and calls `ReactDOMServer.renderToString(<StaticRouterProvider ... />)`.
- `nuxt/nuxt`: `packages/nitro-server/src/runtime/utils/renderer/build-files.ts` exports `getSSRRenderer()`/`getRenderer(ssrContext)`; it creates a `vue-bundle-renderer` `createRenderer(createSSRApp, { renderToString, ... })`, where the local `renderToString(input, context)` calls Vue's `_renderToString` imported from `vue/server-renderer`, then wraps the HTML in the Nuxt app root tags.

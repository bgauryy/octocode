### Q16 — Where is `parse()` implemented in Zod v4?

Find where `parse` is defined in `colinhacks/zod` (v4 core). What internal method does it call to validate, and what happens when the validation result is a Promise?

## Answer

- In Zod v4 core, the core parse implementation is `packages/zod/src/v4/core/parse.ts`.
- `export const _parse = (_Err) => (schema, value, _ctx, _params) => { ... }`; the public core `parse` is `export const parse = _parse(errors.$ZodRealError)`.
- Classic v4 re-exports/wraps it in `packages/zod/src/v4/classic/parse.ts`: `export const parse = core._parse(ZodRealError)`.
- Schema instance methods are wired in `packages/zod/src/v4/classic/schemas.ts`: `inst.parse = (data, params) => parse.parse(inst, data, params, { callee: inst.parse })` and `inst.parseAsync = async (...) => parse.parseAsync(inst, ...)`.
- `_parse` validates by building a synchronous parse context (`async: false`) and calling the schema internal runner: `schema._zod.run({ value, issues: [] }, ctx)`.
- If `schema._zod.run(...)` returns a `Promise` during synchronous parse, `_parse` throws `new core.$ZodAsyncError()`.
- `$ZodAsyncError` is defined in `packages/zod/src/v4/core/core.ts` with the message `Encountered Promise during synchronous parse. Use .parseAsync() instead.`
- If the result is synchronous but has issues, `_parse` finalizes issues into a Zod error, captures stack with the provided callee, and throws; otherwise it returns `result.value`.
- Async parse (`_parseAsync`) sets `async: true`, calls the same `schema._zod.run(...)`, awaits it when it is a `Promise`, then throws finalized errors or returns the parsed value.

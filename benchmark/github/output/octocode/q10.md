### Q10 — Vue 3 reactivity vs React hooks: dependency tracking

3. How does React know which components to re-render?
4. What are the practical consequences of each approach for the developer?

## Answer

- Vue state/reactivity primitives live in `vuejs/core` under `packages/reactivity/src/`: `reactive()` in `reactive.ts` creates proxy-based reactive objects; `ref()`/`RefImpl` in `ref.ts` represents `.value` state with a `Dep`.
- Vue dependency tracking: proxy `get` handlers in `baseHandlers.ts` call `track(target, TrackOpTypes.GET, key)`; `RefImpl.value` getter calls `this.dep.track()`. `track()` in `dep.ts` stores dependencies in `targetMap: WeakMap<object, Map<key, Dep>>`, connecting the currently active subscriber/effect (`activeSub`) to the specific target/key `Dep`.
- Vue invalidation: proxy `set` handlers call `trigger(target, TriggerOpTypes.ADD|SET, key, ...)`; `RefImpl.value` setter checks `hasChanged`, updates `_rawValue`/`_value`, then calls `this.dep.trigger()`. Component renders are `ReactiveEffect`s, so triggering the dep schedules only effects that actually read that reactive key/ref.
- React state primitive: `useState` is implemented in `packages/react-reconciler/src/ReactFiberHooks.js`; `mountStateImpl` creates a hook with `memoizedState`, `baseState`, and an update queue using `basicStateReducer`; `mountState` binds `dispatchSetState` to the current fiber/queue.
- React update tracking: `dispatchSetState` requests an update lane, creates/enqueues a hook update via `enqueueConcurrentHookUpdate`, then calls `scheduleUpdateOnFiber(root, fiber, lane)`; React later re-renders the scheduled fiber/component in the Fiber work loop. It may eagerly compute state and bail out if `Object.is(eagerState, currentState)`.
- How React knows what to re-render: it does not track arbitrary reads of local variables/properties during render like Vue. A state setter is already bound to a specific fiber and hook queue, so scheduling that update marks that component/root/lanes for work; props/context/parent updates can also cause fibers to render.
- Practical consequences: Vue gives fine-grained dependency tracking for reactive properties, so components/effects rerun based on actual reads and developers often mutate refs/reactive objects directly. React is explicit and component-level: developers call setters/reducers, preserve immutability for change detection/bailouts, and expect the component function to rerun with hooks in stable order; this is simpler and scheduler-friendly but can require memoization/selectors to avoid extra child/component work.

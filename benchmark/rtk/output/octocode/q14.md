## SECURITY.md Threat Model

### 1. Trusted vs Untrusted Inputs

The document does not explicitly enumerate a formal trusted/untrusted input list, but implicit trust boundaries are clear from the review guidance and anti-patterns:

**Treated as untrusted (require validation):**
- **User-supplied CLI arguments** — "Validate all user input before passing to `Command`"
- **Package names** — `src/pnpm_cmd.rs` singled out for "package name validation (prevents injection via malicious names)"
- **File paths** — "Canonicalize file paths to prevent traversal attacks"
- **Command flags** — "Use allowlists for command flags (not denylists)"
- **External PR diffs** — every external contributor PR is treated as potentially hostile

**Treated as trusted:**
- **Maintainer-authored code** after review
- **Environment variables** for secrets (e.g. `std::env::var("API_KEY")`) — explicitly recommended as the *safe* pattern vs hardcoded strings

---

### 2. Stated Threat Model for Command Injection

The SECURITY.md identifies **shell injection as the primary threat vector**, centered around two patterns:

1. **`src/runner.rs` is called out as the "primary injection vector"** for shell command execution
2. **`src/discover/registry.rs` is flagged as "command injection risk via rewrite rules"**

The explicitly stated dangerous pattern is:

```rust
// ❌ Shell injection risk
Command::new("sh").arg("-c").arg(format!("echo {}", user_input)).output();
```

The safe alternative recommended is:

```rust
// ✅ No shell, direct binary execution
Command::new("echo").arg(user_input).output();
```

The core model: **never spawn `sh`/`bash` with user input interpolated into a command string**; instead always pass user input as a separate argument to a known binary.

The automated `security-check.yml` workflow scans every PR for:
- `Command::new("sh")` — shell execution
- `.env("LD_PRELOAD")` — library hijacking
- `reqwest::`, `std::net::` — unexpected network operations
- `unsafe {` — bypasses Rust's memory safety
- `.unwrap()` in production code
- `SystemTime::now() > ...` — logic bombs
- Base64/hex strings — obfuscation

**Specific high-risk files (Tier 1):**
- `src/runner.rs` — shell command execution engine (primary injection vector)
- `src/summary.rs` — command output aggregation (data exfiltration risk)
- `src/tracking.rs` — SQLite database operations (privacy/telemetry concerns)
- `src/discover/registry.rs` — rewrite logic (command injection via rewrite rules)
- `hooks/rtk-rewrite.sh` / `.claude/hooks/rtk-rewrite.sh` — thin delegator hook executing in Claude Code context

**Tier 2 (input validation):**
- `src/pnpm_cmd.rs` — package name validation
- `src/container.rs` — Docker/container operations (privilege escalation)

**Tier 3 (supply chain):**
- `Cargo.toml` — dependency manifest
- `.github/workflows/*.yml` — CI/CD pipelines

Any PR modifying Tier 1 files requires **2-reviewer approval and manual security audit**.

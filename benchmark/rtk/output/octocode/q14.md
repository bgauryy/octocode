# Q14 — `SECURITY.md` threat model

## 1. What inputs does rtk consider trusted vs untrusted?

The SECURITY.md does not explicitly use "trusted vs untrusted" language. However, the security model implies:

**Implicitly trusted:**
- Internal command construction (the `Command::new("binary").arg(arg)` pattern with direct args — NOT shell interpolation)
- Config files, `Cargo.toml` dependencies from verified sources

**Implicitly untrusted / requiring validation:**
- All user input before passing to `Command`
- Package names (strict regex sanitization required)
- File paths (must be canonicalized to prevent path traversal)
- Command flags (allowlists, not denylists)

The critical files list flags `src/discover/registry.rs` as a "command injection risk via rewrite rules" — meaning rewrite rules applied to user-typed commands are a trust boundary.

---

## 2. What is the stated threat model for command injection?

From **Dangerous Patterns We Check For**:

> `Command::new("sh")` — **Shell injection** — Spawns shell with user input

The threat model is: **never use shell execution (`sh -c "...{user_input}"`)** because it exposes shell metacharacters. The safe pattern is direct binary execution:

```rust
// ❌ UNSAFE — shell injection risk
Command::new("sh").arg("-c").arg(format!("echo {}", user_input)).output();

// ✅ SAFE — direct binary, no shell interpolation
Command::new("echo").arg(user_input).output();
```

Primary injection vector is identified as **`src/runner.rs`** (the shell command execution engine).

---

## 3. What shell execution patterns are explicitly called out as risk surfaces?

| Pattern | Risk |
|---|---|
| `Command::new("sh")` | Shell injection — spawns shell with user input |
| `.env("LD_PRELOAD")` | Library hijacking — preloads malicious shared libraries |
| `reqwest::`, `std::net::` | Data exfiltration — unexpected network operations |
| `unsafe {` | Memory safety bypass |
| `.unwrap()` in `src/` | DoS via panic on invalid input |
| `SystemTime::now() > ...` | Logic bombs (time-based triggers) |
| Base64/hex strings | Obfuscation of malicious URLs/commands |

**High-risk files identified:**
- `src/runner.rs` — Shell command execution engine (primary injection vector)
- `src/discover/registry.rs` — Command rewrite logic (injection risk via rewrite rules)
- `hooks/rtk-rewrite.sh` — Executes in Claude Code context, intercepts ALL commands
- `src/container.rs` — Docker operations (privilege escalation risk)
- `src/pnpm_cmd.rs` — Package name validation (injection via malicious names)

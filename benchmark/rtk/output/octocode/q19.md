## `// SAFETY:` Comments in `src/`

### Result

There are **zero `// SAFETY:` comments** in `src/` of `rtk-ai/rtk`.

### Why

1. **`unsafe_code = "deny"` in `Cargo.toml`**: The project-wide Rust lint forbids unsafe code across all crates:
   ```toml
   [lints.rust]
   unsafe_code = "deny"
   ```
   
2. **Semgrep enforcement**: `.semgrep.yml` contains an `unsafe-block` rule that treats any `unsafe { ... }` in Rust files as a **severity ERROR**, reporting: "Unsafe block detected. RTK has no legitimate need for unsafe code."

3. **One permitted exception — not annotated with `// SAFETY:`**: The only `unsafe` block in `src/` appears in `src/main.rs` (line 1364) for Unix SIGPIPE signal reset:
   ```rust
   // Reset SIGPIPE to default handler so writing to a closed pipe
   // e.g `rtk git log | head` exits silently instead of panicking.
   // Rust ignores SIGPIPE by default and with panic="abort" in the
   // release profile that becomes SIGABRT + coredump.
   #[cfg(unix)]
   #[allow(unsafe_code)]
   // nosemgrep: unsafe-block
   unsafe {
       libc::signal(libc::SIGPIPE, libc::SIG_DFL);
   }
   ```
   
   This block has:
   - A 4-line explanatory comment (rationale and consequences)
   - `#[cfg(unix)]` — platform scoping
   - `#[allow(unsafe_code)]` — explicit per-block lint suppression
   - `// nosemgrep: unsafe-block` — explicit semgrep suppression
   
   However, it uses an explanatory prose comment rather than the Rust convention of a `// SAFETY: <invariant>` annotation. The project's documentation (`docs/contributing/CODING_PRACTICES.md`) explicitly states: "`unsafe` code. Not allowed except for Unix signal handling in proxy mode, which is correctly scoped to `#[cfg(unix)]`."

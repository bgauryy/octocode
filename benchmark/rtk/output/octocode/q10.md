## 2. Why was the re-implementation necessary?

The codebase changed between the original fix (#235) and this PR (#2129). Specifically, **PR #826** changed the architecture of the `format_*` functions — they now return `String` instead of `print!()`-ing inline. This meant the original implementation in #235 was incompatible with the current `develop` layout and needed to be re-ported to the new function signatures.

Additionally, the second half of #235 (`run_api` `.take(20)` single-pass refactor) was no longer applicable because `run_api` now does a full passthrough via `run_passthrough`.

## 3. What is the `(body contained only badges/images/comments)` fallback note?

When a PR or issue body contains **only filterable content** (badges, images, HTML comments, horizontal rules), `filter_markdown_body()` strips it entirely to empty. Before this fix, `format_pr_view` / `format_issue_view` would silently skip the body section, leaving users and agents with **no signal that body content had existed**.

The fix adds an `else` branch that emits the literal string:
- In `format_pr_view`: `(body contained only badges/images/comments)`
- In `format_issue_view`: `Description: (body contained only badges/images/comments)`

This only fires when the raw body was **non-empty** but filtered to empty — truly empty bodies do not trigger the note.

## 1. When `skip_filter_on_failure` should be `true` — comment text

The field `skip_filter_on_failure` in `RunOptions` has **no `///` doc comment**. There is only a structural inline comment explaining `inherit_stdin` nearby:
> `/// Forward rtk's own stdin to the child process. Needed for commands that can read from a pipe (e.g. \`cat file | rtk wc\`); without it the child gets an empty stdin and reports zero.`

The meaning of `skip_filter_on_failure` is documented only by its behavior in the code (runner.rs ~line 97):
```rust
if opts.skip_filter_on_failure && exit_code != 0 {
    if !result.raw_stdout.trim().is_empty() {
        print!("{}", result.raw_stdout);
    }
    if !result.raw_stderr.trim().is_empty() {
        eprint!("{}", result.raw_stderr);
    }
    timer.track(cmd_label, &format!("rtk {}", cmd_label), raw, raw);
    return Ok(exit_code);
}
```

Set `skip_filter_on_failure = true` (via `.early_exit_on_failure()`) when: the filter would strip error messages that the user needs to see on failure. When the command fails (non-zero exit), rtk bypasses the filter entirely and prints raw stdout/stderr directly, then returns the original exit code. Used for all `gh pr`, `gh issue`, `gh run`, container, and confirmation-style commands.

## 2. What `RunMode::Passthrough` is for — comment text

`RunMode::Passthrough` has **no `///` doc comment** on the enum variant. The only documentation is the comment in `run_api()`:
> `// gh api is an explicit/advanced command — the user knows what they asked for.`  
> `// Converting JSON to a schema destroys all values and forces Claude to re-fetch.`  
> `// Passthrough preserves the full response and tracks metrics at 0% savings.`

In the `run()` match arm for `RunMode::Passthrough`, it calls `stream::run_streaming` with `FilterMode::Passthrough` and `StdinMode::Inherit`, then calls `timer.track_passthrough()`. It is used when rtk should not alter the output at all — forwarding stdin to the child process, streaming output directly to stdout, and recording in the tracking DB that savings were 0%. Used for unknown subcommands, `gh api`, and explicit user passthrough requests (e.g. when `--json` flag is present).

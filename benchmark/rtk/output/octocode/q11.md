## 2. Stated motivation for adding `--ultra-compact` / `-u`

The PR describes a **two-level optimization system** for `rtk gh` output:

**Level 1 (Conservative - Default)**:
- Removes counters from headers, removes `@` prefix, makes merge status compact
- Result: +12-18% savings, zero UX loss

**Level 2 (Moderate - Flag `-u` / `--ultra-compact`)** — the newly introduced flag:
- ASCII icons: 🟢 → "O", 🟣 → "M", 🔴 → "C"
- Inline check format: "Checks: 3/3 passed" → "✓3/3"
- Compact headers: "Pull Requests" → "PRs"
- **Result: +22% additional savings** (87% total on `rtk gh pr view`)

The motivation was maximizing token savings for LLM agent usage, particularly for `gh pr view`, `gh pr checks`, `gh run list`, and `gh pr list`.

Token savings validated on a production repo:
| Command | Before | After | Reduction |
|---|---|---|---|
| `rtk gh pr view` | 24.7K chars | 3.2K chars | **87%** |
| `rtk gh pr checks` | 8.9K chars | 1.8K chars | **79%** |
| `rtk gh run list` | 10.2K chars | 1.8K chars | **82%** |
| `rtk gh pr list` | 5.1K chars | 2.4K chars | **53%** |

## 3. Which commands were updated to support it?

The `--ultra-compact` / `-u` flag was introduced as a **global flag** from the start. In PR #10, the following `rtk gh` subcommands were updated:

- `gh pr list` / `gh pr view` / `gh pr checks` / `gh pr status`
- `gh issue list` / `gh issue view`
- `gh run list` / `gh run view`
- `gh repo view`

The flag is declared as `#[arg(long, global = true)]` in `src/main.rs` (visible from `ultra_compact: bool` in the `Cli` struct), making it available to all commands. However, only `gh` and `glab` commands actively use it (passed as `cli.ultra_compact` to their `run()` functions).

**Note**: PR #1188 later removed the `-u` short alias from `--ultra-compact` to fix a conflict with `git push -u` (git's `--set-upstream` flag). The long form `--ultra-compact` still works.

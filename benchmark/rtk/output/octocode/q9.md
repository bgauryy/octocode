## `gh` subcommands rtk intercepts (in `run()` dispatch)

The top-level `run()` dispatch handles 5 subcommands; everything else passes through unchanged.

**Passthrough short-circuit:** When `--json` flag is present in args, rtk ALWAYS passes through directly (user wants raw JSON).

| `gh` subcommand | `run()` arm | rtk handling |
|---|---|---|
| `gh pr` | `"pr" => run_pr(...)` | Dispatches to sub-subcommand handler (see below) |
| `gh issue` | `"issue" => run_issue(...)` | Dispatches to sub-subcommand handler (see below) |
| `gh run` | `"run" => run_workflow(...)` | Dispatches to sub-subcommand handler (see below) |
| `gh repo` | `"repo" => run_repo(...)` | Dispatches to sub-subcommand handler (see below) |
| `gh api` | `"api" => run_api(...)` | **Always passthrough** — comment: "Converting JSON destroys all values and forces Claude to re-fetch. Passthrough tracks metrics at 0% savings." |
| `gh <anything else>` | `_ =>` passthrough | **Always passthrough** |

## `run_pr()` match arms

| arm | handling |
|-----|---------|
| `"list"` | Filters JSON (`number,title,state,author`) → compact list, capped at `CAP_LIST` |
| `"view"` | Filters JSON (`number,title,state,author,body,url`) → structured view with `filter_markdown_body()` |
| `"checks"` | Filters JSON (`number,name,status,conclusion`) → compact checks summary |
| `"status"` | Filters JSON (`currentBranch,createdBy,needsReviewFrom`) → compact PR status |
| `"create"` | Runs `gh pr create` with `--fill`, captures output, formats confirmation |
| `"merge"` | Captures result, formats confirmation message |
| `"diff"` | Calls `compact_diff()` from git module |
| `"comment"` | `pr_action("commented", ...)` — passthrough + confirmation |
| `"edit"` | passthrough + confirmation |
| `_ =>` | passthrough |

## `run_issue()` match arms

| arm | handling |
|-----|---------|
| `"list"` | Filters JSON (`number,title,state,author`) → compact list, capped at `CAP_LIST` |
| `"view"` | Filters JSON (`number,title,state,author,body,url`) → structured view with `filter_markdown_body()` |
| `_ =>` | passthrough |

## `run_workflow()` match arms

| arm | handling |
|-----|---------|
| `"list"` | Filters JSON (`databaseId,name,status,conclusion,createdAt`) → compact run list |
| `"view"` | Parses text output: shows only Status/Conclusion lines + failed jobs; passthrough if `--log-failed`, `--log`, or `--json` |
| `_ =>` | passthrough |

## `run_repo()` dispatch

Only handles `repo view` → filters JSON (`name,owner,description,url,stargazerCount,forkCount,isPrivate`) → compact repo summary. Everything else passes through.

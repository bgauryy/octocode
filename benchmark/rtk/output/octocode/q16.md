# Q16 — Complete `gh` subcommand dispatch table in `src/cmds/git/gh_cmd.rs`

## Top-level `run()` dispatch

```rust
pub fn run(subcommand: &str, args: &[String], verbose: u8, ultra_compact: bool) -> Result<i32> {
    if has_json_flag(args) {
        return run_passthrough("gh", subcommand, args);
    }

    match subcommand {
        "pr"    => run_pr(args, verbose, ultra_compact),
        "issue" => run_issue(args, verbose, ultra_compact),
        "run"   => run_workflow(args, verbose, ultra_compact),
        "repo"  => run_repo(args, verbose, ultra_compact),
        "api"   => run_api(args, verbose),
        _       => run_passthrough("gh", subcommand, args),
    }
}
```

**Guard clause**: If any arg is `--json`, `--jq`, or `--template` → always passthrough (structured output flag detected).

## Per-subcommand behavior

### `pr` → `run_pr()`
| Match arm | Handler | What rtk does |
|---|---|---|
| `list` | `list_prs()` | Fetches JSON (`number,title,state,author,updatedAt`), formats compact text with state icons, caps at `CAP_LIST` with tee hint |
| `view` | `view_pr()` | Fetches full PR JSON, formats: title, author, state, URL, body (filtered via `filter_markdown_body()`), checks summary |
| `checks` | `pr_checks()` | Formats check status summary (pass/fail counts) |
| `status` | `pr_status()` | Formats PR status text |
| `create` | `pr_create()` | Passthrough with confirmation message |
| `merge` | `pr_merge()` | Passthrough with confirmation |
| `diff` | `pr_diff()` | Passthrough |
| `comment` | `pr_action("commented", ...)` | Returns `ok_confirmation("commented", "#N")` |
| `edit` | `pr_action("edited", ...)` | Returns `ok_confirmation("edited", "#N")` |
| `_` (all others) | `run_passthrough("gh", "pr", args)` | Raw passthrough |

### `issue` → `run_issue()`
| Match arm | Handler | What rtk does |
|---|---|---|
| `list` | `list_issues()` | Fetches JSON (`number,title,state,author`), formats compact list |
| `view` | `view_issue()` | Formats issue with filtered body, state, author, URL |
| `_` | `run_passthrough` | Raw passthrough |

### `run` → `run_workflow()`
| Match arm | Handler | What rtk does |
|---|---|---|
| `list` | `list_runs()` | Fetches workflow run list (last 10), formats status + conclusion |
| `view` | `view_run()` | Extracts status/conclusion lines + failed job details |
| `_` | `run_passthrough` | Raw passthrough |

### `repo` → `run_repo()`
| Match arm | Handler | What rtk does |
|---|---|---|
| `view` | Custom formatting | Fetches JSON (`name,owner,description,url,stargazerCount,forkCount,isPrivate`), formats compact summary |
| `_` (all non-view) | `run_passthrough("gh", "repo", args)` | Raw passthrough |

### `api` → `run_api()`
Always **raw passthrough** — no JSON filtering applied.

> Comment in code: *"gh api is an explicit/advanced command — the user knows what they asked for. Converting JSON to a schema destroys all values and forces Claude to re-fetch. Passthrough preserves the full response and tracks metrics at 0% savings."*

### `_` (all other subcommands)
Raw **passthrough** to native `gh`.

---

## Summary

rtk intercepts 5 top-level `gh` subcommands with custom formatting:
`pr`, `issue`, `run`, `repo`, `api` (api is passthrough-by-design)

All other subcommands (`search`, `auth`, `gist`, `extension`, `secret`, `variable`, `workflow`, `release`, etc.) are passed through raw.

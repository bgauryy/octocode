# Q20 — CI checks in `.github/workflows/`

## Workflow files in `.github/workflows/`

5 workflow files (plus `CICD.md` documentation):

---

## 1. `ci.yml` — Continuous Integration

**Triggers**: `pull_request` on branches `develop` and `master`

**Jobs:**
1. **check-test-presence** — Verifies filter modules have tests; fails if new filter added without tests
2. **fmt** — `cargo fmt --all -- --check` (formatting gate)
3. **clippy** (needs: fmt) — `cargo clippy --all-targets` (linting gate)
4. **test** (needs: clippy) — `cargo test --all` on matrix: `ubuntu-latest`, `windows-latest`, `macos-latest`
5. **security** (needs: clippy) — `cargo audit` CVE check, critical files check, dangerous pattern scan, Clippy security lints
6. **semgrep** (needs: clippy) — `semgrep scan --config .semgrep.yml` with baseline diff
7. **benchmark** (needs: clippy) — Builds rtk release, installs tools (tree, ruff, pytest, mypy, golangci-lint), runs `./scripts/benchmark.sh`
8. **doc-review** (develop PRs only) — AI doc review via Claude Sonnet (Anthropic API)

---

## 2. `cd.yml` — Continuous Deployment

**Triggers**: `push` to `develop` or `master`; `workflow_dispatch`

**Jobs:**
1. **pre-release** (develop only) — Computes semantic version from commits, creates `dev-{version}-rc.{run_number}` pre-release tag
2. **build-prerelease** (needs: pre-release) — Calls `release.yml` reusable workflow with `prerelease: true`
3. **release-please** (master only) — Runs `release-please-action@v4` to create/update release PR
4. **build-release** (needs: release-please) — Calls `release.yml` to build and upload release assets
5. **update-latest-tag** (needs: build-release) — Updates `latest` floating tag to the new release

---

## 3. `release.yml` — Reusable Release Workflow

**Triggers**: Called via `workflow_call` (not triggered directly)

Builds multi-platform binaries and uploads GitHub release assets.

---

## 4. `next-release.yml` — Update Next Release PR

**Triggers**: `pull_request` with type `closed` on `develop` branch

**Job**: When a PR is merged to `develop`, automatically updates the "Next Release" PR body (categorized as Feats/Fix/Other). Creates the Next Release PR if it doesn't exist.

---

## 5. `pr-target-check.yml` — PR Target Branch Check

**Triggers**: `pull_request_target` with types `opened`, `edited`

**Job**: If a PR targets `master` directly (not from `develop`), adds `wrong-base` label and posts an automated comment directing contributor to target `develop`.

---

## Which checks must pass before a PR can be merged?

From `ci.yml` (required for PRs to `develop`/`master`):

| Check | Required |
|---|---|
| `fmt` | ✅ Must pass (formatting) |
| `clippy` | ✅ Must pass (linting) |
| `test` (all 3 OSes) | ✅ Must pass |
| `security` | ✅ Must pass (warnings don't block, vulnerabilities do) |
| `semgrep` | ✅ Must pass (security scan) |
| `benchmark` | ✅ Must pass |
| `check-test-presence` | ✅ Must pass |
| `doc-review` | ⚠️ Informational only (skipped if no API key) |

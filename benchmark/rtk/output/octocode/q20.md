### What Each PR Changes

1. **#2422 (cargo fix)**: `--message-format=json` builds now surface compiler errors properly instead of reporting "compiled" for failed builds. Adds `extract_json_diagnostics()` that recovers NDJSON `compiler-message` records.

2. **#2243 (oc support)**: Adds OpenShift CLI (`oc`) with compact filtering for `oc get pods`, `oc get services`, `oc logs`. Generalizes kubectl k8s helpers (`k8s_pods`, `k8s_services`, `k8s_logs`) to accept a tool parameter.

3. **#2377 (auto filter level)**: Adds `FilterLevel::Auto` to `src/core/filter.rs` — scales by file line count: <100 lines → None, 100–500 → Minimal, >500 → Aggressive. Wired into `rtk read` as `--level auto` (opt-in, default unchanged).

4. **#2418 (vitest/jest refactor)**: Decouples the vitest/jest runner from the `Commands` enum; uses a shared helper and fixes tracking encode and documentation.

5. **#2417 (eks describe-cluster)**: `filter_eks_cluster` now preserves VPC, networking, OIDC, encryption, access mode, tags, and health fields instead of a single summary line. Fixes silent data loss on `describe-cluster`.

6. **#2416 (uv run pytest)**: Teaches hook rewrite to preserve `uv run` wrapper for `uv run pytest ...` and `uv run python -m pytest ...`, rewriting to `uv run rtk pytest ...`.

7. **#2412 (rg --files rewrite)**: Adds rewrite rule: `rg --files` → `rtk find '*' .` and `rg --files <path>` → `rtk find '*' <path>`.

8. **#2354 (proxy permissions)**: Adds a gate in `src/main.rs` → `permissions::proxy_block_reason` that refuses `.env` secret file access, inline interpreter evals, and `Deny`-verdict commands before spawning any child process.

9. **#2411 (Trae IDE)**: Adds Trae IDE support (`rtk init --agent trae`) installing `.trae/rules/rtk-rules.md`. Hooks also route Trae through the new `decide_hook_action`/`HookDecision` flow.

10. **#2410 (prettier fix)**: Keeps non-check prettier invocations as passthrough; only filters `--check` and `--list-different` invocations. Avoids "success" summary when prettier or package manager fails.

### Breaking-Change Labels
No `breaking-change` or related labels were found in any of the top 10 PRs. All PRs target the `develop` branch (except PR #1047 targeting older base SHAs), and all follow the conventional commit format.

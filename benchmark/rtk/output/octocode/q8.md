## Answer

## 1. What rtk keeps from git diff

- **Changed lines only**: all `+` (added) and `-` (removed) lines, preserved in full
- **Per-file summary header**: `[file] {filename} (+{added} -{removed})`
- **Modified lines**: when two lines at the same position have >50% Jaccard character similarity, they're merged as `~{line_num} {old} → {new}`

## 2. What strips/compresses

- **Stripped**: `diff --git` headers, `--- ` (old-file), `+++ ` (new-file) headers, `@@` hunk context markers — all diff metadata removed
- **Compressed**: per-file change list is capped at **10 changes**; if `added + removed > 10`, a trailing `... +{N} more` line is appended
- **No context lines**: space-prefixed unchanged context lines are completely omitted; the comment explicitly states "Ultra-condensed diff - only changed lines, no context"

## 3. Max context lines per hunk

**0** — the codebase comment at the top of `condense_unified_diff` reads:
> "Never truncate diff content — users make decisions based on this data. Only strip diff metadata (headers, @@ hunks); all +/- lines shown in full."

The `@@` hunk headers (which normally indicate the context) are stripped alongside all other metadata. No context lines (lines starting with a space in unified diff format) are preserved. The entire concept of "per-hunk context" does not exist in rtk's diff output — only pure change lines are shown.

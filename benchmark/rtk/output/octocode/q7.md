## Answer

## 1. Trusted vs Untrusted Inputs

SECURITY.md does not use the explicit "trusted"/"untrusted" framing, but the trust model is implicit:

- **Trusted (no special validation required):** Maintainer-authored code, crate dependencies meeting the vetting criteria (>10k downloads, verified maintainer, MIT/Apache-2.0, recent activity)
- **Untrusted (require validation):** All user input passed to `Command`, package names from package manifests (pnpm, npm), Docker/container arguments. The policy mandates allowlists over denylists for command flags, strict regex sanitization for package names, and path canonicalization to prevent traversal attacks.

## 2. Threat Model for Command Injection

The primary injection vector is shell command execution, specifically:
- `Command::new("sh").arg("-c").arg(format!("echo {}", user_input))` — spawning a shell with user-controlled input is flagged as high-risk
- The mitigation is **direct binary execution** (no shell intermediary): `Command::new("echo").arg(user_input)` passes arguments as discrete argv elements, not a shell string
- High-risk files: `src/runner.rs` (Tier 1 — primary injection vector), `src/discover/registry.rs` (command injection via rewrite rules), `hooks/rtk-rewrite.sh` (executes in Claude Code context, intercepts all commands)

## 3. Shell Execution Risk Surfaces

Identified high-risk surfaces requiring 2-reviewer approval (Tier 1):
- **`src/runner.rs`** — Shell command execution engine (primary injection vector)
- **`src/summary.rs`** — Command output aggregation (data exfiltration risk)
- **`src/tracking.rs`** — SQLite database ops (privacy/telemetry concerns)
- **`src/discover/registry.rs`** — Rewrite logic for all commands (injection via rewrite rules)
- **`hooks/rtk-rewrite.sh`** / **`.claude/hooks/rtk-rewrite.sh`** — Shell hook that intercepts all commands in Claude Code context

Tier 2 (input validation):
- **`src/pnpm_cmd.rs`** — Package name validation (prevents injection via malicious names)
- **`src/container.rs`** — Docker/container operations (privilege escalation risk)

The automated security scan also flags: `.env("LD_PRELOAD")` (library hijacking), `reqwest::`/`std::net::` (data exfiltration), `unsafe {` (memory safety bypass), `.unwrap()` in `src/` (DoS via panic), `SystemTime::now() > ...` (logic bombs), and base64/hex strings (obfuscation).

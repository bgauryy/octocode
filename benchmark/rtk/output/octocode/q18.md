## PR #2129: "fix(gh): show fallback note when PR/issue body is filtered to empty"

**Author:** @pszymkowiak  
**Target:** `develop` branch

### 1. Prior Fix + Original Author

This PR re-implements @polaminggkub-debug's **original fix from PR #235** (which closed issue #235 — the same issue this PR closes). The original fix was on the older codebase layout (before PR #826 which changed `format_*` signatures from `print!()`-ing inline to returning `String`).

### 2. Why Re-Implementation Was Necessary

The `format_pr_view` and `format_issue_view` functions were refactored in PR #826 to change their signatures — they now **return `String`** instead of calling `print!()` inline. The original fix from #235 was authored against the pre-#826 layout and could no longer be applied directly. The re-implementation follows the new `format_*` signatures (post-#826 / post-`develop` layout).

### 3. The Fallback Note

When `filter_markdown_body()` strips a PR/issue body completely empty (because it contained only filterable content — badges, images, HTML comments, horizontal rules), the fallback note is:

> `(body contained only badges/images/comments)`

This is emitted in an `else` branch in both `format_pr_view` and `format_issue_view`, under the existing `Description:` prefix, so users and agents know that body content existed but was filtered out rather than being absent entirely.

**Out of scope note from the PR:** The second half of issue #235 (a `run_api` `.take(20)` single-pass refactor) is no longer applicable because `run_api` now does a full passthrough via `run_passthrough` (by design — see inline comment at `gh_cmd.rs:933-938`).

## PR #2129: `fix(gh): show fallback note when PR/issue body is filtered to empty`

**Author:** @pszymkowiak | **Status:** MERGED

### 1. What prior fix is being re-implemented, and who wrote the original?

PR #2129 re-implements the fix originally authored by **@polaminggkub-debug** in **PR #235** (`fix(gh): show fallback note for filtered body; fix api truncation message`). PR #235 was closed without merging.

The original fix addressed: when `filter_markdown_body()` strips a PR/issue body entirely (body contained only badges, images, HTML comments, horizontal rules), the `format_pr_view`/`format_issue_view` functions silently skip the body section — leaving users with no signal that body content existed at all.

### 2. Why was re-implementation necessary?

PR #235 was never merged (it was **closed**). By the time PR #2129 was written, the codebase had been significantly refactored:
- Post-PR #826, the `format_*` functions changed their signatures: they now **return `String`** instead of calling `print!()` inline.
- This made the original #235 patch no longer directly applicable — it would need to be rewritten to match the new `String`-returning function signatures.

So PR #2129 re-implements the same logical fix on the updated `develop` layout.

### 3. What is the fallback note?

The fallback text shown when the body is filtered to empty is:
> `(body contained only badges/images/comments)`

This is emitted as an `else` branch in both `format_pr_view` (body section) and `format_issue_view` (`Description:` prefix), so the user/agent knows content existed but was filtered — rather than seeing nothing and assuming the PR had no description.

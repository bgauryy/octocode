## Answer

1. The introducing PR I found is **#241 — `feat: `rtk rewrite` — single source of truth for LLM hook rewrites`**.

2. Original design rationale: introduce `rtk rewrite <cmd>` as a centralized rewriting engine for LLM hooks (Claude Code, Gemini CLI), eliminating duplicate command-mapping logic across bash hooks. The PR overview says that when a new RTK filter is added, all hooks should automatically support it without bash changes. It simplified `.claude/hooks/rtk-rewrite.sh` from 357 lines to 60 lines by delegating rewrite logic to Rust, and extended `src/discover/registry.rs` with `rewrite_prefixes` plus rewrite functions for simple and compound commands (`&&`, `||`, `;`, `|`).

3. Alternatives/design review points visible in the PR comments:
   - For `head`/`tail` rewriting to `rtk read`, the reviewer warned that simple prefix replacement would lose special argument transformations such as `head -10 file.txt` → `rtk read file.txt --max-lines 10`. Suggested alternatives were: remove `head`/`tail` from `rewrite_prefixes`; add transformation logic in `rewrite_segment`; or update `rtk read` to accept head/tail-style args. The reviewer called option 1 simplest and most consistent with simple prefix replacement.
   - The reviewer also flagged missing command coverage compared with the old bash hook (`pytest`, `ruff`, `pip`, `go`, `golangci-lint`) and suggested adding corresponding patterns/rules to avoid regressions.

## 1. When should `skip_filter_on_failure` be true?

The inline/doc comment for `skip_filter_on_failure` (set via `.early_exit_on_failure()`) comes from the `RunOptions` struct field (implicitly — there's no explicit `///` doc comment on the field). The behavior is documented through code:

In `run_captured_filter()` (L99–L109):
```rust
if opts.skip_filter_on_failure && exit_code != 0 {
    if !result.raw_stdout.trim().is_empty() {
        print!("{}", result.raw_stdout);
    }
    if !result.raw_stderr.trim().is_empty() {
        eprint!("{}", result.raw_stderr);
    }
    timer.track(cmd_label, &format!("rtk {}", cmd_label), raw, raw);
    return Ok(exit_code);
}
```

When `skip_filter_on_failure` is `true` and the command exits non-zero, rtk **bypasses the filter entirely** and forwards raw stdout/stderr unmodified, then returns the original exit code. This is used when structured output (e.g., JSON, state machine output) would be corrupted if partially filtered on error. The `.early_exit_on_failure()` builder is called by `src/cmds/cloud/container.rs`, `src/cmds/cloud/psql_cmd.rs`, `src/cmds/git/gh_cmd.rs`, `src/cmds/git/glab_cmd.rs`, `src/cmds/system/ls.rs`, `src/cmds/system/tree.rs`.

## 2. What is `RunMode::Passthrough` for?

From `runner.rs` L155–L164, the `RunMode::Passthrough` arm:
```rust
RunMode::Passthrough => {
    let result =
        stream::run_streaming(&mut cmd, StdinMode::Inherit, FilterMode::Passthrough)
            .with_context(|| format!("Failed to run {}", tool_name))?;

    timer.track_passthrough(&cmd_label, &format!("rtk {} (passthrough)", cmd_label));
    Ok(result.exit_code)
}
```

`RunMode::Passthrough` is for commands that rtk does not filter — the child process's output is streamed directly to the terminal (stdin is also inherited). Metrics are still recorded via `track_passthrough()` (at 0% savings), so token usage is logged even for pass-through. Used for: unknown `gh` subcommands, `gh api`, `gh pr create/merge/comment/edit`, and any subcommand not explicitly handled.

The key distinction from filtered modes:
- Uses `StdinMode::Inherit` (child can read stdin)
- Uses `FilterMode::Passthrough` (no output transformation)
- Calls `track_passthrough` instead of `track` (0% savings)

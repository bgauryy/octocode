## Answer

Top-level `run()` dispatch in `src/cmds/git/gh_cmd.rs`:

```rust
match subcommand {
    "pr" => run_pr(args, verbose, ultra_compact),
    "issue" => run_issue(args, verbose, ultra_compact),
    "run" => run_workflow(args, verbose, ultra_compact),
    "repo" => run_repo(args, verbose, ultra_compact),
    "api" => run_api(args, verbose),
    _ => run_passthrough("gh", subcommand, args),
}
```

Also, before that match, if the user explicitly passes `--json`, rtk passes through raw `gh` JSON output instead of filtering.

Handlers vs passthrough:

- `pr` → `run_pr(...)`
  - `list` → `list_prs(...)` custom compact list formatting.
  - `view` → `view_pr(...)` custom PR view formatting/body filtering.
  - `checks` → `pr_checks(...)` custom checks formatting.
  - `status` → `pr_status(...)` custom status formatting.
  - `create` → `pr_create(...)` runs `gh pr create` and filters to an OK confirmation.
  - `merge` → passthrough; comment says merge is destructive and should show exact real output.
  - `diff` → compact diff formatting unless `--no-compact` or non-diff format flags (`--name-only`, `--name-status`, `--stat`, `--numstat`, `--shortstat`) require passthrough.
  - `comment` / `edit` → `pr_action(...)` confirmation formatting.
  - other `pr` subcommands → passthrough.
- `issue` → `run_issue(...)`
  - `list` → custom issue list formatting.
  - `view` → custom issue view formatting/body filtering.
  - other issue subcommands → passthrough.
- `run` → `run_workflow(...)`
  - `list` → custom workflow-run list formatting.
  - `view` → custom workflow-run view formatting.
  - other run subcommands → passthrough.
- `repo` → `run_repo(...)`
  - only `view` is custom formatted; other repo subcommands pass through.
- `api` → `run_api(...)`
  - explicit passthrough. The code comment says converting JSON to schema destroys values and forces refetching, so passthrough preserves the full response and tracks 0% savings.
- any other top-level `gh` subcommand → raw passthrough.

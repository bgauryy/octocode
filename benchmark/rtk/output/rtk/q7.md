## Answer

## 1. Trusted vs Untrusted Inputs

SECURITY.md does not use explicit "trusted"/"untrusted" terminology, but the threat model implies:

**Implicitly trusted:** maintainer-authored code, CI-verified dependencies, config files created by `rtk init`, `.rtk/filters.toml` gated behind `rtk trust`

**Implicitly untrusted / requiring validation:**
- User CLI arguments (all args must be validated before passing to `Command`)
- Package names (strict regex sanitization, per `src/pnpm_cmd.rs`)
- File paths (must be canonicalized to prevent traversal)
- PR diffs from external contributors (trigger full security-check workflow)
- New Cargo dependencies (must meet download, maintainer, license criteria)

## 2. Threat Model for Command Injection

Explicit threat model:
- **Primary injection vector**: `src/runner.rs` — the shell command execution engine. Any user-controlled data that reaches `Command::new("sh").arg("-c").arg(user_input)` would be exploitable.
- **Banned pattern**: `Command::new("sh")` — launching a shell with user input is explicitly forbidden.
- **Required pattern**: Direct binary execution — `Command::new("echo").arg(user_input)` — no shell interpolation.
- **Rewrite logic risk**: `src/discover/registry.rs` is flagged because rewrite rules could inject commands via crafted input strings.
- **Container operations**: `src/container.rs` flagged for privilege escalation risk.

The automated `security-check.yml` workflow scans every PR for `Command::new("sh")` and `.env("LD_PRELOAD")` as high-risk shell execution indicators.

## 3. Shell Execution Risk Surfaces

Identified risk surfaces (SECURITY.md Tier 1 critical files):

| Surface | Risk |
|---------|------|
| `src/runner.rs` | Primary shell command execution engine — main injection vector |
| `src/discover/registry.rs` | Command rewrite rules — injection via crafted rewrite patterns |
| `hooks/rtk-rewrite.sh` / `.claude/hooks/rtk-rewrite.sh` | Executes in Claude Code context, intercepts ALL LLM-generated commands |
| `src/summary.rs` | Command output aggregation — data exfiltration risk |
| `src/tracking.rs` | SQLite DB operations — privacy/telemetry concerns |
| `src/container.rs` | Docker/container operations — privilege escalation |

Dangerous shell patterns checked for (in automated scan):
- `Command::new("sh")` — spawning shell with user input
- `.env("LD_PRELOAD")` — library preloading / hijacking
- `reqwest::`, `std::net::` — unexpected network operations (data exfiltration)
- `unsafe {` — bypasses Rust memory safety
- `.unwrap()` in production code — DoS via panic on invalid input
- `SystemTime::now() > ...` — time-bomb patterns
- Base64/hex encoded strings — obfuscation of malicious URLs/commands

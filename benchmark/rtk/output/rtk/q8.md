## Answer

## 1. What parts of git diff does rtk keep?

`src/cmds/git/diff_cmd.rs` implements **`rtk diff`** — an ultra-condensed diff for comparing **two local files** (not `git diff` output directly, though it also accepts unified diff from stdin).

**What it keeps:**
- `+` (added) lines with their line numbers
- `-` (removed) lines with their line numbers
- `~` (modified) lines — shown as `old → new` on one line when similarity > 50%
- File header: `file1 → file2` with counts `(+N added, -M removed, ~K modified)`
- For stdin unified-diff mode: `[file]` headers with `+N -M` counts, then all `+`/`-` lines

**Key quote from the source:**
> `// Never truncate diff content — users make decisions based on this data.`
> `// Only strip diff metadata (headers, @@ hunks); all +/- lines shown in full.`

## 2. What it strips/compresses:
- **All context lines** — completely removed (the doc comment says "only changed lines, no context")
- `@@ ... @@` hunk headers — stripped
- `diff --git`, `--- a/...`, `+++ b/...` header lines — stripped (replaced by compact `[file]` summary)
- Identical lines between diff blocks — dropped entirely

## 3. Max context lines per hunk

**Zero** — `diff_cmd.rs` explicitly strips all context lines. The module-level doc comment is:
> `/// Ultra-condensed diff - only changed lines, no context`

There is no configurable context window. All hunk context (`@@` blocks with unchanged surrounding lines) is dropped. Only `+` and `-` lines are forwarded.

Note: `diff_cmd.rs` is rtk's standalone file-comparison command. The `git.rs` module (97KB) handles `git diff` passthrough with different logic. For stdin unified diffs, `condense_unified_diff()` also retains a cap: if total changes per file exceed 10, it appends `... +N more` at the file level.

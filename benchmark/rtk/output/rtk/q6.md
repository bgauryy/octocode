## Answer

`src/` has only `main.rs` (no `lib.rs`). The top-level `mod` declarations are at lines 1–7 of `src/main.rs`:

```
L1: mod analytics;
L2: mod cmds;
L3: mod core;
L4: mod discover;
L5: mod hooks;
L6: mod learn;
L7: mod parser;
```

Plus `mod tests { ... }` at L2547 (the integration test module inside main.rs).

## Module Responsibilities

| Module | Responsibility |
|--------|----------------|
| `analytics` | **Read-only dashboards** over the tracking database. Implements `rtk gain` (token savings), `rtk cc-economics` (cost reduction analysis), `rtk session` (adoption metrics). Never writes to the DB. |
| `cmds` | **All CLI command implementations** — one subdir per language/ecosystem (git, rust, js, go, python, jvm, etc.) plus cloud, system. Each command module wraps an external tool and filters/compresses its output. |
| `core` | **Domain-agnostic infrastructure**: configuration, TOML filter engine (8-stage pipeline), tee output recovery, token tracking persistence (SQLite), telemetry, display helpers, stream utilities. Leaf in the dependency graph — imported by all, imports none. |
| `discover` | **Command rewriting + history analysis**. Hot path: every LLM hook calls `rtk rewrite "some command"` — this module decides rewrite vs. pass-through via a lexer + registry. Also scans past LLM session history to find rewrite opportunities. |
| `hooks` | **LLM agent hook lifecycle**: install, verify integrity, audit usage, trust management. Manages `rtk init` for 5 agents + special modes (Gemini, Codex, OpenCode). Delegates actual rewrite logic to `discover/`. |
| `learn` | **CLI correction detection**. Analyzes Claude Code session history to find recurring CLI mistakes (unknown flags, wrong paths, etc.) and auto-generates `.claude/rules/cli-corrections.md`. |
| `parser` | **Three-tier parsing infrastructure**: Full JSON parse → degraded partial parse (regex fallback) → raw passthrough with truncation. Used by test runners and structured-output commands. |

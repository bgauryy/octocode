## Answer

Workflow files in `.github/workflows/`:

- `cd.yml` — **CD**
  - Triggers: `workflow_dispatch`; `push` to `develop` and `master`.
  - Jobs: `pre-release`; `build-prerelease` (reuses release workflow); `release-please`; `build-release`; `update-latest-tag`.
  - Purpose/check role: release/pre-release automation, not the normal PR gate.

- `ci.yml` — **CI**
  - Triggers: `pull_request` to `develop` and `master`.
  - Jobs: `check-test-presence` / “test presence”; `fmt`; `clippy`; matrix `test` on `ubuntu-latest`, `windows-latest`, and `macos-latest`; `security` / “Security Scan”; `semgrep` / “semgrep security scan”; `benchmark`; `doc-review` for develop PRs only.
  - Required PR checks visible from workflow intent: formatting, clippy, tests, security scans, benchmark, and test-presence/doc-review gates as configured by branch protection.

- `next-release.yml` — **Update Next Release PR**
  - Triggers: `pull_request` closed on `develop`.
  - Jobs: `update-next-release`, conditional on the PR being merged.
  - Purpose/check role: updates/creates the “Next Release” PR; not a pre-merge PR check.

- `pr-target-check.yml` — **PR Target Branch Check**
  - Triggers: `pull_request_target` on `opened` and `edited`.
  - Jobs: `check-target`.
  - Purpose/check role: for PRs targeting `master` from branches other than `develop`, labels/comments `wrong-base`; it is a PR policy check.

- `release.yml` — **Release**
  - Triggers: `workflow_call`; `workflow_dispatch` with `tag` and `prerelease` inputs.
  - Jobs: `build` matrix for macOS/Linux/Windows targets; `build-deb`; `build-rpm`; `release`; `notify-discord`; `homebrew`.
  - Purpose/check role: release artifact/package publishing, not the normal PR gate.

Also present: `CICD.md`, a documentation file in the workflows directory, not a GitHub Actions workflow.

Checks that must pass before a PR can merge are not explicitly listed in the workflow files themselves; branch protection defines “required” status checks. From the workflow evidence, the merge-gating candidates are the PR-triggered `ci.yml` jobs plus `pr-target-check.yml` for target-branch policy.

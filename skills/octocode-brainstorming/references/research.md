# Research surfaces

Load when you build a surface plan, or when a generic web result cannot show momentum, crowdedness, publication, or a shipped feature. Why: the plan decides which evidence can change the verdict, and a trend list alone cannot.

## Surfaces

Skip local work for a purely external landscape. Carry the real stack into an external query. Skip external work for an explicit local-only task, or when the web is unavailable.

Extract a lead, verify it in code or a package, then reconcile a contradiction with a formal source.

Prefer a recent source. An inactive repository is prior art, not current competition. Package health is publish recency, cadence, maintainers, the issue and pull-request ratio, and dependency freshness.

Fetch the paper or the publisher page. A Scholar hit is a lead.

## Momentum

Use the row that matches the question. A trend surface alone is `weak`. `moderate` or `strong` needs an independent source, or direct repository, package, or paper data. Record the dated signal: release, activity, citation, ranking, or velocity.

| Need | Sources |
|---|---|
| Cross-domain momentum | Hacker News RSS, Techmeme, Product Hunt, Indie Hackers, Google Trends, Exploding Topics. Verify the claim on the primary source. |
| Papers and methods | arXiv, Google Scholar, Semantic Scholar, SSRN, PubMed, CORE, or the publisher page |
| Product landscape | G2, Capterra, AlternativeTo, launch history, and reviews. Use them to find a competitor. |
| Repository and package momentum | GitHub Trending, GitHub Topics, Best of JS, Socket Trending, npm trends, Star History, OSS Insight. Corroborate with the repository or the package. |
| AI signals | Hugging Face trending models, papers, and spaces; Artificial Analysis; LMArena; Good AI List. Pair each hit with a paper or a primary release. |
| Security | CISA KEV, GitHub Advisories, OSV.dev |
| A platform already shipped it | That vendor's changelog or news page |

Add the AI row or the security row only when the idea needs it.

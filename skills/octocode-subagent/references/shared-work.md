# Shared-work coordination

Load when peers, overlapping edits, messages, or handoffs can change EXECUTE or VERIFY.

Use `octocode-agents-communication` and its supplied bound tools when available. Reuse the host's identity, canonical workspace, and shared database. A managed host owns presence and delivery; follow the communication skill instead of starting duplicate lifecycle loops.

Before writing, discover relevant peers, assign disjoint paths, and acquire the required advisory path leases. Resolve conflicts through a handoff or independent work; never treat a lease as permission to exceed the task. Send only questions, decisions, blockers, and results that change the receiver's next action. Link large handoff documents instead of repeating their contents, and acknowledge each delivered message after handling it.

Keep plans, observed checks, unresolved verification, context recovery, and reusable lessons in the host's task state or notes. Reorient from those records after context loss. Communication stores coordination evidence; it does not replace the host's verification or self-regulation workflow.

If communication tools are unavailable, inventory active work through the host, assign disjoint paths, keep the parent as integration owner, and report the missing coordination evidence. Routine solo work needs no coordination setup.

Next: return to `references/coordinate.md` while workers are live. After worker completion, load `references/completion.md`, verify the integrated result, and release owned leases through the communication tools.

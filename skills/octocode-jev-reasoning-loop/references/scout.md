# Scout — typed read-prioritization

Load when many candidate files or rows might hold a capability and reading them all spends host context the task does not need. A scout judges bounded excerpts before candidate bodies enter host context. With native `includeEvidence: true`, it returns the original redacted excerpts for likely and unresolved candidates in the same call; otherwise the host fetches those candidates. Savings depend on useful exclusions and all follow-up reads.

`scripts/scout.mjs` gathers every anchor-matched span per candidate server-side (sandboxed, redacted, ≤12 spans, budget-bounded), sends ONE request with a per-candidate **Score** question over an ordered taxonomy, and maps distributions to `read | skip | gray_read`. A scout **prioritizes reads; it never authorizes an action and never becomes evidence.** Every verdict is `provisional: true` with span anchors. Before asserting, inspect decisive original evidence unless it is already inspected, complete and current; never report absence from a skip alone. Prefer the native `jevScout` tool when available; the skill runner is the standalone alternative. `scripts/code-scout.mjs` accepts a capability question and candidate paths; its implementation taxonomy and documentation veto make it unsuitable for general question relevance. Use native `jevScout` with `taxonomy: "relevance"` for that task. For already-fetched rows, pass `source.items` to native `jevScout` or `items` in a `scripts/scout.mjs --input` packet. Presets `taxonomy: "implements"|"relevance"` replace inline level lists.

For PR discovery plus title triage, use `scripts/pr-triage.mjs --repo owner/repo --query "search terms" --question "relevance question" [--limit 1..12] [--model MODEL] [--output DIR] [--dry-run]`. It uses Octocode `ghSearchHistory`, preserves discovery pagination, and returns every read/gray_read row in `requiredReads` with an executable `ghGetHistoryItem` detail query. Zero or one candidate needs no provider call; a single candidate is returned for direct inspection. Dry-run still searches GitHub but makes no provider call. For already-fetched rows use the items route above. Title-only relevance never proves behavior or absence; inspect original details before asserting that a PR fixes an issue.

## Gate — when NOT to scout

Read directly when you must read the file regardless, a lexical or exact check settles it, or you expect to read nearly all candidates. Keep known task-required evidence (including named tests or type definitions) outside scout's exclusion decision; scout only the unresolved remainder. Scout when the avoided reads justify the request and orchestration overhead.

## Taxonomy, items, dimensions

For native `jevScout`, use `source.local` for file candidates or `source.items` for fetched rows. Discover paths without reading their bodies first; use `includeEvidence: true` to inspect selected excerpts directly. Each returned evidence item has `source`, `content`, and a SHA256 `contentHash` over the redacted UTF-8 content. This is not a disk freshness hash. Skip rows omit content; `gray_read` with no evidence returns an empty array. Widen missing or incomplete deciding spans, while reusing complete current ones. Omission/false preserves metadata-only output. The standalone runners retain their documented output shapes. Set `taxonomy: "relevance"` for history rows; omission uses `implements` (`none → mentions → imports → implements`). One preset needs no `dimensions` array. Use `dimensions` for custom or multiple judgments, without a top-level `taxonomy`: exactly one `primary` drives the action, `veto` may only demote read → `gray_read`, and `info` reports. Order custom levels lowest to highest; the final level triggers read. The skill runner's input shape is listed below.

## Read policy

The current runner maps no anchor matches to `gray_read` with reason `no_evidence`: the file was not semantically examined. A top-level argmax maps to `read`, P(top) ≤ 0.25 to `skip` for complete selected excerpts, and other results to `gray_read`. These are local policy defaults, not universal probability thresholds. Inspect both `read` and `gray_read` candidates, widening anchors or reading directly for `no_evidence`; the strict `reads` list omits uncertain candidates, while `requiredReads` includes both.

The compact `code-scout.mjs` output exposes `required_reads` (read plus gray_read), per-candidate probabilities, anchors and coverage, the resolved model, and artifact paths. Use `--model` to pin comparisons and `--output` to retain a run. Low coverage calls for a wider read; it is not a confidence measure.

Standalone source-size metrics count UTF-16 characters across candidate or skipped files; they do not measure bytes, avoided reads or saved agent tokens. Measure actual host usage and downstream reads for efficiency claims.

Budget truncation is explicit: a rejected excerpt with omitted characters or spans becomes `gray_read` with reason `incomplete_excerpt`. Whole-file coverage remains advisory; an untruncated anchor window still may not cover the deciding code. Widen retrieval before relying on rejection. A skip is never proof of absence. Validate false-skip rates on held-out tasks before automating this policy; compare the combined read/gray-read class when small probability changes cross that boundary.

## Run

`node scripts/scout.mjs --input scout.json [--dry-run]`. Input: local `{claim, anchors[], candidates[2..12], root?, taxonomy?, levels?, window?, spanBudget?}` or `{claim, items[2..12], itemSpanBudget?, taxonomy?, levels?}`; either may add `dimensions`. Output per candidate: `action`, `level`, `score`, `probabilities`, `coverage`, `truncated`, `anchors`, `provisional: true`. Apply the read policy above; confidence is distribution concentration, not correctness. A second pass needs changed evidence and a useful next decision, not a repeat vote. Reuse already inspected, complete and current source evidence; retrieve changed, incomplete or unseen deciding spans before using them in a claim or reasoning judgment.

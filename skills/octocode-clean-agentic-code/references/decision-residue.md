# Decision Residue

Load when code, comments, skills, or docs carry the record of how a decision was made rather than the decision itself. A number nobody re-derives becomes a false claim.

The test is whether a reader must act on it. A decision is instruction; the evidence that produced it is history, and history belongs in the commit, the PR, or one declared evidence owner.

## Residue types

| Type | Example | Remove when |
|---|---|---|
| Decision narration | `// chose a Map here after benchmarking both`, `// verified: no other callers` | Always — the reasoning is not a constraint the next reader can act on |
| Pasted probe output | caller counts, search hit counts, tree listings, tool transcripts copied into source or prose | Always — it was true for one run and nothing re-derives it |
| Provenance trail | "Sources consulted", research-trail sections, evidence tables, confidence scores, ratings, install counts | The artifact is not the declared owner of that evidence |
| Process metadata | round or attempt labels, session and run IDs, reviewer names, "generated by", ticket chatter | Always in a shipped artifact |
| Dated claims | "as of <date>", "currently", "recently added", version stamps in prose | The document is evergreen and no owner refreshes the date |
| Stale-prone counts | counts of files, references, classes, packages, or tests stated in prose | No check reads the number |
| Restated facts | the same rule stated by two files, or a summary that repeats its own reference | A second owner exists — keep one |

## The number test

Ask one question: does a check fail if this number is wrong? If yes, it is a contract — leave it and note which check enforces it. If no, rewrite the sentence without the number, or delete it. A measured figure survives only with an owner and a refresh path; otherwise it decays into a claim the artifact cannot support.

## Keep rules

Keep residue when removing it would lose something nobody else holds:

- a threshold, limit, or version that a script, test, lint rule, or manifest reads;
- evidence in the file whose declared job is evidence, when it is the single owner of that concept;
- provenance a license, security review, or compliance record requires;
- a dated finding that a document explicitly scopes as a dated snapshot.

Routed evidence references are load-on-demand and owned, so they are not residue. The same content copied into a lobby, README, or source comment is.

## Detection

Text-search the markers rather than reading whole files: `Sources consulted`, `Research trail`, `as of`, `verified`, `confirmed`, `Based on`, `per the`, `generated by`, `round`, `attempt`, plus bare years and percentages in prose. Then read each hit in place — the same phrase can be a live constraint or a leftover.

## Excision

Behavior-preserving, so these belong in a normal batch. Two guards before deleting: search the repository for the literal number or key in case a check consumes it, and confirm no document index declares the provenance section as that file's owned concept, which removing would orphan.

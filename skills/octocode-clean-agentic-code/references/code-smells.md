Load when classifying code as dead, duplicate, kludge, bloat, redundant declaration, or tangled structure. Signal → removal bar; defects to report: [agent-defects](agent-defects.md).

# Code smells

## Dead, duplicate, kludge

- Logic-free re-export `export { X } from './X'`, barrel `export * from './m'`, alias `export default aliasedName` → references, import paths, package exports, public entrypoints traced; export behavior unchanged; graph misses external consumers.
- Legacy shim (`// legacy`, `// compat`, `// deprecated`, `// removed in vX`), old-API adapter, `if (legacyMode)`/`if (version < X)` → no caller or live config needs the old path.
- Duplicate bodies, copy-pasted constants, parallel helpers → AST match and diff, literal search, or graph confirms every site; pick canonical.
- Module-scope `str.replace(/old-value/, ...)` fixup → fix the value at source.
- `Object.assign(prototype, ...)` outside tests → patched object internal, owned.
- Env check always true when deployed → confirmed on every target.
- Repeated string literal → same meaning everywhere; extract a constant.
- Rust stringly identity (tool, vendor, error code as `String`/`&str` compared by literal) → producers, consumers traced; enum or newtype at the boundary.
- Rust `Result<_, String>` beside a typed error → caller only formats; typed error keeps the variant.

## Speculative generality and leftovers

- One-implementation interface/ABC/Protocol, one-entry factory/registry/strategy table → no other implementor or registrant via public exports, plugins, config, test substitutes.
- Option every caller passes identically, unused internal parameter, one-instantiation generic, forwarding-only wrapper → not exported; `lspSearch` lists all callers; no public contract, interface, or callback slot needs it.
- Unimported generated type or module (often under module-wide `allow(dead_code)`) → search and `cargo` build find no consumer; remove generator and allow together.
- Type-hint, decorator, annotation-only hunks on untouched functions → no runtime reader (pydantic, dataclasses, FastAPI, attrs, DI, reflection); else report.
- Unreferenced `fix_*`, `migrate_*`, `debug_*`, `scratch*`, `tmp_*`, `test_*` outside test roots → no script, CI job, or doc runs them.
- AI-attribution comments (`generated by`, `written with`, `assisted by` + tool) outside data, fixtures, transcripts → no disclosure or license policy requires them.

## Checker suppressions

Skip generated, vendored, fixture, third-party suppressions. Keep when → else:

- `as any`, `: any`, `as unknown as`, `@ts-ignore`, `@ts-nocheck`, `# type: ignore`, `cast(Any, ...)` → line says why the type is inexpressible; else real type if typecheck passes, report runtime fixes.
- Non-null `!` or `as T` on a nullable → adjacent invariant proves presence; else report.
- `eslint-disable`, `# noqa`, `//nolint`, `#[allow(...)]` → one item with a reason (file- or crate-wide: reason per lint); else remove if the linter passes.
- Suppressed `dead_code`, `unused`, `unreachable` → written structural cause (helper shared by test binaries); else delete the item or cause; "parity with the old X" is residue.
- Complexity lint (`too_many_arguments`, cognitive or type complexity) → inventory under [Structure](#structure), never batch-fix; raising a threshold only moves it.
- Safety lint (`expect_used`, `panic`, `unwrap_used`) in production → comment says why it cannot fail; else report.

Sweep:

1. Self-reporting: `#[allow]` → `#[expect]` (`unfulfilled_lint_expectations`); `@ts-ignore` → `@ts-expect-error`; ESLint `--report-unused-disable-directives`; mypy `warn_unused_ignores`; ruff `RUF100`; golangci-lint `nolintlint`.
2. Run the checker under every built configuration (features, targets, test and non-test).
3. Delete what none needs; else fix the local cause (feature-gated literal, map for a struct with an unread field, written-out macro arm, dropped import-path hack).
4. Blanket test allowances → tool config (`allow-expect-in-tests`, `allow-panic-in-tests`, ESLint test-glob override).
5. Revert self-reporting forms some configuration leaves unfulfilled; each survivor carries `reason = "..."` or a comment.

## Types and schemas

- Consumers: `lspSearch` references (aliases, interfaces lack call hierarchy); constraints: exact read + `astSearch`. Empty references: still check public exports, generated consumers, protocol and version boundaries.
- Same shape ≠ same role: merge only on proven semantic identity (`UserId`, `ProductId` as `string` stay apart).
- Constraint-free `type Foo = Bar`, empty `interface A extends B {}` → LSP shows every consumer can use `Bar`; trace A's role.
- Duplicate `enum`, near-identical interfaces, same Zod or JSON Schema object twice → AST match or distinguishing field literals; pick canonical; confirm callers.
- Same-shape per-version protocol types (`v1`, `v2`), old-to-new message shim → all producers emit the new shape; check persisted and serialized compatibility first.
- Type behind an always-on flag → inline it; drop the branch.

## Dependencies

- Removal or version change: explicit consent, except unused-only removals in an approved batch.
- Internal monorepo package: `workspace:*` (or configured protocol), never a version pin.
- Declared, never imported → `localSearch` all sources. Imported but undeclared or only transitive → declare at the correct version, or drop the import.
- Test-only in `dependencies` → `devDependencies` once no production import. Peer also direct → does the package ship its own copy?
- Versions differ across workspace packages → inspect consumer ranges and compatibility before deduplicating. Multiple transitive versions may be required; use a root resolution only after checking every affected consumer.
- In root and workspace `package.json` → keep where used; in `dependencies` and `devDependencies` → keep the correct one; build tool as dev and peer → per consumer intent.

## Structure

- Mixed responsibilities (IO, parsing, formatting, domain policy) → one file per responsibility under its owning layer; update callers; build and test. Size is no signal; large pure data is fine.
- Prefixed flat names (`user-api.ts`, `user-db.ts`) → group only when shared ownership or navigation improves; naming alone does not justify a move.
- One document → split only when readers load distinct parts for different tasks; otherwise keep the single entry.
- Wrong layer (`utils/auth-logic.ts` → `domain/auth/`, `api/db-queries.ts` → `repositories/`) → move, update imports, verify with build and LSP; rename only a wrong name.

## Spaghetti

Next step depends on flags, nested special cases, or cross-phase jumps; a long straight procedure is not spaghetti. High confidence only after reading the body, `astSearch` on its branch, loop, try shape, and `lspSearch` callers for passed flags; length, one `if`, or size proves nothing.

- Branch proven unreachable by callers, entrypoints, config → remove; move a phase without adding a branch.
- Else report class `spaghetti` (not safe to delete) with file, line range, signals: inner nested branch decides a different job (fused phases); boolean, mode, or enum set in one region, read in a distant branch; decision retested after a branch settled it; exception, labeled break, or callback jumping phases; cleanup typechecks only after a new flag, wrapper, condition, or copy (weaving).

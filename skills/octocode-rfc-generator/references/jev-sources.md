# Sources and responsibility

Load when tracing the protocol's origin or updating an API assumption.

- `references/workflow.md` and `references/rfc-template.md` define evidence-first decisions, blocker closure, acceptance before implementation and accepted-document audit rules. The optional Jev review adds a bounded debate; it does not replace evidence with votes.
- `octocode-clasify`: inspected configuration and host protocol define provisional typed judgments, one call per unchanged crossroad, matrix/page handling, and protected credentials. Discover the current native `clasify` schema before constructing requests.
- `octocode-subagent`: inspected worker packets define bounded objectives, authority, result barriers and parent verification. The host mediates both workers and owns effects.
- `octocode-eval-benchmark`: inspected evaluation rules and graph-of-loops guidance require frozen baselines, held-out outcomes, independent anchors and whole-workflow cost.
- [Jev documentation index](https://docs.typesafe.ai/llms.txt): official API navigation for changes to provider semantics. Native Octocode owns transport, paging, and typed validation; this skill owns debate admission, evidence binding, and host decisions over the public SemanticQuery `resources[] × questions[]` contract. RFC debate packets use one supplied-value resource to preserve the workers' inspected evidence.

These are source attributions and optional integrations, not runtime filesystem dependencies. All required operating instructions live inside this folder.

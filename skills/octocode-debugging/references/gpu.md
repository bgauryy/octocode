# Frame and GPU timelines

Start with a missed frame, slow batch or other observable unit. Identify the affected work and preserve the environment needed to reproduce it; record device, viewport, warmup or build differences when they affect the comparison. Rendering can belong to the browser GPU process, compositor or terminal emulator even when the application PID is quiet.

| Workload | Capture the interval | Follow the work |
|---|---|---|
| Browser | Record the interaction in DevTools **Performance**, stop and save the trace. Keep throttling and screenshot settings with it. Use the browser's Network panel for waterfall and request timing. | Select the long or dropped frame. Follow input and JS through layout, paint, raster and compositor tracks. Inspect the GPU track when present. A renderer task or browser GPU-process event alone cannot quantify hardware utilization. [Performance reference](https://developer.chrome.com/docs/devtools/performance/reference) · [Network timing](https://developer.chrome.com/docs/devtools/network/reference) |
| NVIDIA CUDA | For a finite reproduction, `nsys profile -t cuda,nvtx -o "$out/run" ./app`. Open the resulting .nsys-rep in Nsight Systems. For a live job use the collection mode supported by the installed version and target. | Match host CUDA calls to device work by correlation ID, device, context and stream. Inspect kernel intervals, memory copies, synchronization and gaps. Use Nsight Compute on an implicated kernel when counters would distinguish compute from memory limits. Replay can change timing. [Nsight Systems](https://docs.nvidia.com/nsight-systems/UserGuide/index.html) · [Nsight Compute](https://docs.nvidia.com/nsight-compute/ProfilingGuide/index.html) |
| AMD ROCm | Use the installed rocprofv3 system trace for a finite workload, e.g. `rocprofv3 --sys-trace -- ./app`. | Follow HIP calls to dispatches, memory copies, queue IDs and correlation IDs in the trace. [ROCprofiler tracing](https://rocm.docs.amd.com/projects/rocprofiler-sdk/en/latest/how-to/using-rocprofv3.html) |
| Apple Metal | In Instruments, select **Metal System Trace** if available and choose the target. Record the relevant frames and save the trace. Use `xcrun xctrace list templates` to discover installed templates. | Compare CPU encoding and submission with command buffers executing on GPU tracks and frame presentation. [Apple Metal performance analysis](https://developer.apple.com/documentation/xcode/analyzing-the-performance-of-your-metal-app) |

A host API can return as soon as work is enqueued. Follow the submission to the device queue, transfers, execution and the completion the frame waits for. Use device events or correlated hardware timestamps for execution duration. Synchronizing each launch changes overlap. Device-wide utilization can include other processes. When kernels or copies overlap, their summed time can exceed the frame's: identify which completion gates the frame or result. If the device lanes are absent, give the host measurements and name the missing capture. [CUDA timing and overlap](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html)

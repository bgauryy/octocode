# Style pass

Load when reviewing wording, structure, formatting, or a disputed style choice. Use the project's documented style first, then its consistent convention, then the relevant topic page in this skill.

Read the changed text for structure, accurate claims, clear steps, terminology, links, and accessibility. Give an exact location and rewrite for each material issue. Group repeated minor issues into one finding. If a fix depends on an uncertain fact, verify it with `octocode-research` before changing the claim.

Check the live [Google developer documentation style guide](https://developers.google.com/style) when a rule is disputed, may have changed, or affects a sensitive public claim. If it conflicts with a local reference, update the reference and say what changed. Do not claim a page was checked when it was not.

Return to the `SKILL.md` workflow after the pass. The review response format is in `output.md`.

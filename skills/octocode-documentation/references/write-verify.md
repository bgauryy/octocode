# Write and verify

Use for a document that needs an outline, a drafting pass, or verification beyond copyediting.

## Plan and write

Identify the reader, target paths, purpose, evidence, and material gaps. Outline a large document or document set when that helps. The user's request to write or edit already covers the scoped work; ask only about an unresolved destination or effect.

Follow the existing terminology and heading style. Keep facts with their owning page, examples close to the concept they explain, and steps in execution order. Use [mode guidance](modes.md) or [style guidance](style-pass.md) only where a choice remains open.

## Verify

Check changed claims, paths, commands, and examples against their source. For agent instructions and ADRs, check the relevant conventions in [modes](modes.md).

For API or tool docs, trace schema → accepted input → runtime behavior → result. Exercise applicable continuations and error examples. Distinguish static types from runtime checks and measured reliability from untested claims.

Report material gaps and a concise verification result using [output.md](../output.md). Keep the authored document free of probe results, generated metadata, and work narration.

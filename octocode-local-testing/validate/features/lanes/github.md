## DOC DRIFT

1. **TDC:99** says "a path-only GitHub file read defaults to standard minification". Actually the default is `none`: `file3` keeps comments and the continuation shows `"minify":"none"`. This matches TOOLS:274 and contradicts TDC.
2. **TOOLS:1536** ("Shared response cache: ghSearchRepo, ghSearchCode, ghSearchHistory, ghGetHistoryItem, and artifactSearch use per-response freshness periods from 5 minutes to 24 hours") and **TOOLS:1538** (cache:1 marker). Actually: history tools bypass cache by design (gh_search_history/mod.rs:3-5, gh_get_history_item/mod.rs:4-9). Code search has a per-process memo only, repo search has none, and artifact has an in-process HTTP cache only. No disk response cache or `cache:1` marker exists for any of them; only ghGetFileContent (and the ghStructure conditional cache) persist.
3. **TOOLS:405-406** says "Cached batches are isolated by authentication identity" (commit file batches). ghGetHistoryItem does no caching (see 2), so the sentence describes a cache that does not exist.
4. **TOOLS:59** says "Queries batched in one call share one goal and one reasoning." Actually each row requires its own goal/reasoning (`bulknog`: row 1 rejected `queries.1.goal: Missing required field`). This also contradicts TDC:47.
5. **TOOLS:366-373** (patchUnavailable, previousPath) and the whole TOOLS/TDC PR section: changedFiles inventory rows are now compact strings `"M +3 -1 [!tooLarge|!binary|!omitted ]path[ <- old/path]"` grouped as `{"dir/":[…]}`. The docs describe object fields `patchUnavailable`/`previousPath`, which survive only on patch rows. The compact format appears only in the schema description.
6. **fileFilter / matchContext** (new ghGetHistoryItem PR params) are undocumented in TOOLS and TDC, apart from a passing mention in TDC:112. They also do not appear in TOOLS' `ghGetHistoryItem` field list or in the "Token cost control" table (TOOLS:529, "Review a PR's changes"), which still says changedFiles then selected patches.
7. **TOOLS:513** says "PyPI keyword discovery returns an unsupported-capability error with exact-lookup guidance". Actually it gets a generic schema `invalidInput` ("Unknown field: keywords" + "Missing required field: packageName").
8. **TOOLS:1506-1510** (clone example `…/main__sp_a3f8c1 (kind: tree, complete: false)`; cache key `{branch}__sp_{hash}/`). Actually a sparse clone returns `complete:true` (complete is relative to the requested scope, as TOOLS:470/TDC say), and the directory is `main__sp_41cf67__host_4dc11541e2f7a1d9` (host suffix).
9. **MCPD:68** lists `ghCloneRepo` in the MCP "GitHub" tool family table with no CLI-only note, while the same table marks `astRewrite` "(CLI-only)". MCPD:61-62 and README:208-218 are correct.
10. **`--redact-emails` CLI flag** (cli/mod.rs:50) is undocumented in docs/ and CLI; only env/config `OCTOCODE_REDACT_EMAILS` / `output.redactEmails` appears (docs/generated/CONFIG_SETTINGS.md:85).
11. **TDC:9** (MCP 12 / CLI 13) is accurate for default settings with no Jev key. The observed MCP 13 is `clasify` enabled by the Jev key present in ~/.octocode/.env, not ghCloneRepo. No drift, but the doc could say "13 with a classification key".
